## Why

`@byok-sdk/{client,protocol,core,sdk,server,cloud,cloud-dataplane,implementation-identity,testkit,ui-runtime}` and `byok-sdk` have been published at `0.20.0` on npm since 2026-09-23, and `@byok-sdk/keys` at `0.6.1`; the `v0.20.0` tag at `48605554` is their source. Since then `main` has taken PR #226 (prepared message egress, merged as `644f8473`), a BREAKING input-preparation cut: wire version 6, the capability token renamed to `agent-input-preparation-v6` with no dual token or dual read, `TaskOfferPreparedPayload` now requiring `egressPolicy` and optionally carrying `messageEgress`, and Pi `auto` + `allowTools: []` reinterpreted on the fresh lane from "Pi's full default tool table" to "zero native tools, observed MCP only". The cut has an operator precondition — drain in-flight input preparations and prepared Executions, then upgrade cloud and devices as a pair — because on long-poll an unknown key or type freezes the device cursor, and the enqueue capability gate is the only guard. If this ships wrong — manifests bumped but `bun.lock` left behind — `bun pm pack` resolves `workspace:*` from the lockfile, and keys 0.6.2 would pack a `@byok-sdk/core@0.20.0` edge, which is the one thing its re-release exists to change. If the release notes omit the precondition, an operator upgrades one side with work in flight and freezes a mailbox. On 2026-09-24 the Owner also chose option B for this train: stop publishing the `byok-sdk` umbrella (ADR-035, accepted 2026-09-05 with implementation deferred to a breaking release) and `@byok-sdk/testkit` (its only consumer is the private `@byok-sdk/conformance`). If that cut is half-done — a package removed from one release inventory but not another — the publish driver, the pack, the registry readback and the release graph disagree about what the train is, and `publish.mjs` (which publishes every non-private manifest under `packages/`) could still ship a package the docs call retired.

## Goal

The repository is prepared for the `0.21.0` / keys `0.6.2` train and NOTHING is published. The published set is exactly nine packages: eight aligned manifests (`core`, `protocol`, `client`, `server`, `cloud`, `cloud-dataplane`, `ui-runtime`, `implementation-identity`) read `0.21.0` and `packages/keys/package.json` reads `0.6.2`; `packages/sdk` is deleted, `@byok-sdk/testkit` is `private: true` at `0.0.0`, and every `bun.lock` workspace record agrees with its manifest. `check:release-graph` fails on any other public manifest under `packages/` or a reappearing `byok-sdk`; `check:release-pack` packs exactly nine tarballs; `registry-readback` expects exactly nine; `check:api-surface` gates exactly the nine published packages and no orphan golden; `check:version-authority` reads train mentions as scoped `@byok-sdk/<published>@x.y.z` and rejects any `byok-sdk@x.y.z`. `docs/releases/v0.21.0.md` carries a "Packages no longer published" section (existing versions stay on npm, scoped-package replacement for the umbrella imports, optional `npm deprecate` commands), and the handoff repeats those commands as an optional post-publication Owner step. `README.md` and `docs/spec.md` advertise exactly those two versions, still name `0.20.0` / keys `0.6.1` as the registry's `latest`, and state that `0.21.0` / keys `0.6.2` are prepared and unpublished. `docs/releases/v0.21.0.md` and `docs/releases/v0.21.0-handoff.md` exist; the notes carry every breaking change from PR #226's body (the v6 cut with its drain-then-pair precondition and cursor-freeze rule, `egressPolicy` required on `TaskOfferPreparedPayload` with optional `messageEgress`, sanitized prepared envelopes, the daemon-authored reply body at turn end, the fresh Pi lane `allowTools: []` reinterpretation, the native-expressibility check before pin), the empty-`requiredToolsets` deferral to the official Pi 0.87.1 migration, the three known unrelated CI timing flakes, and the frozen Pi fork at 0.86.1001; the handoff gives the Owner's exact publication commands, including the interactive npm 2FA step in Terminal.app and the tag push. `CHANGELOG.md` gains a `0.21.0 / @byok-sdk/keys 0.6.2` section. The root required checks plus `check:release-graph` and `check:release-pack` pass. No `npm publish`, no `publish.mjs --execute`, no tag, no push, no GitHub Release.

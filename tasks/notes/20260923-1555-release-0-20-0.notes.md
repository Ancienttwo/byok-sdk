## Design Decisions

- **Same two authorities, same three physical copies as 0.19.0.** `packages/core/package.json` and `packages/keys/package.json` moved first; the ten aligned manifests, the eleven `bun.lock` workspace records, and `README.md` + `docs/spec.md` were edited to agree. The `bun.lock` diff is exactly eleven lines, and `bun install --frozen-lockfile` accepted it without rewriting anything.
- **keys takes a PATCH, by the policy.** `docs/spec.md#pre-10-package-version-policy` limits PATCH to "corrections with no new public behavior, API, persistence, or security authority". `git diff --stat v0.19.0 HEAD -- packages/keys packages/core packages/implementation-identity` is empty, so keys' source and the code behind both of its workspace edges are unchanged. The same policy paragraph requires keys' packed and published `@byok-sdk/core` edge to equal the current dispatch release, which the published keys 0.6.0 (core 0.19.0) cannot satisfy. `check:release-pack` shows `byok-sdk-keys-0.6.1.tgz internal @byok-sdk edges all pin 0.20.0`.
- **The runbook pointer was stale before this work-package.** `deploy/runbooks/release-responsibility.md` still called 0.19.0 "prepared" and 0.18.0 `latest` after the 0.19.0 closeout. It now points at the 0.20.0 handoff and names 0.19.0 / keys 0.6.0 as `latest`, with its publication record.
- **The handoff makes web 2FA the primary publish command.** Both 0.17.0 and 0.19.0 published with `--execute` and no `--otp`, answering npm's web 2FA prompt. `--otp <code>` is documented as the alternative. Both routes run interactively in Terminal.app, and the E404 readback-propagation recovery (readback alone, then the step-8 tag) is spelled out because it happened on both previous local publishes.
- **CHANGELOG gets a new top section.** PR #223 added no Unreleased section, so the `0.20.0 / @byok-sdk/keys 0.6.1` section summarizes the release notes and is headed "unpublished until the registry confirms", as the 0.19.0 cut was.

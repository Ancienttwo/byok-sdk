### Owner rework design decision

- P1: SDK admission owns authenticated binding and terminal delivery; the product consumer owns its external effect and immutable outcome. The existing egress contract already requires duplicate product publication to be idempotent.
- P2: consumer commits -> SDK terminal write fails -> exact admission stays pending -> transport retry must invoke the same idempotent consumer and recover its decision. Throwing preserves pending; SDK must not invent `held/consumer_failed`. Existing reservation recovery remains valid after cancellation or task terminalization; a new reservation still requires a live task.
- P3: retain the existing at-least-once consumer seam, without a new lease/recovery API or local cache. At higher concurrency callback invocations can multiply, but the product transaction must permit only one logical effect. Public cloud/server documentation states that requirement.
- #143 host reject timeline events now require `reason: string | null`; null is explicit first-write absence. Recovery compares and uses that stored payload. Historical host reject entries without reason cannot prove the original command and are rejected, not inferred as null. Before deployment against an existing timeline, operators must inventory these entries and settle or explicitly migrate them from authoritative facts; this source slice does not authorize production migration or claim that cutover is complete.

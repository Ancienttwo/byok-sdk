## Design Decisions

- P1: `@byok-sdk/client` owns the pi CLI/RPC subprocess boundary. The required
  `pi-coding-agent` package owns `pi-agent-core`, `pi-ai`, `pi-client`,
  `pi-protocol`, and `pi-tui` transitively; BYOK does not import them.
- P2: `task.offer` reaches `PiAdapter.start()`, resolves the package-relative
  CLI (or explicit `BYOK_PI_BIN` sidecar), spawns RPC mode, maps delta-only
  `message_update` frames, and completes only on `agent_settled`.
- P3: exact `pi-coding-agent@0.84.1` plus Node `>=22.19.0` is one contract.
  The old global-PATH fallback and 0.74.x completion semantics were removed.
  pnpm and `bun install` are installation choices; supported execution is Node.
- Release boundary: the six dispatch packages plus `byok-sdk` move together to
  `0.2.0`. `@byok-sdk/keys@0.1.0` stays outside that dependency graph and keeps
  Node 20 support.

## Deviations From Plan Or Spec

- The Node SEA smoke exposed a pre-existing Homebrew packaging defect: copied
  Node binaries can remain mode `0555`, so postject cannot write them. The
  recipe now makes only its disposable copy owner-writable.
- The installed Homebrew Node 24/26 binaries do not contain postject's expected
  SEA sentinel, so they cannot verify the supported minimum-runtime artifact.
  The smoke was rerun with the SHA-256-verified official Node 22.19.0
  darwin-arm64 distribution and passed injection plus both runtime scenarios.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Directly depend on every pi workspace package | Rejected | BYOK consumes only the coding-agent CLI/RPC boundary; duplicate direct dependencies create another version authority. |
| Keep global `pi` PATH fallback | Rejected | It silently substitutes an unversioned core runtime. |
| Claim Bun runtime support | Rejected | Bun's Node API compatibility is incomplete; only install/packaging plus a Node sidecar was verified. |

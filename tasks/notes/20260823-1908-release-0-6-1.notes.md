## Design Decisions

- Pi stays at the current exact 0.84.2 authority after the user corrected an
  accidental 0.84.1 instruction. No manifest, lockfile or runtime source change
  is required; all projections must prove the existing value.
- The aligned public train is already authored at 0.6.1 and keys at 0.2.2.
  Release preparation changes only README/CHANGELOG and workflow evidence.
- Publish from the clean, accepted release worktree. Remote `main` remains on
  the last released source until npm registry readback succeeds, then
  fast-forwards to the same candidate SHA before tag/Release publication.

## Deviations From Plan Or Spec

- Initial contract-worktree setup created the worktree but CodeGraph init
  returned non-zero without diagnostics. A direct `codegraph init` succeeded
  (640 files, 10,040 nodes, 44,026 edges); `switch-plan` then restored the
  isolated worktree markers. No product or release semantics changed.
- The first installed-pin assertion looked under root `node_modules`; Bun's
  workspace install places Pi under `packages/client/node_modules`. The
  corrected readback proved manifest, lock and installed package are 0.84.2.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Downgrade Pi to 0.84.1 | Rejected | User corrected the request; current source, lock and probes consistently author 0.84.2. |
| Push candidate main before npm publish | Rejected | It would make public README claim a release before registry authority exists. |
| Publish from accepted release worktree | Adopted | The branch and clean source SHA remain recoverable through partial publication, while remote main stays truthful until readback. |

## Design Decisions

- Public dispatch identity is `@byok-sdk/*`；the retired `@byok/*` names were never published and receive no compatibility shim。
- `byok-sdk` is a namespace umbrella over six dispatch packages。`@byok-sdk/keys` remains separately installed and is forbidden from the umbrella/dispatch transitive graph。
- All first public dispatch releases use `0.1.0`；the existing registry placeholder `byok-sdk@0.0.1` advances to `0.1.0`。
- npm registry preflight observed `byok-sdk@0.0.1` and `@byok-sdk/keys@0.1.0` maintained by `ancienttwo`；all six target scoped packages and all old-scope names were unpublished。The owner completed npm WebAuthn write confirmation as `ancienttwo` after merge/freeze；no TOTP、password or token was read or stored by the release process。
- The local executable release invariants now cover eight public manifests（six dispatch、`byok-sdk` umbrella、isolated keys），require the umbrella's exact six namespace dependencies, traverse the runtime graph to prove no keys edge, and pack/install the seven artifacts owned by this release。The already-published keys artifact is inspected but is not republished。
- Local pre-gate evidence after architecture/sprint sync: `pnpm run check:release-graph` passed；`pnpm -r run typecheck`、`pnpm -r run build` and isolated `pnpm run check:release-pack` passed on Node v26.5.0 / Darwin arm64。The hard-env workspace test passed 11 projects：core 112、keys 330、protocol 189、cloud 130、server 217、client 1,034、conformance 117、cloud-postgres 200、umbrella 1 tests（examples are build/typecheck-only）。`pnpm run check:deploy-sql`、protocol golden zero-diff、migration zero-diff、`git diff --check` and strict workflow also passed。
- The initial strict workflow rerun reported only a stale recovery packet。The installed helper command resolved `scripts/recovery-view-cli.ts` relative to the repo and failed because that helper is not repo-owned；running the selected Bun-global 0.14.0 materializer by absolute package path refreshed `.ai/harness/handoff/resume.md`, after which `repo-harness run check-task-workflow --strict` passed。No repository dependency or compatibility fallback was added。
- First PR CI on exact head `e7fd4fc` exposed a Windows-only separator bug in the old-scope scanner：recursive paths were produced with `path.join()` but historical-directory exclusions compared POSIX literals, so the Windows Node 20/22 legs scanned intentionally frozen architecture snapshots and failed。The fix normalizes each candidate directory to `/` only for policy comparison；the scanner still reads the native absolute path and no exclusion is widened。Both duplicate PR/push runs otherwise passed 42/42 jobs。
- Second PR CI on `9a7d78c` advanced past the scanner and exposed the next Windows portability boundary：Node `spawnSync()` cannot execute `.cmd` shims directly with `shell:false`, so `pnpm.cmd` returned `status=null` before build。The release scripts now run the trusted pnpm JS entrypoint from `npm_execpath` and the Node-distribution `npm-cli.js` through `process.execPath` on Windows；fixed argument arrays stay shell-free, preserving path/argument safety。Unix keeps direct `pnpm`/`npm` execution。
- Independent Codex exact-SHA review on `c6a7c7a` rejected the first candidate because registry readback proved metadata/imports but did not bind registry bytes back to the frozen tarballs。The artifact manifest now records the exact source Git SHA plus SHA-256 and registry-compatible SHA-512 integrity for every tarball；post-publish readback requires that manifest and fails unless every npm `dist.integrity` matches the frozen artifact exactly。
- PR #40 merged as `705a956`；the post-merge freeze found one persistent-output smoke path bug, fixed by PR #41 without changing package bytes semantics。PR #41 merged as `aebe6b6eec54ab0ce3e67d1cb3f04e07ee1be13b` after all Linux/macOS/Windows Node 20/22 pack/install jobs passed。
- Frozen release directory: `_ops/releases/byok-sdk-0.1.0`（ignored operations state；do not regenerate）。The manifest records `sourceGitSha=aebe6b6eec54ab0ce3e67d1cb3f04e07ee1be13b` and seven exact SHA-256 values: core `60d7324376712d2d399f7bd3e49b22629e0c64fdefdd6005b28d32019605050f`；protocol `65404afcaec66db8d4ee96d07d084d45855b34364b32942ae15e92d7bcd1bad1`；server `46c359ed97ce5312b2b40ae61ddaae66b5ed28eea61862f7ef3ec94505f4dfa4`；cloud `726ede9200fb43c0b2e9deb2cc6ebaedc855b4330d3b69853ddcc854093e2e35`；client `44b0d1f774771a70c541d29a8019024ac230e90f615b101b4e41d01cf279c734`；cloud-postgres `4bf9454c145fea4c151f71c79613552f1f7fe0171540bbf9ff96ecf834b7f489`；umbrella `744c08aa88504142e1390729569fafaf955361c7ee0f0c638b5b0d013b801816`。

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Re-export every symbol at umbrella top level | Reject | cross-package names can collide and flatten ownership boundaries |
| Namespace exports for all dispatch packages | Accept | complete SDK surface with stable ownership and no symbol collision |
| Depend on/export keys from umbrella | Reject | would collapse the secret-plane dependency/security boundary |
| Publish old-scope forwarding packages | Reject | creates an unbounded compatibility path before any public contract exists |

## Design Decisions

- **Same two authorities, same three physical copies as 0.20.0.** `packages/core/package.json` and `packages/keys/package.json` moved first; the ten aligned manifests, the eleven `bun.lock` workspace records, and `README.md` + `docs/spec.md` were edited to agree. The `bun.lock` diff is exactly eleven lines, and `bun install --frozen-lockfile` accepted it without rewriting anything. The package set is the release-graph authority's (`scripts/release/check-package-graph.mjs`: seven dispatch packages + `testkit` + `implementation-identity` aligned, the `byok-sdk` umbrella, and independent `keys`), unchanged from 0.20.0.
- **keys takes a PATCH, by the policy.** `docs/spec.md#pre-10-package-version-policy` limits PATCH to "corrections with no new public behavior, API, persistence, or security authority". `git diff --stat v0.20.0 HEAD -- packages/keys packages/core packages/implementation-identity` was empty at the base `644f8473`, so keys' source and the code behind both of its workspace edges are unchanged. The same policy paragraph requires keys' packed and published `@byok-sdk/core` edge to equal the current dispatch release, which the published keys 0.6.1 (core 0.20.0) cannot satisfy.
- **The runbook pointer moves back to "prepared" form.** `deploy/runbooks/release-responsibility.md` pointed only at the published 0.20.0; it now points at the 0.21.0 handoff first, names 0.20.0 / keys 0.6.1 as `latest` with its publication record, and restates the version selection for this train.
- **The release notes state the v6 precondition as the spec does, not only as the PR body does.** PR #226's body gives "drain, then upgrade as a pair; unknown key or type freezes the cursor; the enqueue gate is the only guard". `docs/spec.md` and `docs/protocol.md` add two operator facts the notes carry too: required message dispositions must be settled and v5 preparations are recreated rather than read forward, and an old prepared offer already enqueued without `egressPolicy` is NOT repaired by a paired upgrade and needs operator handling.
- **The fresh-lane `allowTools: []` note names the escape hatch.** Omitting `allowTools` still selects Pi's default native registry on a fresh run (`permission-mapping.ts`, spec "Pi policy" paragraph), so the notes tell a Host that wanted the defaults to omit the list rather than send an empty one.
- **Handoff route unchanged from 0.20.0.** Web 2FA (`--execute`, no `--otp`) is primary, `--otp <code>` the alternative, both interactively in Terminal.app; the E404 recovery (readback alone, then the step-8 tag `git tag -a v0.21.0 -m "v0.21.0" -m "sourceGitSha <sha>"`, identical to `publish.mjs`'s `${tag}\n\nsourceGitSha ${headSha}`) is kept because it happened on 0.17.0, 0.19.0 and 0.20.0 (`docs/releases/v0.20.0-publication.md`).
- **Option B (Owner, 2026-09-24): the umbrella is deleted, not made private.** Every dependency on `byok-sdk` as an authority was inventoried first. The train version was already keyed on `packages/core/package.json` in all three release scripts and in `check-version-authority.mjs`; the umbrella was only a README/spec *wording* authority (`byok-sdk@X` mentions and the "agree with byok-sdk@X" message) plus release-graph rules that existed to check the umbrella itself (exactly seven workspace dependencies, seven namespaces in `src/index.ts`, no keys export). No workspace package, example or script imports `byok-sdk`, and neither Salesko nor aip depends on it. A private re-export with no consumer would be dead code that the graph still has to special-case, and ADR-035 (accepted 2026-09-05) already rules "delete `packages/sdk`'s workspace/publication authority in one breaking release; no empty umbrella, alias package or dual export". So `packages/sdk` is deleted (option a) and no authority moves: `packages/core` stays the train authority. `check:version-authority` now reads README train mentions as `@byok-sdk/<name>@x.y.z` for every non-private workspace manifest except keys (names derived from the manifests, so the external `@byok-sdk/pi-*` fork artifacts are ignored) and rejects any `byok-sdk@x.y.z`.
- **testkit becomes private at `0.0.0`, like conformance.** A private package carrying the train version would look like a train member; `0.0.0` matches the existing private convention. `publishConfig`, `files`, the repository/bugs/homepage fields and the per-package `LICENSE` were publish-only and are dropped; the build/test scripts stay because conformance consumes testkit's `dist/` through `workspace:*`.
- **The published set is enforced by closure, not only by lists.** `publish.mjs` already derives its publish set from every non-private manifest under `packages/`, so it needed no edit. `check-package-graph.mjs` now fails if any manifest under `packages/` is neither in the declared nine nor a declared private package (conformance, testkit), if a declared private package is public, versioned, or has `publishConfig`, or if `byok-sdk` reappears. `check-api-surface.mjs` fails on a full run if its gated inventory is not the non-private package set or a golden is orphaned. Probes on the working tree: flipping testkit to `private: false` → `[release-graph] packages/testkit/package.json: must remain private @byok-sdk/testkit` (exit 1); recreating `packages/sdk/package.json` named `byok-sdk` → "byok-sdk is retired and must not exist as a workspace package" + "undeclared workspace package" (exit 1); restored → exit 0.
- **The pack/readback install walk still collects `node_modules/byok-sdk`.** With `byok-sdk` gone from the expected set, a tarball that drags the umbrella back in fails as an unexpected package, which costs nothing to keep.
- **Downstream inventory.** `package.json` files under `apps/`, `packages/` and the root of `/Users/kito/Projects/salesko-new-wt-c07-host` and `/Users/kito/Projects/aip-main-open`: neither depends on `byok-sdk` or `@byok-sdk/testkit`. Salesko's root `overrides` still pins `@byok-sdk/testkit: 0.20.0` with no workspace consumer; the release notes and handoff tell Salesko to drop that line when it moves to 0.21.0.
- **Historical text is left alone.** Archived plans/contracts/notes, `docs/releases/v0.1x`/`v0.20.0` records, `docs/researches/`, and the historical S7/RC and ARCHITECTURE-PROPOSAL tracking sections of `sdk-architecture.md` (§12 diagram, RC table) describe the umbrella as it was and are not current-state claims.
- **CHANGELOG gets a new top section.** PR #226 added no Unreleased section, so the `0.21.0 / @byok-sdk/keys 0.6.2` section summarizes the release notes and is headed "unpublished until the registry confirms".

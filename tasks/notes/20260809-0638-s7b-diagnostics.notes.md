## Design Decisions

- `collectDiagnostics` is the single typed source for doctor and support bundle. It probes runtimes, normalized authenticated-control reachability, read-only health/journal/workspace state and bounded quarantine metadata without importing a write capability。
- SQLite doctor never opens the store DB. It copies a ≤512 MiB regular DB/WAL/SHM set into an OS temp dir, rechecks source dev/inode/size/mtime/ctime identity, and runs read-only `quick_check(1)` only against that snapshot；invalid SQLite header is corrupt, open/query/race is unavailable, so report-only cannot create store sidecars or mislabel every access failure as corruption。
- The only fix requires both `--fix` and `--yes`. Daemon start-to-stop and doctor fix use one cross-process owner lease；fix re-inspects under the lease, rejects symlink/non-regular paths, atomically moves the actual inode first, then hashes the moved evidence and writes the digest manifest. It never rebuilds health/journal state。
- Support bundle projects an allowlist field by field, not a redaction pass over raw objects: product/device/runtime/filenames become SHA-256；runtime version output is omitted；audit accepts only closed `DaemonEvent.kind` values from the last 256 KiB / 200 facts；offline/error detail is normalized. Same-directory hard-link publication is atomic/exclusive；the unpublished inode is 0600 on POSIX or restrictive-DACL hardened on Windows before linking, followed by target fsync and POSIX parent fsync。

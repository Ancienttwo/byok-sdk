## Design Decisions

- `collectDiagnostics` is the single typed source for doctor and support bundle. It probes runtimes, normalized authenticated-control reachability, read-only health/journal/workspace state and bounded quarantine metadata without importing a write capability。
- SQLite doctor opens DB/WAL/SHM only as `O_RDONLY|O_NONBLOCK|O_NOFOLLOW` regular-file handles, copies at most the pre-observed ≤512 MiB bytes from those same handles into an OS temp dir, rechecks handle and pathname identity, and runs read-only `quick_check(1)` only against that snapshot；invalid SQLite header is corrupt, open/query/race is unavailable, so report-only cannot create store sidecars or read a raced FIFO/symlink/oversized replacement。
- The only fix requires both `--fix` and `--yes`. Pair/start through complete writer teardown、unpair cleanup and doctor fix use one cross-process owner lease；one process-local lifecycle queue serializes pair/start/stop/control shutdown/unpair and pair/renewal share one credential-mutation queue，auth renewal is armed only after start owns the lease，and stop awaits the whole mutation tail；failed-start teardown runs inside the same lifecycle slot，and any timed-out late writer remains a barrier across retries。`device.json` is read/removed only through a bounded pathname-bound handle plus same-inode hard-link guard。Health/device/owner readers use `lstat → open → fstat + lstat identity binding` before reading；POSIX additionally uses no-follow/non-blocking flags，while Windows rejects static/raced reparse points without pretending those flags exist。Fix distinguishes unavailable from confirmed JSON/shape corruption，refuses bytes above the same 1 MiB canonical read cap，then enters the checked quarantine directory as a cwd-pinned inode；one synchronous section rechecks inode/size/mtime/ctime、copies and hashes exact bytes、publishes evidence plus manifest，and only then removes the unchanged source name。A pre-unlink failure rolls both publications back；a crash after manifest publication preserves a valid duplicate rather than losing the source。Ordinary quarantine reporting uses the same pinned-directory/path-binding discipline and validates health size/digest or journal same-directory files binding；invalid/unbound evidence is unavailable/fail。It scans at most 200 directory entries and performs at most 128 MiB cumulative synchronous content reads。It never rebuilds health/journal state。Owner/reclaim v2 records require PID、process-start identity and a kernel-owned exclusive loopback listener；self identity comes from Node process lifetime rather than `ps`/PowerShell，foreign PID reuse is reclaimed when the old lease listener is no longer bound，while a port collision remains availability-safe fail-closed；owner reads are pathname-bound/4 KiB-positional，malformed stale reclaim is recoverable after a bounded grace，and bare-PID/missing-start-token compatibility authorities are not accepted。
- Support bundle projects an allowlist field by field, not a redaction pass over raw objects: product/device/runtime/filenames become SHA-256；runtime version output is omitted；audit accepts only closed `DaemonEvent.kind` values from the last 256 KiB / 200 facts；offline/error detail is normalized。Device/audit/health inspection rejects special files without blocking。Same-filesystem hard-link publication is atomic/exclusive；POSIX bytes are 0600，while Windows hardens an empty private directory before any sensitive byte exists，then writes and explicitly hardens the inherited-DACL inode before linking，followed by target fsync and POSIX parent fsync。
- Post-eighth-review authority: a canonical-realpath-derived kernel-exclusive loopback mutex is held across the full owner lease so only one process can perform stale owner/reclaim check-remove-publish；symlink/junction aliases therefore contend on the same mutex。The listener returns its canonical store hash：same identity rejects，a different valid BYOK identity advances through deterministic port candidates，a no-identity timeout remains fail-closed，and a listener that explicitly closes/resets advances to another candidate before the mandatory owner/reclaim record check；the separate random liveness listener continues to adjudicate PID reuse。Device and audit readers both use pre/post-open/read pathname-handle identity binding on every platform。POSIX health quarantine fsyncs evidence/manifest directory entries before unlinking source and fsyncs the source parent afterward；Windows retains file fsync + ordered publication because Node/libuv exposes no directory flush。

## Deviations From Plan Or Spec

- First exact-SHA review (`019fe394-9015-7b23-a295-912b8c944bda`) rejected `ed75e86dd4bbb99dfdfa1750f7f656fbcf2ed4d0`: direct WAL quick_check could create sidecars；health fix followed symlink and lacked exclusive daemon authority；bundle passed product/audit/runtime strings；runtime/device input and Windows permissions were not bounded/enforced。
- Second exact-SHA review (`019fe3ad-66af-7ca3-9e5a-cc5e595125f6`) rejected `0f64fc85aba7ad01a3cd0875d4a94d13da79679b`: failed-start leaked the pressure-engine writer after releasing lease；health unavailable was still labeled corrupt；Windows DACL was applied after bytes existed；device/audit special files could block。The hardening above replaces both rejected assumptions with executable invariants；Claude remains paused/not invoked。
- Third exact-SHA review (`019fe3bf-e4bf-7c41-bee4-8b51b0595c9c`) rejected `38cbc14a05188945954425c76e30edb1180fdb29`: auth renewal escaped ownership；concurrent stop could release after another path timed out；post-rename identity checking could move the wrong inode；SQLite `copyFile` reopened a raced path；stale reclaim/PID reuse could wedge availability。The current hardening closes each with deterministic revert guards；Claude remains paused/not invoked。
- Fourth exact-SHA review (`019fe3d8-70d2-7840-bf21-d52e74dc3de0`) rejected `7394926e6e9afe960d422222e36e658472363629`: oversized shape-valid health could be called corrupt then read without bound；pair could race an already-started renewal writer；owner/reclaim read and legacy authority remained unbounded/PID-reuse-prone；quarantine directory validation had a symlink swap gap；unpair read cleanup identity before reacquiring the lease。The current working tree closes all five with canonical bounded health reads、credential serialization、strict process identity/no compatibility authority、cwd-pinned quarantine publication and under-lease unpair identity read；Claude remains paused/not invoked。
- Fifth exact-SHA review (`019fe3f0-bce6-7473-b2f4-71f31c7afeed`) rejected `edf434c13acbd9f4418e77cdbc0a1eb87c0e7b6d`: a second concurrent daemon-level pair could write after the first released their shared lease；hash-to-publication allowed same-inode byte drift；unpair used an unbounded/follow-symlink `device.json` read under the lease；and acquisition depended on undeclared `ps`/PowerShell commands。The current working tree serializes the full outer pair operation、copies and hashes the exact evidence bytes in one synchronous pinned section、uses bounded no-follow guarded device removal，and derives self start identity only from Node；Claude remains paused/not invoked。
- Sixth exact-SHA review (`019fe406-7527-7212-a800-abb98fa31ab7`) rejected `1790a537129df7cc5b7f061c1c60fc8052f164d5`: pair/start/stop could still share and release the daemon lease concurrently；read-only quarantine inventory followed a directory/path race and did not validate manifest/evidence binding；foreign PID reuse remained permanently fail-closed；the self-hosted runbook still described the superseded hard-link evidence design。The current working tree adds one lifecycle queue、pinned bounded quarantine verification、kernel listener liveness authority and corrected runbook；Claude remains paused/not invoked。
- Seventh exact-SHA review (`019fe419-6965-7711-b7d5-1a95fe417b9e`) rejected `1a3189161f50bc03cf2837ccffbe10d4a545a60c`: Windows silently lost no-follow/non-blocking protection；source unlink preceded a Windows-risky descriptor chmod and manifest publication；quarantine validation still permitted ~10.38 GiB synchronous work；the unpair regression spy no longer crossed `DeviceStore.remove()`。The current working tree binds pathname/handle identity before every sensitive read on Windows、publishes manifest before source removal with rollback、caps scan/read work at 200 entries/128 MiB、repairs the remove-under-lease guard and adds pair/unpair serialization coverage plus a real Windows CI leg；Claude remains paused/not invoked。
- Eighth exact-SHA review (`019fe42c-138f-7492-955d-f50b8f1c5890`) rejected `fe4e01d6f81cd4454e13704ed4e6199a573d9db1`: concurrent stale-owner reclaim could create two leases；Windows `device.json` and audit tail were not pathname-bound；evidence/manifest names were not durable before source unlink；Windows CI omitted support-bundle and late-writer shutdown suites。The current working tree adds the kernel transition mutex、complete input binding、POSIX directory fsync order、concurrent/symlink revert guards and the missing Windows suites；Claude remains paused/not invoked。
- Ninth exact-SHA review attempt (`019fe43f-c65a-71a2-be01-313b4debdc4b`) inspected target `9f350b000f8c14ec10b39eb1e5c249183ba12836` but produced no verdict after its Codex runtime exhausted the skills-context budget；it is infrastructure-inconclusive and cannot serve as acceptance。Main-thread review then found that hashing only `path.resolve(storeDir)` let a symlink/junction alias derive a different mutex for the same store；the current working tree derives the mutex from `fs.realpath(storeDir)` and adds a cross-alias exclusivity guard。Claude remains paused/not invoked。
- First post-canonicalization acceptance preparation exposed two deterministic full-suite failures where unrelated temp stores hashed into the same 10,000-port mutex space。The initial "all collision means active" policy was safe but operationally flaky under parallel test/fleet cardinality；the current listener identity handshake keeps same-store and unknown listeners fail-closed while routing a proven different BYOK store to another deterministic candidate，with a brute-forced first-port-collision regression guard。

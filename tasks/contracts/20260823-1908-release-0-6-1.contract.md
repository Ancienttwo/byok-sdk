## Why

The accepted Agent-first home, Agent-local/cloud egress, connector operability
and Local Agent version-readback source is on `main`, while npm still exposes
the 0.6.0 train. Publishing from the wrong SHA, with a mismatched Pi runtime or
partial package graph, would give downstream hosts an unreproducible contract.
The release therefore needs one clean 0.6.1 source authority and exact registry,
tag and GitHub Release readback.

## Goal

Publish the aligned public BYOK SDK package train at 0.6.1 plus independently
versioned `@byok-sdk/keys@0.2.2`, preserving exact
`@earendil-works/pi-coding-agent@0.84.2`, and bind npm artifacts, annotated
`v0.6.1` and the GitHub Release to the frozen source candidate. Synchronize
public README/CHANGELOG and explicitly leave deployment, production migration
and Salesko cutover outside the release claim.

## Scope

- In scope: release documentation; exact package/Pi graph verification; full
  repository checks; packed tarball smoke; npm publish/readback; annotated tag;
  GitHub Release; temporary release worktree/branch cleanup.
- Out of scope: product behavior changes, dependency upgrades/downgrades,
  Cloudflare deploy, production database migration, secret mutation, Salesko
  dependency update or downstream runtime acceptance.
- Taste constraints: package manifests and `bun.lock` are already authoritative;
  do not rewrite them without a proven mismatch. Pi stays exact 0.84.2. No force
  tags, republish, dist-tag rewrite, fallback release path or version alias.

## Stop Conditions

- Stop and hand back to the parent if the change would require editing a path outside Allowed Paths.
- Stop if an Exit Criteria command cannot be run in this environment.
- Stop if Goal, Scope, or Exit Criteria are internally contradictory.
- Stop before publication if source is dirty, npm already contains any 0.6.1/
  0.2.2 artifact with conflicting integrity, or a remote tag/Release exists at
  another SHA.
- After the first successful npm write, preserve the exact partial registry
  state and continue only at the same immutable versions; never bump or retag
  merely to hide partial publication.

## Falsifier

The direction is wrong if any public manifest is not in the intended aligned
0.6.1 train, keys is not 0.2.2 with the exact current core edge, the installed
or packed Pi is not 0.84.2, or registry/tag/Release already owns the requested
identity at a different source. Cheapest proof: package graph plus live npm and
remote-tag inventory before editing or publishing.

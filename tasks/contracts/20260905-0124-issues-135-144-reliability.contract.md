## Why

WP3B made the cloud kernel the durable authority, but ten audited failure schedules still let notification, in-memory cursor state, or partial cross-store writes outrun durable truth.

## Goal

Close GitHub issues #135–#144 at source level with fault-injected retry convergence across durable cursor acknowledgement, outbound batch outcomes, inbound lifecycle commits, offer publication, relay liveness, and host approval decisions.

## Scope

- In scope: the client, protocol response, cloud inbound/offer/approval, server relay/handle, focused tests, generated API declarations if required, and workflow/architecture evidence.
- Required invariant: tenant is `1:N` devices and `1:N` agents; device is `1:N` active AgentPlacements; each agent currently has at most one active placement. Task, offer, terminal, approval, dedup, and receipt retry authority remains isolated by exact `tenantId + deviceId + AgentRef`, including two agents on the same device.
- Forbidden schema/key shape: no `UNIQUE(tenant_id, device_id)` or any derived one-device-one-Agent authority.
- Out of scope: one-profile-per-tenant assumptions, Profile/Placement decomposition, cross-device migration, Salesko `hostedJournal` and downstream journal-before-ack E2E, `ws/wss` cleanup, publish, deploy, production migration, GitHub issue closure, compatibility shims, unrelated package-topology work, and protocol v2.

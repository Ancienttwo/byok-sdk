## Why

The accepted long-poll capability negotiation fix is not consumable until the aligned public SDK train is published. Publishing the wrong version, a split dependency graph, or bytes that differ from the reviewed candidate would permanently poison an npm version and block downstream salesko from safely repinning.

## Goal

Publish the eight aligned dispatch packages as 0.4.1 from one exact merged source SHA, prove registry tarball integrity against a frozen manifest, verify fresh exact installs, and create an exact `v0.4.1` Git tag and GitHub Release. Keep `@byok-sdk/keys` at 0.1.0.

## Scope

- In scope: the already accepted long-poll capability implementation carried by this release branch, eight package manifests, Bun lock consistency inspection, release-version authorities, CHANGELOG, local and CI release gates, PR/merge, frozen tarballs, npm publication/readback, exact tag and GitHub Release.
- Out of scope: downstream salesko edits/deployment/smoke, keys publication, new runtime behavior, compatibility shims, binary signing or host updater work.

## Stop Conditions

- Stop and hand back to the parent if the change would require editing a path outside Allowed Paths.

## Falsifier

If `bun run check:release-graph` or the frozen pack/install smoke shows any package outside the aligned 0.4.1 train, any keys edge, any registry-translated dependency mismatch, or any tarball differing from the frozen manifest, the release must stop. The cheapest first proof is the release graph check before packing or network writes.

## Root Cause Evidence

Required when Task Profile is `bugfix`; leave as-is otherwise.

- root_cause: one sentence naming file:line/condition (testable, not "a state issue").
- repro: the command or UI path that reproduces the symptom.
- regression_guard: path to a test that fails on the unfixed code and passes after the fix (must also appear under exit_criteria.tests_pass).
- pre_fix_failure_artifact: path to a captured run of regression_guard on the UNFIXED code. Capture with `bun test <regression_guard> > <artifact> 2>&1; echo "PRE_FIX_EXIT=$?" >> <artifact>` (no pipes — pipes swallow the exit status). The gate requires a non-zero `PRE_FIX_EXIT=` line plus the regression_guard path string in the artifact (see the Root Cause Evidence Gate section in docs/reference-configs/sprint-contracts.md).

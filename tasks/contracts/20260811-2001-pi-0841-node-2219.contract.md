## Why

Pi is a core runtime dependency for BYOK. Staying on the legacy Node 20 build
leaves the adapter on an old RPC completion contract; upgrading only the npm
version without changing `agent_end`/`agent_settled` semantics can complete a
task before pi finishes retries, compaction, or queued work.

## Goal

Ship the dispatch package graph as `0.2.0` with
`@earendil-works/pi-coding-agent@0.84.1` as an exact required client dependency,
raise all dispatch and private conformance Node surfaces to `>=22.19.0`, and
make `agent_settled` the single authoritative BYOK task-completion event. The
independent `@byok-sdk/keys@0.1.0` package remains on Node 20 and outside the
dispatch graph. pnpm remains supported. Bun is supported as an
installer/packager while production execution remains Node 22.19+; standalone
bundles inject the external pi Node sidecar through `BYOK_PI_BIN`.

## Scope

- In scope: dispatch manifests/versioning, release graph scripts, changelog,
  pnpm lockfile, Node/CI baseline, pi binary resolution, pi RPC
  mapping/fixtures/tests, packaging guidance, registry publication/readback,
  and product truth.
- Out of scope: Harness V3 implementation, changing runtime preference order,
  claiming Bun runtime compatibility, or adding dual 0.74/0.84 semantics.
- Taste constraints: one exact pi version; no automatic global PATH fallback;
  fail closed when the required package/explicit sidecar cannot be resolved.

## Stop Conditions

- Stop and hand back to the parent if the change would require editing a path outside Allowed Paths.
- Stop if an Exit Criteria command cannot be run in this environment.
- Stop if Goal, Scope, or Exit Criteria are internally contradictory.

## Falsifier

The direction is wrong if pi 0.84.1 cannot install/launch from pnpm's isolated
layout on Node 22.19, or if its documented RPC stream does not emit
`agent_settled` after `agent_end`. Cheapest proof: resolve and run the pinned
package's `--version`, then execute the targeted adapter fixture/tests.

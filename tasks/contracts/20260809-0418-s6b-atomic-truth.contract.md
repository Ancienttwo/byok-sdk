## Why

现有 `TruthStore`、`ObjectStore`、`QuotaStore` 与 proof receipt 各自正确，但 handler 若依次调用它们，会在进程/数据库故障时留下已写 truth 无 reference、reference 无 receipt、inline bytes 未计费等不可恢复中间态。

## Goal

交付 proof-only record manifest/get/put surface 与一条高层原子 commit authority。生产 Postgres 必须在同一 transaction 内完成 receipt、terminal/snapshot CAS、object reference replacement/recount、inline reservation/accounting；exact replay 返回首次结果，binding mismatch conflict，terminal immutable，manifest metadata-only。

## Scope

- In scope: cloud truth capability/DTO/handlers/application port；Postgres committer；deterministic handler fake；必要 additive 0005；record route tests、transaction rollback、docs/ledger。标准 InMemory composition 不声称跨 store atomicity。
- Out of scope: daemon signer/selector/fetch、semantic merge/ranking、protocol DTO/golden、record deletion、key rotation。
- Taste: proof-only auth；no fallback；raw request bytes are the proof body；object must already be committed；cloud never merges snapshots。

## Stop Conditions

- Stop if any route can write without S6 proof.
- Stop if Postgres needs more than one transaction for a successful truth commit.
- Stop if object reference can land without a committed tenant-scoped manifest.
- Stop if `packages/protocol/**` changes.

## Falsifier

在 receipt/truth/reference/accounting 任一步注入失败；若 transaction 结束后任何其他一步仍可观察，即证伪。并发同 requestId 不得产生两个结果；同 requestId 不同 binding 不得复用首次结果。

## Why

`@byok/keys` is the artifact `aip-main-open` must pin before K4's swap can start, and `docs/researches/k4-aip-swap-dryrun.md` §5.2 measured the package as not publishable today: no `publishConfig` (a first-time scoped publish defaults to `restricted` and fails on a free account), no `LICENSE` file anywhere despite four manifests declaring `"license": "MIT"`, no `prepublishOnly` while `dist/` is gitignored at `.gitignore:2` (so a missed manual build publishes an empty or stale tarball), and a README whose module table lists 7 of the package's 18 modules. Two softer defects ride along: no `repository`/`bugs`/`homepage` for the npm page, and a doc comment in `packages/keys/src/errors.ts` that misstates which error-code strings are a K4 compatibility surface. Skipping this leaves the K4 sequence blocked at its first step; shipping it wrong publishes a broken first artifact under a scope that has never been used, where a bad `0.1.0` cannot be cleanly withdrawn.

## Goal

Close dry-run §5.2 items 3-7 and §7.2 step 1 in this repo, without publishing anything.

Three acceptance targets, projected from the plan's `## Task Breakdown`:

1. **Manifest metadata** (`P1`). All four of `packages/{keys,protocol,server,client}/package.json` carry `publishConfig.access: "public"`, `repository` (`git+https://github.com/Ancienttwo/byok-sdk.git` with the per-package `directory`), `bugs`, and `homepage`. `packages/keys` additionally moves `version` `0.0.1` → `0.1.0` and gains `"prepublishOnly": "pnpm run build"`. The other three stay at `0.0.1`.
2. **Licence, README, comment** (`P2`). An MIT `LICENSE` (`Copyright (c) 2026 ancienttwo`) exists at the repo root and is copied byte-for-byte to `packages/keys/LICENSE`. `packages/keys/README.md`'s `## What is in K0` section becomes a complete `## Module inventory` table with one row per non-test module in `packages/keys/src/`, its row count equal to the programmatic count. `packages/keys/src/errors.ts`'s `SECRET_NAMESPACE_INVALID` provenance comment is corrected — comment text only, no code change.
3. **Verification** (`P3`). `pnpm -r run typecheck`, `pnpm --filter @byok/keys run test`, `pnpm -r run build`, and `repo-harness run check-task-workflow --strict` all pass; `npm pack --dry-run` in `packages/keys` lists `LICENSE`, `README.md`, and `dist/`; the run summary is recorded in this slice's notes file.

Two constraints bind the slice: no runtime source change (the 328-test suite must pass with no test-file edit), and no registry interaction of any kind.

## Falsifier

If `npm pack --dry-run` in `packages/keys` does not list `LICENSE` after the file is created, the packaging assumption behind item 3 is wrong — a root-only `LICENSE` would then have sufficed, or `files: ["dist"]` is suppressing it — and the per-package copy must be re-justified before anything else lands. Cheapest proof: run `npm pack --dry-run` immediately after creating `packages/keys/LICENSE`, before touching the README. The second-cheapest falsifier: if `ls packages/keys/src/*.ts | grep -v '\.test\.ts$' | wc -l` does not return 18, the README row count in the plan is wrong and the programmatic count wins.

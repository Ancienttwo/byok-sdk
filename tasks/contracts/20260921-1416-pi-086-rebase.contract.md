## Why

The Owner asked (2026-09-21) to move the Pi dependency to upstream 0.86.1. Upstream has no prepared-input seam, and 0.86 rewrote the exact hosts the fork's seam hangs on (system prompt → `SystemMessage`/sections, provider input → `TranscriptContext`, new `CacheWarmer`). Shipping it wrong breaks the lane's one invariant — the bytes the Host counted are the bytes the provider receives — either silently (a renderer that no longer matches the live session, a cache-warming request nobody counted) or as a permanent drift refusal for every prepared launch.

## Goal

The SDK pins a published `@byok-sdk/pi-*` build based on upstream 0.86.1 whose prepared seam is rebuilt on upstream's own prompt builders: a request body computed from explicit snapshot inputs is byte-identical to the live 0.86.1 session's first request across the extended falsifier matrix; a prepared session issues exactly one request and constructs no `CacheWarmer`; the SDK wire is contract v3 carrying `toolGuidelines`/`sections`, with no v2 reader, and a stored v2 record is refused at readiness with `runtime_contract_superseded`.

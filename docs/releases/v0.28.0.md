# 0.28.0 / keys 0.13.0: source candidate

Date: 2026-10-21 (Asia/Taipei).
Status: not published. The target stable channel is npm `latest`.
The published baseline is `v0.27.0` (`cd977261`). The runtime source
baseline is `ff4c9f810031658b7814dd9d4ce70e0976f5006c`.
All 60 commits after the published baseline are included.

Eight aligned packages move from 0.27.0 to 0.28.0: core, protocol, server,
cloud, client, cloud-dataplane, cloud-do and ui-runtime.
keys moves from 0.12.0 to 0.13.0. Its packed core dependency must be exactly
0.28.0. The private workspace, conformance, testkit and examples are outside
the publication set. This is a MINOR under the pre-1.0 version policy.

## New runtime and Host surfaces

- `GrokAdapter` and `HermesAdapter` add ACP runtime sessions, lifecycle
  handling and capability declarations to the client package.
- The client exposes MCP Streamable HTTP at `@byok-sdk/client/mcp-server/http`.
  The Host supplies authorization. The private `examples/byok-mcp-server`
  adds a scoped key ledger, task tools, routine tools and read-only memory.
- Bot outcomes add fragments and Main Bot delegation cancellation requests.
  The core adds calendar validation and next-occurrence calculation.
  Embedded and Durable Object scheduled wakes accept up to 368 days.
- The private Host execution and Bot collaboration examples add durable
  execution truth, routine control, input coalescing, group mentions,
  Cross-Bot delegation, cancellation, joins and an IM delivery outbox.
  These examples are copy-and-own Host code. They are not new npm packages.
- The daemon reports a content-free `execution-record` after a started task's
  terminal event. It reports trajectory evidence, not task success authority.
- keys can declare `openai-responses`, API-specific compatibility fields,
  long cache retention and input limits in Pi profiles.

## Breaking changes and upgrade steps

1. Remove `DaemonConfig.agentMemoryFilesystem` from embedded daemon config.
   The client also removes the `AgentMemoryFilesystemHelperConfig` export.
   Direct `TaskRunner` embedders replace `agentMemoryFilesystemHelperBin`
   with `resolveAgentMemoryFilesystemHelperBin`.
   macOS memory uses the SDK-owned helper and its verified manifest.
   Use `bun run build:release` for source builds and include the native assets
   in a compiled product. Do not pass an arbitrary helper path.
2. Prepare Pi inputs again after upgrading to the exact official Pi 1.3.0
   closure. A preparation made for 1.2.0 fails runtime identity admission.
   A bare model ID now fails when more than one provider offers that ID.
3. Update daemon event consumers that assume the terminal event is last.
   An `execution-record` can follow it. Keep terminal truth separate.
4. Keep the prepared Pi profile limits. The frozen prepared entry refuses
   `openai-responses`, `inputLimits` and unsupported compatibility fields.
   Those fields do not silently fall back to another API.

Wire major remains 3. The v3 corpus registration appends 0.28.0 with the
same 157 envelope lines and 17 HTTP lines as 0.27.0. Earlier corpus bytes
and the published 0.27.0 decoder floor remain unchanged.
No new PostgreSQL migration ships after 0026 in this train.
A rollback must preserve Host and device state; a package downgrade does
not reverse persisted state.

## Fixes

- Pi RPC accepts max thinking and restores current tools on session resume.
- BYOK Pi sessions remain outside temporary launch scratch directories.
- A reasoning-only key probe can retry once within the same deadline.
- Memory writes enforce the strict CAS barrier and macOS parent sync.
- Recovery tests exercise cancellation faults, killed processes and Linux
  native execution recovery; IPC smoke failures retain diagnostics.

# 0.26.0-rc.2 / keys 0.11.0-rc.2: release candidate (prepared; not published)

Current manifests: aligned train `0.26.0-rc.2`, independent keys `0.11.0-rc.2`.
The release owner approved this version set and the npm dist-tag `rc` on
2026-10-10, after 0.26.0-rc.1 was only partially published (see
[0.26.0-rc.1 partial publication](#0260-rc1-partial-publication)). rc.2 has
the same content as rc.1; only the version and release metadata change. The
route is rc first, then stable after end-to-end verification. This document
records source preparation. It is not proof of npm publication, and it does
not approve npm execution.

## Summary

0.26.0 is the first train after 0.25.0. It adds public API: memory-reader
Attempts beside the one writer of an Agent home (#317), the closing reply on
`task.complete` (#322), optional `workspaceRoot` for a strict daemon (#319),
Agent home projection evidence on Agent terminals (#318) and
`copyPiRuntimeAssets` for single-file Pi hosts (#327). keys makes its Pi
launcher entry public (#323) and fixes two Pi projection faults (#324, #325).
The client denies every provider credential name that pinned Pi 1.1.0 reads
(#326), and the private OAR source moves to 0.48.0.

The wire protocol stays v2. Every protocol change is an optional field or a
new capability flag, and the frozen v2 golden only adds lines. The client has
a small set of breaking cuts around the Agent home execution lease; read
"Breaking changes since 0.25.0" before you upgrade.

## Breaking changes since 0.25.0

### Client: one writer per Agent home (#317)

- `DaemonConfig.maxConcurrentMutableSessionsPerAgentHome` is removed. Setting
  it is a construction error. A home has exactly one writer; use
  memory-reader Attempts for concurrent reads.
- `AgentHomeExecutionStatus` reports `maxConcurrentReaderAttemptsPerAgentHome`
  and `activeReaderAttempts` instead of
  `maxConcurrentMutableSessionsPerAgentHome`.
- `AgentHomeExecutionLeaseManager.activeAttemptCount(canonicalHome, homeAccess)`
  takes an access mode and counts only that mode.
- `AgentHomeExecutionLease` has the new required members `homeAccess` and
  `writerOverlapped()`. A host that implements the interface must add them.
- The writer decline reason `agent home busy` does not change.

### Client: diagnostics workspace status (#319)

- `DiagnosticsSnapshot.workspace.status` has the new value `'not-configured'`,
  reported for a strict daemon without `workspaceRoot`. A host that switches
  exhaustively over this union must handle it.

### keys: Pi admission (#324, #325)

- An `anthropic` profile whose endpoint does not end in `/v1/messages` (for
  example `base_url: 'https://api.anthropic.com'`) now fails Pi admission with
  `PROVIDER_URL_INVALID`. Set `base_url` to the `/v1` form. The direct keys
  client still accepts it.
- The `pi-durable` entry refuses a keyless (`auth_mode: 'none'`) profile at
  admission with `PROVIDER_PROFILE_INVALID`, as `pi-prepared` already did.
  Before, it failed in the worker after the child started.

### Client: Pi credential deny list (#326)

Pi MCP server children and the Pi BYOK key lane no longer inherit
`ANTHROPIC_AUTH_TOKEN`, `COPILOT_GITHUB_TOKEN`, `GOOGLE_CLOUD_API_KEY`,
`META_API_KEY`, `TYPESAFE_API_KEY`, `AWS_BEARER_TOKEN_BEDROCK`,
`ANTHROPIC_IDENTITY_TOKEN_FILE` or `AWS_WEB_IDENTITY_TOKEN_FILE`. A test
compares the list with the names that pinned Pi discovers.

## Additions

### Memory-reader Attempts (#317)

- An Agent offer with `homeAccess: 'memory-reader'` runs in its own run
  directory, `<home>/.byok/runs/<taskId>/`, beside the home's one writer.
- `DaemonConfig.maxConcurrentReaderAttemptsPerAgentHome` (default 4) limits
  readers per home.
- The device advertises the capability `agent-home-readers`
  (`AGENT_HOME_READERS_CAPABILITY`). Server and cloud refuse a reader offer to
  a device without it before the task exists.
- Reader terminals carry `agentHomeMemoryChange` (`unchanged`,
  `reader-attributed`, `unattributed` or `unmeasured`), and `TerminalResult`
  projects it. The SDK records evidence; it does not make memory read-only.
- A reader session resumes in its recorded run directory. The Codex adapter
  makes the home the project root for a reader, so Codex still reads the
  home's `AGENTS.md`. Durable Pi declines a reader offer without retry.
- Design: `plans/plan-20261009-issue-317-reader-attempts.md`.

### Closing reply, strict workspace root, projection evidence (#318, #319, #322)

- `task.complete.finalMessage` carries the runtime's closing reply.
  `TaskResult`, `TerminalResult` and `ResultDocumentTask` expose it. `summary`
  keeps the whole run's text. For Codex the closing reply is the last
  `agentMessage`.
- `DaemonConfig.workspaceRoot` is optional when `strictAgentOnly` is true.
  Diagnostics report `not-configured` for a strict daemon without it.
- Agent Attempt terminals carry the optional `agentHomeProjection` evidence:
  the projection revision and hash applied at Attempt start. The host decides
  whether it matches the offer.
- Design: `plans/plan-20261009-issues-318-319-322.md`.

### `copyPiRuntimeAssets` (#327)

`copyPiRuntimeAssets({ outDir, form })` creates the Pi asset root of a
single-file product in its build. It requires the exact pinned official Pi
package, verifies the Pi export resources and the SDK todo locale assets, and
refuses a target that is not empty. With `sdkHelperHost` and `PI_PACKAGE_DIR`,
a host download runs official Pi with no `node_modules`. The release pack
smoke calls it from the installed tarball. Design:
`plans/plan-20261009-issue-327-pi-host-payload.md`.

### keys Pi launcher entry (#323, #325)

- `runPiProviderLauncher(options, { createSecretStore })` and
  `parsePiProviderLauncherOptions` are public, with the types
  `PiProviderLauncherOptions` and `PiProviderLauncherHost`. A host with its
  own `SecretStore` options builds its own launcher executable. The entry keeps
  the exact profile checks, the custody lock and the pending-change refusal.
- The bundled `byok-pi-provider-launcher` uses this entry. Its flags and
  behavior do not change.
- A keyless profile runs through the `pi-rpc` entry with the fixed, non-secret
  key `PI_AUTH_NONE_API_KEY` (`byok-sdk-auth-none`). The endpoint receives
  `authorization: Bearer byok-sdk-auth-none`.

### OAR 0.48.0

The private OAR source moves from 0.45.1 to 0.48.0 (`087df16`). The derived
Codex fold reports `turn_active`, streamed command output as `outputDelta` and
`app_request_cancelled`. SDK events read native Codex frames only, so ordinary
task launches and SDK events keep their behavior. See
`docs/notes/2026-10-09-oar-0.48-upgrade.md`.

## Upgrade steps

1. Remove `maxConcurrentMutableSessionsPerAgentHome` from `DaemonConfig`. Use
   memory-reader offers for concurrent reads.
2. If the host implements `AgentHomeExecutionLease` or calls
   `activeAttemptCount`, add `homeAccess` and `writerOverlapped()` and pass the
   access mode.
3. Before the host sends a memory-reader offer, upgrade the server or cloud and
   the client. The server and cloud refuse a reader offer to a device without
   `agent-home-readers`.
4. Change an Anthropic keys profile used by Pi to the `/v1` `base_url` form.
   Do not route a keyless profile through `pi-durable`.
5. A Pi MCP server that read one of the denied credential names from the
   daemon environment no longer sees it.

Protocol v2, the prepared-record versions and the storage schemas do not
change; this train adds no migration. The [0.25 upgrade steps](v0.25.0-stable.md#upgrade-requirements) still
apply to a host that upgrades from 0.24 or earlier.

Install the candidate with the explicit tag or exact version:

```sh
npm install @byok-sdk/server@0.26.0-rc.2 @byok-sdk/client@0.26.0-rc.2
npm install @byok-sdk/keys@0.11.0-rc.2
```

These commands work only after the candidate is published.

## Known residuals

- The owner's report-only residuals of 0.25 still apply: re-parented POSIX
  background jobs can outlive disposal, Codex `inherit` sandbox has argv
  evidence only, and the Pi keys-profile lane was not part of the recorded
  real-agent run. See [0.25 known residuals](v0.25.0.md#known-residuals).
- #333 and #335 close the measured `wake-inbox`, WinSW, Pi ACL evidence budget,
  Windows Credential Manager and result-document rollback flakes in test and
  CI code only. Other timing flakes in `tasks/todos.md` remain report-only.
- Keyless durable Pi needs a change to the client durable worker. It is not in
  this train.

The publisher derives this order from the runtime dependencies, with
alphabetical ties. All packages use the dist-tag `rc`. The tag that follows
publication is `v0.26.0-rc.2`.

Steps before execution:

1. Merge the release commit. Get the green push CI run for that exact SHA and
   download its `release-pack-<sha>` artifact.
2. Dry run `node scripts/release/publish.mjs --artifacts <dir> --tag rc`. Before
   any write, the publisher checks that each exact version is absent and that
   `latest` is still 0.25.0 / 0.10.0.
3. Get a separate approval for npm execution. Then run the same command with
   `--execute`. On a slow uplink, set a longer npm request timeout, for example
   `npm_config_fetch_timeout=3600000`. The publisher reads the registry back
   and only then creates the annotated tag `v0.26.0-rc.2`.
4. Push the tag separately.

See the [release responsibility runbook](../../deploy/runbooks/release-responsibility.md).

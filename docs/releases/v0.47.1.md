# 0.47.1 — candidate, 2026-11-26 (UTC)

0.47.1 is the PATCH after 0.47.0 on `release/0.47`. It keeps wire v8 and
carries zero breaking and zero additive entries in the upgrade manifest. The
public API surface and the Wire v8 corpora are unchanged. Hosts on 0.47.0 keep
their server databases, daemon journals, provider stores, and device pairings.
Hosts upgrading from 0.46.x still follow the
[0.47.0 Host upgrade checklist](host-upgrade-0.47.0.md).

## Version set and release gates

All nine public packages move together to 0.47.1 (`core`, `protocol`, `client`,
`server`, `cloud`, `cloud-dataplane`, `ui-runtime`, `bot-collaboration`, and
`keys` under `@byok-sdk`). Publication requires separate authorization,
exact-SHA release validation, and registry readback.
[Upgrade manifest](../../packages/client/upgrade-manifest.json) ·
[Release process](README.md#publishing)

## Fixed

### One runtime-detection module across client package entries

On 0.47.0, each `@byok-sdk/client` entry bundle (`dist/index.js`,
`dist/adapters/index.js`, `dist/testing/index.js`, `dist/bin/byok-agent.js`)
inlined its own copy of the runtime-detection module, with its own
verified-detection and admission-delegation registries. A Host that built the
daemon from `@byok-sdk/client` and its adapters from
`@byok-sdk/client/adapters` therefore lost two 0.47.0 features: the daemon
ran the full `detect()` on a decorator registered with
`delegateAdmissionDetection`, and `ClaudeAdapter.prepare()` /
`CodexAdapter.prepare()` re-resolved or re-probed instead of reusing the
forwarded `input.detected`.
[Refs #2505](https://github.com/Ancienttwo/byok-sdk/issues/2505)

0.47.1 builds the module once as `dist/runtime-detection.js`, reached through
the private package import `#byok-runtime-detection`, and every other entry
imports it instead of bundling a copy (PR #2508). The registries stay
module-private; there is no process-global registry, so a caller still cannot
forge a verified detection to skip a probe. A packaged-dist test now runs an
offer through a `dist/index.js` daemon with an adapters-entry `ClaudeAdapter`
behind `delegateAdmissionDetection`.

A bundler that re-bundles a client dist file must resolve the package's
`#byok-*` imports, as it already must for `#byok-oar-readers`.

### `readHostLedger` on a database without a Host ledger

On 0.47.0, `readHostLedger(path)` in `@byok-sdk/server` validated the K4 store
format before checking for the `host_ledger` table. A readable SQLite file with
unrelated tables, or with `host_store_format` rows for other owners, and no
`host_ledger` table returned `{ kind: 'unreadable', code: 'format_unsupported' }`.
0.47.1 returns `{ kind: 'absent', reason: 'no_table' }` for any readable
database without `host_ledger`. When the table exists, the K4 format
validation is unchanged (PR #2506).
[Refs #2504](https://github.com/Ancienttwo/byok-sdk/issues/2504)

## Test reliability

The durable daemon recovery test no longer fails during setup when a
short-lived descendant exits between the process-tree snapshot and identity
capture. The daemon and launcher identities are still required, and every
captured process must still exit after `SIGKILL` (PR #2507, test-only).
[Refs #2502](https://github.com/Ancienttwo/byok-sdk/issues/2502)

## Protocol compatibility

`golden/v8.releases.json` registers 0.47.1 with the same 514 envelope and
41 HTTP lines and hashes as 0.47.0.

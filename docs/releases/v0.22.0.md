# 0.22.0 draft — official Pi migration

This is a source work-package draft, not a publication or provider acceptance record.
M1/M2/M3 replace the maintained Pi fork with exact official 0.87.1 dependencies and
attest all six official packages. Runtime, release-pack and registry-readback guards
use verified tarball integrity, provenance and file digests; no fork marker remains
an accepted identity authority.

Prepared input switches once to `agent-input-preparation-v7`, wire/record 7 and
SDK envelope v4. Hosts must send a complete `prompt.systemPrompt`; Pi renderer
inputs and default prompt disappear from this lane. Preparation supports empty
requiredToolsets. Tools remain observation-derived; no message or native tool is
added to D. Cloud/device upgrades require draining old work and recreating records.

The official serializer compiles D using real baseUrl and a placeholder-only capture
fetch. It must be called once and terminate without transport. The runtime compares
the first actual URL/body with D in scoped fetch. Session/provider retries are off;
tool continuations are at-most-once per stream and retain post-response overflow
handling. P(D)=D, residual=[]; bytes are not tokens. The Host must reissue its ruling
and C after the separately approved M5 measurements, and assemble its full prompt.

A2′ history sentinel is request-local and wire-neutral, never persisted. Existing
usage-before-body, typed overflow/usage_unavailable, pre-pin and redaction guarantees
remain. Exact-version offline conformance is an upgrade prerequisite.

M4 recursion/custody gate, M5 provider probes, release CI and Owner publication are
separate, pending boundaries. This draft does not authorize any of them.

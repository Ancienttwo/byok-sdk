## Breaking prepared-input cutover

- The maintained `@byok-sdk/pi-*` fork is retired. Client uses unmodified
  official `@earendil-works/pi-coding-agent@0.87.1`, pi-ai and pi-agent-core,
  with exact 0.87.1 versions throughout the six-package official closure.
  Runtime and release checks attest package/version, tarball integrity,
  provenance, upstream commit and installed file digests. There is no fork
  marker, private deep import, patched package or copied serializer fallback.
- Preparation wire and record are **7**; the sole capability token is
  `agent-input-preparation-v7`. Old tokens, records and prompt shapes are
  rejected; no dual read or automatic historical-record conversion exists.
- The prompt snapshot is exactly the required Host string
  `prompt: { systemPrompt: string }`. Host must assemble its complete framing
  and product instructions. The prepared model sees this prompt, **not Pi's
  default system prompt**. The string enters D verbatim and counts toward
  requestBytes. custom/append prompt inputs, cwd, skills, docs, context files,
  tool snippets and coding guidelines are no longer rendering inputs.
- Envelope **v4** uses the complete captured request body: **P(D)=D**,
  **residual=[]**. It makes no token-count claim. Host must reissue a ruling
  for the official runtime/compiler identity with `ruledResidualKeys=[]`;
  an unchanged numeric C does not preserve an old ruling's identity binding.
- Empty `requiredToolsets` is now supported. Tool declarations come only from
  the admitted tools argument/observed MCP schemas. Prepared sessions retain
  zero native tools, and no reserved message tool enters D. Reply egress stays
  daemon-owned with the existing usage-before-body, sanitizer and reliable
  disposition gates.

## Request and failure guarantees

D is compiled through official streamSimple with the real baseUrl (which can
change official compat serialization), a placeholder key and an injected
capture fetch that must be called exactly once and throw. Compilation creates
no session and installs no real credential or transport configuration. The
exact-version URL/body conformance test must pass before every Pi upgrade.

Scoped execution fetch checks the first actual URL/body against frozen D,
blocks environment-derived OpenAI organization/project/custom headers, and
permits at most one transport attempt per stream. Both session and provider
retry layers are disabled. Authorized history uses a request-local,
wire-neutral sentinel that is never persisted as provider metadata.

Only the first request is pre-frozen. Tool continuations use their actual
context rather than replaying D, retain the accepted post-response overflow
boundary, and have retries off. Continuation gate refusals, including
`prepared_context_drift`, now reach the daemon as a typed **task.fail**, rather
than only an assistant error. Existing typed overflow/usage_unavailable,
pre-pin checks and egress redaction remain enforced. INV-12 recursion depths,
charge-once custody, permits and root/parent bindings are unchanged.

## Installation and residual risks

The official OpenAI constructor reads exactly OPENAI_ADMIN_KEY, OPENAI_ORG_ID,
OPENAI_PROJECT_ID, OPENAI_WEBHOOK_SECRET, OPENAI_LOG and OPENAI_CUSTOM_HEADERS.
Compile purity means D is independent of those values and the read set is
exactly restricted; it does not mean zero environment reads. Prepared children
inherit none of these six variables. A device owner enabling **OPENAI_LOG** may
cause local request logging during compilation; this accepted side effect is
local, does not change D and does not send the log externally.

If upstream both ignored the injected fetch and escaped the conformance test,
compilation could attempt one request to the execution provider with a placeholder
key. The accepted residual-risk assumption is that the invalid key is rejected
without billing. No real credential is available during compilation.

Official coding-agent includes an npm shrinkwrap. The measured npm installation
has **10 physical roots**: pi-ai, pi-agent-core, chord and pi-telemetry each occur
twice; coding-agent and pi-tui occur once. All roots are attested. Current
scripted workflow/pi-subagents regressions pass across that layout, but this is
not a singleton guarantee. pi-ai/compat's apiProviderRegistry is module-local;
a future extension's registerApiProvider call on one copy is invisible to the
other. Cross-instance extension registration remains a deferred prerequisite.

Official pi-tui transitively contains
`native/win32/prebuilds/win32-x64/win32-platform.node`. The installation tree is
not native-free or automatically portable as a SEA/single-file payload. SDK
sealed headless entries bundle their measured JS closure and declared resource
inventory; they do not silently copy/load that interactive terminal addon.
Interactive Win32 Pi packaging needs separate evidence. Only coding-agent,
pi-ai and pi-agent-core are direct client dependencies and remain subject to
the direct-dependency purity guard.

## Completed calibration and upgrade procedure

M5 evidence: [20260925-official-pi-c-reprobe.json](../../tasks/runs/20260925-official-pi-c-reprobe.json)
and its [.sha256](../../tasks/runs/20260925-official-pi-c-reprobe.json.sha256).
Three ordinary device-local z.ai requests, no tokenizer, support retaining
**C=1024** for the recorded official closure, compiler 4, wire 7 and envelope v4.
Bare: 171 request bytes / 13 prompt tokens. Prepared: 17638 / 6581. Repeated
identical D: 6581 prompt tokens, including 6528 cached (53 non-cached). Observed
uncovered amount max(0, prompt_tokens-requestBytes) was zero; prepared headroom
was 11057 below bytes and 12081 below bytes+1024. This is empirical calibration,
not a universal bound proof or a production Salesko admission receipt.

Before upgrade, fence admissions and drain old queued/in-flight preparations
and Executions. Upgrade Host/cloud and devices as a coordinated cutover; rebuild
runtime installation bindings and preparation records under the new identity,
wire 7 and complete Host prompt. Do not replay old work or rewrite terminal
audit facts. Reissue the Host ruling, verify `agent-input-preparation-v7`, then
reopen admission after downstream checks. SDK publication alone performs none
of these Host migrations or deployments.

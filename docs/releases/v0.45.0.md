# 0.45.0 release candidate

Prepared from main `cb5c941ffa1d612d7592f71fd3c6814ed66e14fa`. These notes
cover the changes since [0.44.1](v0.44.1.md), the current stable npm release.

## Version set and release gates

The release aligns `@byok-sdk/core`, `@byok-sdk/protocol`, `@byok-sdk/client`,
`@byok-sdk/server`, `@byok-sdk/cloud`, `@byok-sdk/cloud-dataplane`,
`@byok-sdk/ui-runtime`, `@byok-sdk/bot-collaboration`, and `@byok-sdk/keys` at
0.45.0.

The 0.44.1 → 0.45.0 upgrade manifest has **26 entries (12 breaking and 14
additive)**. The breaking entries require a MINOR under the pre-1.0 policy.
[Upgrade manifest](../../packages/client/upgrade-manifest.json) ·
[Version policy](../spec.md#pre-10-package-version-policy)

0.45.0 is the first wire v8 candidate. Its compatibility registration pins
514 envelope and 41 HTTP corpus lines. The published 0.44.1 protocol tarball
serves as the v7 rejection oracle.
[Protocol compatibility evidence](README.md#protocol-compatibility-baseline)

The reviewed registry plan records 0.44.1 as the prior `latest` for all nine
packages. Candidate validation uses exact-SHA CI tarballs. Publication
requires successful release validation on the approved commit, separate
authorization, and registry readback.
[Registry plan](../../scripts/release/registry-expectations.json) ·
[Release runbook](../../deploy/runbooks/release-responsibility.md#release-checklist)

## Host upgrade order

1. Drain tasks, provisioning intents, and device outboxes with 0.44.1. Export
   needed history and retain the old binaries, stores, configuration, and
   credential settings for rollback.
2. Prepare fresh server storage, daemon journals, outboxes, and K4/K8 ledgers.
   Use a new SQLite database for embedded servers or apply migrations through
   `0041_wire_v8.sql` on a fresh PostgreSQL database. Check provider stores
   and prepare a fresh namespaced database for any pre-namespace store.
3. Upgrade the Host, server, daemons, and Pi launcher in the same window.
   Re-enter credentials in the new provider store, re-pair devices, and wait
   for the harness inventory before submitting explicit offers. Update
   dispatch to the v8 target shape and apply the runtime and MCP changes below.
4. Check pairing, provider launch, task admission, and terminal delivery before
   restoring traffic. Roll back with a matching 0.44.1 set of binaries,
   configuration, stores, and credentials.

[Host upgrade checklist](host-upgrade-0.45.0.md#wire-v8-and-the-provider-store-cutover)

## Wire v8 and runtime selection

- Use `lane: 'harness'` with an advertised `harnessId` and a supported
  `selection` for explicit dispatch. Use `lane: 'auto'` to let the device pick
  from harnesses that support device defaults. Hello and presence share the
  device's scanned inventory. Keep the original target when replaying a task
  ID. [#2419](https://github.com/Ancienttwo/byok-sdk/issues/2419) ·
  [#2430](https://github.com/Ancienttwo/byok-sdk/pull/2430)
- Read advertised `defaultModelModes` before omitting a model ID. DSH can
  select a model in its configured route, and OpenCode can take an explicit
  model without a configured list. Ordinary Pi offers can use device defaults
  or an exact catalog ID. For Pi profile offers, use `byok-profile` with the
  persisted binding and an optional per-task model override. Check image
  support for the override. Subscription offers require eligible native
  Claude or Codex sign-in.
  [Harness model selection](host-upgrade-0.45.0.md#harness-model-selection)
- Set `DaemonConfig.runtimeInstallRoot` and call `upgradeRuntime` to stage and
  activate a qualified Claude, Codex, DSH, or OpenCode v2 installation. The
  SDK activates the managed copy after its version and liveness probes pass.
  Read local runtime diagnostics for the installed source and upgrade advice.
  [Managed runtime upgrades](host-upgrade-0.45.0.md#managed-runtime-upgrades)

## Provider stores and model discovery

Each provider store now owns a credential namespace. Use
`inspectProviderProfileStore` before switching. For `PROVIDER_STORE_SCHEMA_STALE`,
create a fresh store on a different path and re-enter keys. Pass matching base
credential settings to the Host and Pi launcher. Pass `adapter`, `auth_mode`,
and `base_url` to `discoverProviderModels`. Provider URL normalization removes
all trailing slashes in one pass.
[Provider store checklist](host-upgrade-0.45.0.md#provider-store-credential-namespace) ·
[Model discovery migration](host-upgrade-0.45.0.md#model-discovery-connection-fields) ·
[#2416](https://github.com/Ancienttwo/byok-sdk/pull/2416)

### Model list unreachable

Handle `MODEL_LIST_UNREACHABLE` when `discoverProviderModels` encounters a
transport failure while connecting or reading a successful response body.
The original error is available in `cause`.
[#2407](https://github.com/Ancienttwo/byok-sdk/issues/2407)

- Opt in to `exposure: 'search'` for qualified ordinary Pi and DSH tasks.
  The task-scoped `byoktools` server exposes `tool_search` and `call_tool`.
  Include `byok-mcp-hub` in fixed SDK helper bundles and handle `mcp-hub` in
  exhaustive `SdkReservedHelperKind` switches. Prepared inputs use `direct`.
  [MCP search qualification and setup](host-upgrade-0.45.0.md#mcp-toolset-search) ·

  Remove DSH `model.keyEnv` and the provider keys from the environment
  allowlist. Use credentials of at least 20 characters and follow the Host
  guide's whitespace and control-character rules. Plain JSON configuration
  cannot supply the callback.
  [Credential setup](host-upgrade-0.45.0.md#dsh-and-agy-provider-keys) ·
  [#2408](https://github.com/Ancienttwo/byok-sdk/issues/2408)

  `MEMORY.md` before launching the filesystem helper. Use
  `resolveAgentMemoryFilesystemHelper` for its verified path.

  [#2410](https://github.com/Ancienttwo/byok-sdk/issues/2410)
- Add exact `approveTools` grants for Codex task MCP servers. Omitted or empty
  lists expose zero tools. Offers with toolsets require Codex CLI 0.48.0 or

## Bot collaboration and local stores

- Pass the Host test runner's `describe`, `it`, and `expect` into each shared
  vector. The testing entry no longer declares a Vitest peer. Observe-mode
  instructions suppress cross-Bot delegation. You can render extra persona
  files and run an idempotent post-write hook under the home lease.
  [#2415](https://github.com/Ancienttwo/byok-sdk/pull/2415)

## Fixed

- After `start()` → `stop()` → `start()` on the same embedded `Daemon`
  instance, `assertion.issue` and `task_assertion.issue` resume. The new
  start resets `shuttingDown` after acquiring the owner lease and checking
  the auth cancellation epoch. `unpair()` invalidates queued starts and any
  start still acquiring the lease. An in-flight `pair()` credential write
  can finish. The control `shutdown` RPC synchronously
  reserves its lifecycle slot before acknowledging the request, so an
  immediate restart waits for teardown.
  [#2434](https://github.com/Ancienttwo/byok-sdk/issues/2434) ·
  [#2436](https://github.com/Ancienttwo/byok-sdk/pull/2436)

## Known issues

- After `stop()` exceeds its shutdown grace deadline, a restart on the same
  `Daemon` instance preserves sealed terminal replay, but the stopped
  control handle stays closed. The timed-out stop retains the store owner
  lease, so a replacement `Daemon` for the same store fails with
  `store_owned` until the lease is released. Wait for the hung teardown to
  settle and retry a clean `stop()`, or exit the original daemon process to
  release the lease, before restarting or starting a new `Daemon` instance.
  [#2437](https://github.com/Ancienttwo/byok-sdk/issues/2437)
- On POSIX, slow zombie reaping can make process-liveness integration tests
  intermittent. The best-effort reap wait can also overshoot its deadline
  when an OS process-table read is slow.
  [#2435](https://github.com/Ancienttwo/byok-sdk/issues/2435)
- Pi 1.5.2 still pins undici 8.12.3, which is affected by six advisories.
  Override undici to 8.12.4 in the Host root, verify the resolved dependency
  tree, and rebuild shipped artifacts.
  [Host override steps](host-upgrade-0.45.0.md#undici-in-the-host-dependency-tree) ·
  [#2098](https://github.com/Ancienttwo/byok-sdk/issues/2098)

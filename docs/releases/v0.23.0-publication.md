## Interruptions and resumption

The `--execute` run was interrupted three times. Each time the registry held
only packages whose bytes equal the frozen artifact, and the next run resumed
through `publish.mjs`'s partial-candidate path (already-published packages
leave the publish set; the rest publish from the same frozen tarballs):

1. One npm web-auth browser confirmation did not complete; the publish of
   `@byok-sdk/cloud` failed with E403. Nothing was written for that package.
2. After `@byok-sdk/client` had published successfully, npm web-auth retried the
   PUT and the second attempt failed with "cannot publish over the previously
   published versions". The first PUT had landed; the registry bytes are the
   frozen tarball (see the integrity table).
3. With every package published, the script's own step-7 readback got a 404 for
   `@byok-sdk/server` because of registry propagation lag, so the run stopped
   before step 8. Once the version was visible, the standalone readback above was
   re-run and passed, and the tag was created by hand as described.

No package was republished, unpublished or repacked.

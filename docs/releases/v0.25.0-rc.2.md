acceptance of [PR #314](https://github.com/Ancienttwo/byok-sdk/pull/314).

## Version set and channel

Eight aligned packages use 0.25.0-rc.2: client, server, core, protocol, cloud,
cloud-dataplane, cloud-do, and ui-runtime. Keys uses 0.10.0-rc.2 and pins the
packed core dependency to 0.25.0-rc.2. All nine packages use the npm dist-tag
`rc`. The stable `latest` versions stay 0.24.0 and keys 0.9.0.

## Fixes since rc.1

- Direct adapter hosts can import `buildRuntimeEnv` from
  `@byok-sdk/client/adapters`. It removes `CLAUDECODE` and `BYOK_*`, while
  preserving loader variables. Adapters still use the Host-supplied environment.
- `createDaemonWithAdapters` rejects `codexSandbox`; set `sandbox` on the
  injected Codex adapter. `createDaemon` keeps its existing option.
- Device credential tests now match the OS store: one product identity shares
  credentials across local store directories. A new directory keeps pairing.
  Unpair or use a new `productId` for a separate enrollment.
- The embedded SQLite server refuses pending non-v2 mailbox bodies with
  `SQLITE_MAILBOX_PROTOCOL_UNSUPPORTED` before serving requests.
- Keys rejects old profile DDL before WAL setup or schema writes. Rejected
  legacy stores retain their original bytes, rows, tables, and indexes.
- The adapters bundle no longer retains Zod through a version constant.
  The same Node 24 ESM consumer fixture decreased from 922759 to 295741 bytes
  without minification. Protocol runtime validation remains unchanged.
- rc.1 release records now reflect npm publication and preserve the missing
  historical tag as a separate unresolved record.

## Mailbox startup and upgrade

Every SQLite open scans the pending mailbox rows and parses their JSON text.
Custom mailbox writers must store protocol wire envelopes with numeric `v: 2`.
An arbitrary application body, malformed JSON, missing major, or another major
now prevents startup. A v2 major alone does not establish full payload validity.
Acknowledged and expired history does not block startup. The check neither
removes rows nor converts old envelopes.

Before upgrading from v1, stop new dispatch and drain with the previous SDK.
Preserve an undrained database for reconciliation. The read-only inspection
query is in [the protocol guide](../protocol.md#sqlite-startup-check-for-wire-major-upgrades).
A fresh server store needs fresh enrollment; changing only client `storeDir`
retains its product-scoped OS credential.

## Publication plan

1. Merge the release preparation and wait for green push CI on its exact SHA.
2. Download `release-pack-<sha>`. Dry run
   `node scripts/release/publish.mjs --artifacts <dir> --tag rc`.
3. Under the owner's publication authorization, run the same command with
   `--execute`. The npm account must require 2FA for writes. Local publication
   carries no GitHub OIDC attestation.
4. Read all nine package versions, integrities, dependency edges, and dist-tags
   back. Only then create and push `v0.25.0-rc.2` at the artifact source SHA.
5. Record the receipt and release assets. Do not migrate or deploy a Host.

The publisher determines dependency order. Partial RC publication cannot be
resumed by republishing or skipping checks; inspect registry state and follow
[the release runbook](../../deploy/runbooks/release-responsibility.md).

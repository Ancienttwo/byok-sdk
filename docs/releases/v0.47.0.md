## Host upgrade order

Existing 0.46.1 server databases, daemon journals, provider stores, and device
pairings carry forward in place. This candidate introduces no Postgres
migration or SQLite store format change.

1. Update Host test doubles typed as `Daemon` to implement `whenCapabilitiesSettled`.
2. Upgrade the Host, server, and daemons to 0.47.0.
3. If your Host dispatches offers based on capabilities immediately after
   startup, await `whenCapabilitiesSettled` and check the returned flags.
   If you wrap a built-in runtime adapter, pass its admission observation
   through to `prepare()` as described in the checklist.
4. Update Antigravity CLI to 1.5.16 if you want to clear the default advisory
   for the previous qualified version, 1.5.11.

[Host upgrade checklist](host-upgrade-0.47.0.md)

## Settled device capabilities

Embedded Hosts can await `daemon.whenCapabilitiesSettled({ signal })` after
`whenOpen()`. Settlement waits for initial memory-backend proof and
deployment discovery to reach a decision and for the server to accept the
corresponding `conn.hello` for that connection generation. A disconnect
resolves the bound waiter with `status: 'disconnected'`. Check the returned
flags before scheduling work that depends on them. `whenOpen()` still returns
without waiting for discovery. On the server, `machines.list()` exposes the
latest accepted known capability flags through `MachineInfo.capabilities`,
omitted before the first handshake.
[Host steps](host-upgrade-0.47.0.md#settled-device-capabilities-2471) ·
[#2471](https://github.com/Ancienttwo/byok-sdk/issues/2471) ·
[#2473](https://github.com/Ancienttwo/byok-sdk/pull/2473)

## Runtime detection and adapter wrappers

- All seven built-in adapters accept `detect(signal?: AbortSignal)`. An abort
  stops an active probe and rejects with `signal.reason`. Task admission
  passes its observation in `RuntimeAdapterPrepareInput.detected`. Adapters
  that reuse the observation validate that it came from the same adapter
  instance and consume it once, then launch the invocation they probed.
  [Host steps](host-upgrade-0.47.0.md#detect-signal-prepare-detected) ·
  [#2469](https://github.com/Ancienttwo/byok-sdk/issues/2469) ·
  [#2476](https://github.com/Ancienttwo/byok-sdk/pull/2476)
- `@byok-sdk/client/adapters` exports `delegateAdmissionDetection(decorator, inner)`.
  Wrappers can opt into the fast Claude or Codex admission probe. If a chain
  member's `detect` changes or the chain has no built-in fast path, admission
  calls the outer wrapper's `detect`. Claude, Antigravity, and Grok now
  expose version evidence in `prepared.detected`. Forward the original
  `input.detected` and the inner `prepared.detected` through wrappers.
  Subscription launches still check login in their launch context.
  [Host steps](host-upgrade-0.47.0.md#decorated-adapters-keep-fast-admission-detection-2495) ·
  [#2495](https://github.com/Ancienttwo/byok-sdk/issues/2495) ·
  [#2496](https://github.com/Ancienttwo/byok-sdk/pull/2496)

## K4 Host ledger reader

`@byok-sdk/server/execution-core` exports `readHostLedger(path)`. It reads every
K4 tenant in tenant order from one committed snapshot, including committed
WAL frames. It opens a private copy and leaves the live database and its
sidecars untouched. A malformed row reports `corrupt_row` while other tenants
remain readable. Back off and retry on `snapshot_changed` or `hot_journal`.
[Host steps](host-upgrade-0.47.0.md#host-ledger-reader-2474) ·
[#2474](https://github.com/Ancienttwo/byok-sdk/issues/2474) ·
[#2486](https://github.com/Ancienttwo/byok-sdk/pull/2486)

## OAR 0.131.0

The client vendors OAR 0.131.0 (up from 0.129.1) as snapshot `19ccd9a`,
projected from `byok/0.131.0` at `28254cd7`. The shared redactor update is
included in that fork pin.
[Vendor provenance](../../packages/client/vendor/oar/19ccd9a/PROVENANCE.md) ·
[#2487](https://github.com/Ancienttwo/byok-sdk/issues/2487) ·
[#2490](https://github.com/Ancienttwo/byok-sdk/pull/2490) ·
[#2497](https://github.com/Ancienttwo/byok-sdk/pull/2497)

- DSH accepts task-scoped MCP servers with stdio `env` or HTTP `headers`.
  The bridge mounts them in memory after startup and fails the start if it
  refuses a mount. `DaemonConfig.mcpToolsets` still rejects these fields.
  Cold profile initialization now serializes across processes sharing a DSH
  profile.
- The shared redactor covers credential-shaped MCP environment and header
  values across Claude, Codex, Grok, Antigravity, OpenCode, and DSH, in addition
  to the existing credential-name and authorization rules. It covers raw
  values and one or two levels of JSON escaping in native events, errors and
  stderr. The limit for values outside those existing rules is described in
  [Known issues](#known-issues).
- Antigravity CLI 1.5.16 replaces 1.5.11 as the qualified version. Under the
  default `warn` policy, an installed 1.5.11 now triggers an advisory.
- The vendored Codex session forwards an explicit sandbox on `thread/resume`.
  The SDK's `CodexAdapter` sets the sandbox at app-server launch and continues
  to omit that field on resume.

## Fixed

- Codex includes usage already observed at interrupt time in the cancellation
  receipt even when the runtime gives no interrupt acknowledgment. If final
  usage arrives before the receipt, it replaces the earlier snapshot.
  [#2467](https://github.com/Ancienttwo/byok-sdk/issues/2467) ·
  [#2484](https://github.com/Ancienttwo/byok-sdk/pull/2484)
- POSIX runtime disposal sends a second group `SIGTERM` when the root exits
  and its owned process group survives. This lets a descendant missed in the
  first signal race exit before escalation to `SIGKILL`.
  [#2483](https://github.com/Ancienttwo/byok-sdk/issues/2483) ·
  [#2489](https://github.com/Ancienttwo/byok-sdk/pull/2489)

## Protocol compatibility

0.47.0 keeps wire v8. Its registration pins the same 514 envelope and 41 HTTP
lines and hashes as 0.46.1. The published `@byok-sdk/protocol@0.45.0` remains
the v8 decoder baseline and 0.44.1 remains the v7 rejection oracle.
[Protocol compatibility evidence](README.md#protocol-compatibility-baseline)

## Known issues

- A short MCP value or a long value made only of letters and `/ - _ .` can
  remain visible when it matches none of the redactor's existing credential
  rules. The redactor handles up to two levels of JSON escaping.
  [Refs #2493](https://github.com/Ancienttwo/byok-sdk/issues/2493)
- Existing macOS launchd plists created before 0.46.1 still need `install()`
  or `repair()` to acquire `ProcessType=Interactive`.
  [0.46.1 residual boundary](v0.46.1.md#residual-boundary)
- Install the Windows `windows-user` service from a non-elevated process.
  An elevated launcher can be invisible to a non-elevated status query
  during crash backoff.
  [Windows residual boundary](v0.45.1.md#residual-boundary)

# 0.30.2 — source candidate

This is release preparation, not a publication record or approval to merge,
tag or publish. Issue #978 holds the Host upgrade scope, and issue #977 holds
the product loop gate. All nine public manifests and their lock records name
0.30.2.

0.30.2 is a PATCH release under a one-release exception to the pre-1.0
policy, as 0.30.1 was. By that policy it would be a MINOR: it adds public API
and Postgres migration 0029, and it has pre-1.0 breaking changes in client,
core, cloud and protocol. All nine public packages move to 0.30.2. Private
packages remain unchanged.

These notes do not say that 0.30.2, or a Host on it, is ready for production.
The product loop gate (#977) is evaluated after release, against the
published 0.30.2. Until the gate records a result, no statement about
production use follows from this release.

Registry state. Public npm metadata read on 2026-10-26 at 10:58 UTC reports
`latest` 0.30.1 for all nine packages. keys 0.30.1 depends on exactly
`@byok-sdk/core` 0.30.1. Version 0.30.2 was absent for all nine packages.
Recheck before publishing. The published 0.30.1 record is in the
[0.30.1 release notes](v0.30.1.md).

## Upgrade notes for Hosts and deployments

The [Host upgrade checklist](host-upgrade-0.30.2.md) lists what a Host does
to move from 0.29.x, 0.30.0 or 0.30.1 to 0.30.2: the fixed revisions, the
Postgres migrations and their order, the `sealed-payload-v1` gate on both
ends, the Breaking changes that touch Host config, the checklist with a
Topology L smoke, and the rollback. The CHANGELOG is the authority; when the
two disagree, the CHANGELOG wins. In short:

- Upgrade the Host first, then daemons and web clients. A 0.30.1 Host
  refuses version 2 key packages, and a 0.30.2 daemon keeps E2EE off on a
  Host that does not declare `e2ee.member.kem-epoch`.
- Before migration 0029, run the `rotate` count from the checklist on a
  0.30.0 or 0.30.1 store. If it is not 0, stay on 0.30.1 and open an issue.
- Remove `hostedJournal` from each daemon config; a 0.30.2 daemon refuses
  it.
- Keep each Agent home root on a filesystem with hard links.
- A hosted Postgres Host passes `proofReceiptRetention` to
  `createByokCloud`, or the new maintenance step reports `not-configured`.

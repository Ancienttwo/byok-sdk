# 0.35.1 — source candidate

This is the release preparation record, not a publication record. It does not
approve any merge, tag or publish. The previous published version is 0.35.0
(see the [0.35.0 notes](v0.35.0.md)), npm `latest` for all nine packages from
2026-11-02 (UTC), tag `v0.35.0` on main `312d5f6b6`. A read-only registry read
on 2026-11-03 (UTC), during the version commit, showed `latest` 0.35.0 for all
nine packages.

0.35.1 is a PATCH release under the default pre-1.0 policy: corrections only,
with no new public API, persistence or security authority. The upgrade
manifest from 0.35.0 holds 1 additive entry, for an example package, and no
breaking entry; `check:upgrade-manifest` fails a PATCH that carries one. The
wire stays v5. All nine public packages move to 0.35.1. Private packages
remain unchanged. `docs/spec.md` names the current aligned release
([version policy](../spec.md#pre-10-package-version-policy)).

These notes do not say that 0.35.1, or a Host on it, is ready for production.

## Release flow

1. The owner asked for a 0.35.1 PATCH on 2026-11-03. Every change below is
   already on main; this PR adds only the version bump, release records and
   derived release data on main `43e8a92b1`.
2. After this PR merges, release validation runs once on the merged SHA
   (`ci.yml` with `release_sha`), and the owner publishes the same artifacts.
   This PR dispatches no validation and creates no tag or GitHub Release.

Publication needs separate owner authorization, after the release matrix
passes on the exact `release_sha`.

## Source and scope

`git log --first-parent v0.35.0..43e8a92b1` lists 9 commits, each one PR
merge. Seven change the packages or the K8 example; two change only docs.

Client:

- #1348 (#1342): `byok-agent status`, doctor and the support bundle no longer
  report a store file as replaced or as changed during the read when only its
  metadata changed (its ctime). A replaced file or changed bytes still fail.
- #1351 (#1350): a failed or interrupted service upgrade rolls back a Host
  directory store whose accepted path ends in `/`, `/.` or `/./`; before,
  restore failed with `EINVAL` on Linux and `recover()` stayed pending.
- #1353 (#1335): Grok no longer declares `isolation.userContext`; a Host that
  gates on it reads `false` for Grok, as for Codex.
- #1368 (#1365): the `device` diagnostics check summary names the reason when
  the device identity cannot be read. The `DiagnosticsSnapshot` type is
  unchanged.
- #1367 (#1366): operational health hardens its `storeDir` once per tracker
  instead of running icacls on every write, which changed the ctime of
  `device.json` and `control.token` on Windows (the likely source of #1342).

Keys:

- #1370 (#1364): the Windows Pi projection ACL query no longer loads
  `System.Web.Extensions` or `JavaScriptSerializer`. The cold-query median in
  CI is about 0.45s, down from 2.65s.

Examples:

- #1347 (#1325): K8 exports `./l-test-host`, an L test Host built only from the
  published packages, and runs its routine and delivery vectors on it. This
  is the manifest entry `k8-l-test-host`; the example package is not one of
  the nine npm packages.

Docs only: ADR-046 (#1354) and the 0.35.0 publication record (#1352).

## Not in 0.35.1

- S4-3, the Windows per-user autostart service unit (#1337), goes to the next
  MINOR.
- The PowerShell host start and exit time on slow Windows machines (#1373).
- The other 0.35.0 exclusions are unchanged (see the
  [0.35.0 notes](v0.35.0.md#not-in-0350)).

## Known limitations

- A Windows Pi projection ACL query still pays the PowerShell host start and
  exit, which can take seconds on a slow VM (#1373).
- Windows has no per-user autostart unit yet (#1337).
- The 0.35.0 limitations are otherwise unchanged (see the
  [0.35.0 notes](v0.35.0.md#known-limitations)); the #1342 status race is
  fixed in this release.
- The PR CI ran checks selected by changed paths and skipped the full macOS
  client suite. The release matrix runs it on the exact `release_sha`.

## Upgrade notes for Hosts and deployments

The [Host upgrade checklist](host-upgrade-0.35.1.md) covers a Host that moves
from 0.35.0 to 0.35.1; a Host on an earlier release applies the
[0.35.0 checklist](host-upgrade-0.35.0.md) first. No Host code or config
change is required. Pin all nine packages to exactly 0.35.1 together. A Host
that gates on Grok's `isolation.userContext` now reads `false`. A Host that
vendored K8 can copy `src/l-test-host.test-support.ts` to run the K8 vectors.

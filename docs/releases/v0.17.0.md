## Breaking storage boundary

Schema v3 replaces the unpublished v2 candidate. Stop all writers and back up
before explicit v1-to-v3/v2-to-v3 adoption. Existing task/message/admission or
advanced cursor history causes refusal: earlier compositions lost receipt facts
and cannot be repaired by guessing. Preserve rejected databases for separate
reconciliation; never delete history/reset cursors to pass migration. V1 requires
explicit pairing after eligible migration. V2 devices remain. Old writers reject v3.
Receipts have no TTL and grow with the database; mailbox cleanup does not remove
identity fences. See packages/server/README.md for exact adoption requirements.

No real database migration, host deployment, capability enablement, recovered
TaskHandle, provider exactly-once guarantee, consumer ACK or management HTTP route
is included. Product host/consumer wiring remains separate. Postgres generic receipt
retention and broader legacy schema constraint validation remain known independent
limitations; this release does not claim those compositions satisfy G1c.

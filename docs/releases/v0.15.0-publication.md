## Publication handoff

- [ ] Commit and land the intended release documents; identify the final source SHA.
- [ ] Read that SHA's push CI and download its matching release-pack artifact.
- [ ] Run the existing `publish.mjs --artifacts` dry-run against that exact HEAD.
- [ ] Restore npm login and verify the intended account and `auth-and-writes` 2FA.
- [ ] Under publication authorization, run the existing driver with `--execute`;
  retain registry identity, integrity, exact dependency and installation readback.
- [ ] Verify the annotated v0.15.0 tag points to the published source and push it
  non-forcibly; verify the remote tag target.
- [ ] Prepare the final GitHub body from `v0.15.0.md`: remove its draft status only
  after registry success, append the final source SHA, CI URL and verified manifest
  SHA-256, and verify the tag-pinned links. Keep this final copy with the receipts.
- [ ] Create the GitHub Release for the existing verified tag using that final body,
  then read back its tag, title, body and published status. Do not use automatic
  tag creation or auto-generated notes as a substitute for the prepared body.
- [ ] Update README/CHANGELOG publication status from observed registry and GitHub
  results. Preserve the original artifact source identity in the release receipts.

The GitHub step, after the preceding checks and authorization, uses
`gh release create v0.15.0 --verify-tag --title 'BYOK SDK 0.15.0 · keys 0.4.1' --notes-file <verified-final-body-file>`.
The final body is a derived copy of the reviewed release notes with release receipts;
it is not a second independently authored changelog.

The missing v0.14.0 GitHub Release page is historical publication bookkeeping.
It does not make npm 0.14.0 unpublished and is not permission to retag or republish it.
Signing/distributing host binaries, production SQL application and downstream
rollout remain governed by the [release responsibility runbook](../../deploy/runbooks/release-responsibility.md).

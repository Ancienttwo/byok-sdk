# 0.25.0-rc.1 / keys 0.10.0-rc.1: release candidate (prepared; not published)

Current manifests: aligned train `0.25.0-rc.1`, independent keys `0.10.0-rc.1`.
The release owner approved this version set and the npm dist-tag `rc` on
2026-10-09. This document records source preparation. It is not proof of npm
publication, and it does not approve npm execution.

## Summary

0.25.0-rc.1 is the first train after 0.24.0. It applies the minimal-guardrails
decision ([ADR-037](../architecture/adr-2026-10-07-minimal-guardrails.md)): the
SDK bridges a Host to the user's own local agents, and each agent keeps its own
guardrails. The SDK permission policy, executable attestation, launch-cwd
wrapper and egress sanitizer are removed. The wire protocol moves to v2. The
candidate also moves the official Pi runtime to 1.1.0 and the private OAR
source to 0.44.0, and it fixes the downstream issues #290 to #293.

This train has many breaking changes. Read "Upgrade steps" before you upgrade.

## Breaking changes since 0.24.0

### Protocol v2

- `PROTOCOL_VERSION` moves from 1 to 2. There is no v1 reader. A v1 envelope
  is rejected.
- v2 removes the task offer `policy` (`PermissionPolicy`), the runtime
  capability `permissionModes` and the input-preparation `permissionMode`.
- v2 removes the egress `activity.mode` field, the `metadata-status` mode and
  the `sanitizer_rejected` drop reason.
- v2 removes the input-preparation `toolImplementationKinds` (now `toolNames`),
  the readiness reason `executor_identity_unproven` and the error code
  `launch_boundary_unavailable`.
- See [docs/protocol.md](../protocol.md) and the frozen v2 goldens in
  `packages/protocol/src/__tests__/golden/`.

### Removed configuration keys and public APIs

`createDaemon` throws when one of these removed `DaemonConfig` keys is set:

- `permissionDefaults`
- `mcpLaunchCwd`
- `agentEgress.sanitizer`
- `toolImplementationAuthority`

These are also removed without a throw: `DaemonConfig.runtimeEnvironment`,
`RuntimeAdapterDescriptor.environmentRequirements` and
`RuntimeAdapterDescriptor.mcpServerLaunch`. The client also removes the
tool-implementation identity exports, the trusted launch-cwd exports, the
egress sanitizer types, the `mcp-env` helper kind,
`CodexAdapterOptions.sdkHelperHost`, `RuntimeAdapter.detectInstallation` and
the `runtime_version_unsupported` refusal reason. The package no longer ships
`bin/byok-launch-cwd.mjs`. The CHANGELOG lists each removed name. The API
goldens in `api-surface/` show the complete change.

### Retired `@byok-sdk/implementation-identity`

The SDK no longer attests tool or runtime executables. The package is removed
from the workspace, and `check:release-graph` refuses it as a public package.
Remove it from your dependencies. The client no longer re-exports it.

### keys launcher grammar

- The Pi provider launcher drops `--launch-binding` and takes
  `--pi-projection-dir`.
- `--pi-fixed-args` is now only the single-file re-entry prefix.
- `buildPiProviderChildEnvironment` takes `projectionDir` and keeps an ambient
  `PI_PACKAGE_DIR`.

### Minimal guardrails and YOLO launch (ADR-037)

- An ordinary Claude session starts with `--dangerously-skip-permissions`.
  Codex keeps `approvalPolicy: never`. Pi pre-trusts the session cwd.
- Runtimes inherit the user's own agent configuration: Claude loads the user
  MCP configuration, settings, deny rules and hooks. Pi loads the user
  extensions and skills.
- A task child gets the full daemon environment. The daemon removes only
  `CLAUDECODE` and its own `BYOK_*` names.
- Codex has a new sandbox setting, `DaemonConfig.codexSandbox`. The default
  stays `danger-full-access`. `inherit` uses the user `config.toml`.
- The runtime and its MCP servers start in the session cwd. There is no
  trusted launch cwd.
- Codex task MCP servers go to Codex in the thread config. A user
  `config.toml` entry with the same name cannot disable a task server.
- The SDK keeps the toolset registry, the Host content-read gate, the Agent
  home and Git workspace leases, the process-tree kill and the BYOK key
  custody.

### Agent egress passthrough

Agent egress goes to the Host as the runtime produced it. The SDK does not
filter, redact or omit content. The default policy revision is `default-v1`
with `maxCoalesceMs: 250` and `maxEventBytes: 262144`. A reliable payload that
is not valid JSON or is larger than 256 KiB is refused with
`invalid_envelope`. The Host decides what to store and show.

### Pi 1.1.0

- The official Pi runtime moves from 1.0.4 to 1.1.0 (all nine
  `@earendil-works/*` packages, upstream `abe508e1`).
- The adapter reports `agent_settled.aborted` as a non-retryable failure.
- The SDK reads the installed indirect Pi packages and does not gate them.
- `closureDigest` changes. A preparation compiled before this train declines
  with `preparation_runtime_identity_mismatch`.

### OAR 0.44.0

- The private OAR source moves from 0.25.0 through 0.29.0, 0.33.1 and 0.37.0
  to 0.44.0. See the upgrade notes in `docs/notes/` (2026-10-07 to 2026-10-09).
- A Codex prompt or steer with empty text and no images is refused with
  `unsupported` before any RPC. A Codex task with an empty instruction does
  not start.
- When Codex does not end an interrupted turn in 10 s, the abort is accepted
  and the app-server is killed. An in-flight control then records `rejected`
  with code `runtime_exited`.
- The SDK event projection reads native frames only, so its events do not
  change.

### Codex version advisory

Codex detection no longer refuses a Codex CLI version other than 0.160.0.
Another version is `available` with
`advisory: { reason: 'runtime_version_unqualified', qualifiedVersion }`, and
the daemon logs a warning. Native contracts stay probed.

### Other changes

- `SqliteSchemaError` with a `code` for every SQLite open refusal (#292).
- `requestTimeoutMs` on the keys provider clients (#290).
- A single-file bundle of `@byok-sdk/client` no longer runs a CLI on import
  (#291).
- `undici` 8.11.2 (#293).
- Detection probes get the task child environment.
- A cancel that aborts a runtime start no longer quarantines the runtime.
- The Pi launch configuration is written once, 0600, in a new 0700 directory.
- On POSIX, disposal also ends descendants that left the runtime process
  group, while they are still below the runtime root.

## Upgrade steps

1. Upgrade the server and the client together. Protocol v2 has no v1 reader.
   Before the upgrade, drain the v1 mailbox rows.
2. Prepare again each prepared record. The input-preparation record moves to
   version 10, the prepared binding and surface digests to v3 and the Pi MCP
   fingerprint to v2. An old record declines with
   `preparation_tool_binding_digest_mismatch` or
   `preparation_runtime_identity_mismatch`.
3. Remove the removed `DaemonConfig` keys. Remove
   `@byok-sdk/implementation-identity` from your dependencies.
4. Run the daemon as a normal OS user. Claude refuses
   `--dangerously-skip-permissions` as root unless the environment marks a
   sandbox.
5. A single-file product sets `sdkHelperHost: { mode: 'self-executable' }` and
   sets `PI_PACKAGE_DIR` to its Pi asset root. Every Pi lane re-enters the
   product executable.
6. If you need isolation, use the agent's own sandbox and deny rules, or an OS
   boundary (container, VM or separate OS user). The SDK no longer supplies
   one.
7. Update the keys launcher arguments to `--pi-projection-dir`.
8. Decide in the Host which egress content to store and show. The SDK no
   longer filters, redacts or omits it.

Install the candidate with the explicit tag or exact version:

```sh
npm install @byok-sdk/server@0.25.0-rc.1 @byok-sdk/client@0.25.0-rc.1
npm install @byok-sdk/keys@0.10.0-rc.1
```

These commands work only after the candidate is published.

## Known residuals

- **POSIX descendant residual.** Disposal reaches only the processes that are
  still below the runtime root when the SDK reads the process table. A process
  whose parent exited before that read is re-parented to init, and the SDK does
  not end it. Real Claude and Pi run each shell command in a session of their
  own, so a background job (`cmd &`) outlives `close()` and `daemon.stop()`.
  OAR has the same limit. The owner ruled: document it, add no new mechanism.
- **Flaky tests.** `tasks/todos.md` records timing flakes that are not
  measured: cloud-do `test/wake-inbox.test.ts` (Node 26 CI job), keys
  `pi-projection-windows.test.ts` (Windows non-admin leg), and the older
  load-sensitive client tests (`pi-mcp-launch-cwd`, `terminal-projection-selection`,
  `pi-prepared-launcher`). The owner ruled report-only. Tests and timeouts do
  not change.
- `codexSandbox: 'inherit'` is proven by argv only. The Pi keys-profile lane
  was not run in the real-agent acceptance.

Steps before execution:

1. Merge the release commit. Get the green push CI run for that exact SHA and
   download its `release-pack-<sha>` artifact.
2. Dry run `node scripts/release/publish.mjs --artifacts <dir> --tag rc`. Before
   any write, the publisher checks that each exact version is absent and that
   `latest` is still 0.24.0 / 0.9.0.
3. Get a separate approval for npm execution. Then run the same command with
   `--execute`. The publisher reads the registry back and only then creates the
   annotated tag `v0.25.0-rc.1`.
4. Push the tag separately.

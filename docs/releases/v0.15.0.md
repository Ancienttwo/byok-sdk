# BYOK SDK 0.15.0 · keys 0.4.1

> Draft — prepared, not yet published. Install commands below apply after npm publication and registry verification.

This release adds device diagnostics for embedded hosts and explicit enrollment
metadata repair, strengthens durable task/message recovery, and makes runtime
probe failures observable. It includes a breaking custom adapter return contract.

## Packages

The nine aligned SDK packages move from 0.14.0 to **0.15.0**.
`@byok-sdk/keys` moves from 0.4.0 to **0.4.1** so its packed dependency is exactly
`@byok-sdk/core@0.15.0`; there are no keys API or provider changes in this update.
The bundled Pi runtime remains pinned to **0.85.1**.

```sh
npm install byok-sdk@0.15.0
# For applications that use the independent keys package:
npm install @byok-sdk/keys@0.4.1
```

## Device diagnostics and explicit repair

- Public `diagnoseDevice` lets embedded hosts provide their actual adapters and
  consume a structured device diagnostic report.
- Public `repairDeviceEnrollmentMetadata` and
  `doctor --repair restore-enrollment-metadata` restore missing or valid-but-stale
  non-secret metadata from existing OS enrollment authority. The caller must
  explicitly confirm and supply the expected tenant and device. Repair uses the
  existing store lease and verifies the resulting metadata.
- Malformed/legacy metadata, missing or mismatched authority, and concurrent
  ownership are refused. Repair does not renew or replace credentials, rebuild a
  journal, or rerun tasks. Existing `doctor --fix` remains health-only.

Device diagnostics do not prove that every Agent on the device is ready.
See the [integration guide](https://github.com/Ancienttwo/byok-sdk/blob/v0.15.0/docs/agent-diagnostics-integration.md).

## Durable execution and Agent messages

- JSONL compaction preserves record boundaries for subsequent appends and
  reopen. Uncertain writes quarantine the writer, while cursor persistence and
  compaction use durability barriers.
- Required-message refusal settles through the existing terminal/disposal path.
  Cancellation durably revokes staged messages before terminal delivery,
  including cancellation before runtime startup completes.
- Terminal message evidence no longer permanently consumes send quota; explicit
  durable archival preserves its audit record.
- Recovery respects persisted message dispositions, immutable offer ownership
  and terminal receipts. Pending terminal decisions fence re-admission, and
  competing claims cannot acknowledge ownership they did not acquire.
- Adapter admission/prepare waits honor deadlines and cancellation. Processes
  already owned by an adapter still require actual disposal receipts.

These fixes do not automatically salvage damaged logs or promise exactly-once
external business effects. Retain failed state for an explicit recovery procedure.

## Protocol and runtime integration

- Add capability-gated `afterSeq` mailbox navigation independently of durable ACK,
  bounded to 4096 sequences plus one returned page.
- Add the `custom-harness` contract for explicit inventory, selection, immutable
  claim identity and terminal echo. Built-in runtime identities are unchanged.
- Reject unsupported envelope wire majors before admission. Client long-poll
  leaves unsupported executable envelopes unacknowledged. Wire major **1**
  remains the supported version; SDK version numbers do not determine capability.
- Bound sensitive runtime output and remove prompt/MCP environment values from
  affected command-line arguments. Official packaged CLI helpers are exercised
  through real MCP calls on Windows, macOS and Linux.

## Upgrade from 0.14.0

1. **Custom adapters:** return `RuntimeDetectResult.kind` as `available`,
   `not-found`, `not-executable`, `timeout`, or `probe-failed`. Only `available`
   carries optional version/auth observations. Remove old `present` return values
   and mixed shapes. UI presence is derived from `kind === 'available'`.
2. **Postgres-backed servers:** apply
   [`0021_custom_harness_identity.sql`](https://github.com/Ancienttwo/byok-sdk/blob/v0.15.0/deploy/sql/0021_custom_harness_identity.sql)
   through the deployment's migration procedure before deploying the new server.
   npm installation does not run this migration.
3. **SDK dependencies:** update the aligned SDK packages together and retain exact
   internal dependency closure. If using keys, select 0.4.1 with this SDK train.
4. **Local Agent hosts:** await the existing daemon stop/owned-resource lifecycle
   and preserve device identity, store and canonical Agent home. A rejected stop
   does not authorize starting a second owner. Do not use unpairing or deleting
   local state as an upgrade mechanism.

The hash-only journal predecessor rejection and keys provider-store changes
belong to **0.14.0**, not new 0.15.0 migrations. Applications upgrading from an
earlier release must also follow the
[0.14.0 changelog](https://github.com/Ancienttwo/byok-sdk/blob/v0.15.0/CHANGELOG.md).

## Scope and further reading

The SDK release does not deploy a host application, update a Salesko pin, or
qualify a production updater or live OS credential provider. Those integrations
require their own rollout evidence.

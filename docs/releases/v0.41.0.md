## Changes since 0.40.0

- **Wire v6.** The envelope wire moves from v5 to v6 (`PROTOCOL_VERSION = 6`); 0.40.0 is the last v5 release. A v5 peer cannot read v6 and there is no v5 reader or negotiation, so the server side and the daemons upgrade together. The runtime capability `isolation.userContext` is replaced by one bit per user-level source (#1572, #1574–#1576), and v6 retires every v5 gate both sides always advertised and requires `expiresIn` on token responses (#1573). A store that still holds a pending v5 row refuses to open and is left unchanged; there is no drain tool. `golden/v6.releases.json` registers 0.41.0 as the first v6 release. See the [wire v6 migration](../migrations/wire-v6-isolation-sources.md).
- **Keys store migration.** `migrateProviderProfileStore(path)` migrates a keys SQLite profile store written with an earlier `provider_kind` CHECK set in one transaction, keeping every profile and its credential-store key reference, so users do not re-enter keys. The Host calls it before opening the store; opening never migrates (#1562).
- **Store precheck `migration-required`.** A store precheck can report that the candidate opens a store only after its explicit migration. `ServiceInstallationOptions.migrate(versionDir)` runs the Host's migration after the store snapshot and prechecks again; without it the upgrade fails with `store_migration_required` and the store is unchanged (#1577).
- **Pi subagents.** Single-file products offer foreground Pi subagents again: `copyPiRuntimeAssets` writes pi-subagents 0.87.0 (an exact pin, from 0.83.1) and the SDK child gate extensions into the Pi asset root, about 22 MB more. Background runs stay refused in a bundled product, and the `auto` gate judges each workflow child launch (#1589, #1592).
- **Sealed Pi host removed.** The private import `#byok-pi-runtime-host-sealed` and its build are removed; a bundle that redirects to it fails at bundle time and points at `#byok-pi-runtime-host` instead (#1589, #1601).
- **Codex `agentUserContext: 'excluded'`.** Opt-in; an Agent task runs in an SDK-owned `CODEX_HOME` without the user's `AGENTS.md`, skills or memories, and Codex declares `userInstructions` and `userMemory` (#1565, #1594).
- **OpenCode on macOS.** The OpenCode adapter declares `platforms: ['darwin']` and a default version policy qualified at 2.2.6, so a Host can enable it on macOS. macOS arm64 has no task evidence yet and Windows stays undeclared (#1593, #1596).

The [client upgrade manifest from 0.40.0](../../packages/client/upgrade-history/0.40.0-0.41.0.json) has three breaking entries (`wire-v6-isolation-sources`, `wire-v6-retired-gates`, `token-lifetime-expires-in`) and four additive entries (`keys-profile-store-migration`, `codex-agent-user-context`, `store-migration-required-verdict`, `native-assets-archive-path`). The sealed host removal is breaking but has no manifest item. There is no new `deploy/sql` migration and no SQLite schema change. Other changes include the Claude output-style exclusion (#1564), the `copySdkNativeAssets` `archivePath` option (#1567), the `/tmp` socket fallback cleanup (#1580), daemon-local completion timing (#1549), a successor daemon's sockets kept on teardown (#1610), canonical Windows session environment names (#1611, #1595), a bounded wait for a brief agent-home lock holder (#1604), concurrent first directory create (#1605) and the bounded `subagent_launch` approval card (#1597). The CHANGELOG records the full changes.

## Not in 0.41.0

The OpenCode Go key check ([#1551](https://github.com/Ancienttwo/byok-sdk/pull/1551)) is not in this release. Until it ships, reach OpenCode Go through a gateway you run yourself with a custom keys profile, as described in [Your own OpenAI-compatible gateway](../../packages/keys/README.md#your-own-openai-compatible-gateway). SDK key custody for OpenCode waits for [#1586](https://github.com/Ancienttwo/byok-sdk/issues/1586); the SDK holds no OpenCode key.

## Known limitations

- No published v6 decoder is pinned as an oracle yet, so cross-release v6 gates stay unproven until a later release pins one.
- OpenCode keeps no isolation guarantee, `auto` tool authorization is unsupported, and task-scoped Host MCP is unqualified.

## Upgrade notes for Hosts and deployments

Follow the [Host upgrade checklist](host-upgrade-0.41.0.md): stop the 0.40.0 deployment, migrate keys profile stores, start the 0.41.0 server side and daemons together, and start on a new store where one refuses. Review the manifest and the release's platform and rollback boundaries before upgrading.

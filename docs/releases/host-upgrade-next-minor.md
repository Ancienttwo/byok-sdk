# Host upgrade to the next MINOR

Draft checklist for a Host moving from 0.42.0 to the next MINOR. Earlier Hosts must first apply the preceding Host upgrade checklists. Release preparation must review this guide against the final train before assigning a version and publishing it.

## Pi cache warming stops at settlement (#1949)

No configuration change is needed. Every SDK Pi RPC session now caps its settings getter at Pi's native `"streaming"` cache-warming mode, preserving `"off"` without rewriting device settings, instead of answering each idle `cache_warming_decision` with `stop`. Pi cancels the warmer at settlement and revalidates pending decisions before dispatch, so a late `"warm"` answer cannot send a refresh after settlement. Under `agentUserContext: 'inherit'` a device setting of `"off"` still turns warming off; under `excluded` the session's settings are in memory and do not read the device file.

## Enrollment clear is scoped to its store (#1964)

`clearDeviceEnrollment` and `Daemon.unpair()` no longer delete another store's credential or staged first pairing under the same `productId`, except a credential that a running daemon's token renewal writes back while the clear runs: renewal does not take the lock yet (#2034). A Host that switches on `DeviceEnrollmentClearError.code` handles the new code `pairing_attempt_unattributed`: the OS entry holds a first-pairing attempt staged by 0.42.0, which names no store, and nothing was cleared. When no other store of this `productId` is pairing, call `clearDeviceEnrollment({ productId, storeDir, clearUnattributedAttempt: true })` once the daemon has exited. `store_not_bound` now also covers a first-pairing attempt another store staged. A first-pairing attempt now carries `storeIdentity`; an injected `DeviceCredentialBackend` must store and return every attempt field, or a clear refuses the store's own attempt as `pairing_attempt_unattributed`. Pairing applies the same rule (#2033): it reuses only its own store's staged attempt and otherwise throws the new `FirstPairingAttemptRefusedError`, with `store_not_bound` (another store's attempt; pair with `replaceOtherStore` to discard it) or `pairing_attempt_unattributed` (clear it as above, then pair again). A clear or pairing that waits more than 30 seconds for another store's clear or pairing of the same `productId` fails; the clear deletes nothing.

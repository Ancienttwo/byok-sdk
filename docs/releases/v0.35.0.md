## Source and scope

`git log --first-parent v0.34.0..df5163450` lists 8 commits, each one PR
merge. The train merge #1341 carries #1326, #1330, #1327, #1340 and #1339
(which contains #1334), each merged at its accepted head. The commits are
grouped by area.

Daemon config and adapters:

- #1332 (#1315): `DaemonConfig.runtimes.pi.packageDir` (and
  `PiAdapterOptions.packageDir`) is the only source of the Pi asset root. It
  must be absolute; the SDK sets `PI_PACKAGE_DIR` from it for Pi and the
  pi-host helper only, and a `PI_PACKAGE_DIR` in the login-shell snapshot or
  the Host environment no longer reaches Pi. Breaking in client (manifest
  `pi-package-dir-config`). `createRuntimeAdapters(config)` from
  `@byok-sdk/client/adapters` builds the adapters `createDaemon` builds, for a
  Host that decorates adapters for `createDaemonWithAdapters`. Additive
  (manifest `runtime-adapters-factory`).
- #1330 (#1323): `RuntimeAdapterDescriptor.progressEventsAreMessages` is
  replaced by `progressMessageBoundary` (`'event'` or `'session'`). The daemon
  binds the members a descriptor declares once, when `start()` returns; a
  `'session'` adapter whose Session lacks `progressStartsMessage()` fails at
  start with `runtime_session_incomplete`. Breaking in client (manifest
  `client-progress-message-boundary`). `ExecutionRecordUnknown` gains
  `evidence_missing` for an `event-stream` adapter whose Session has no
  `evidence()`. Additive (manifest `client-execution-record-evidence-missing`).
- #1327 (#1324): `approveTools` on a toolset server is a grant, projected only
  to a runtime that declares `mcpToolApprovals: true` (Codex today). It takes
  no part in admission or runtime selection, and the two "cannot enforce Host
  MCP tool approvals" declines are removed. An explicitly selected Claude, Pi
  or Grok now runs such a task, and automatic selection with Claude and Codex
  both present picks Claude by `DEFAULT_RUNTIME_PREFERENCE`. No field, default
  or wire shape changes. Breaking in client by behavior only; no manifest
  entry.
- #1340 (#1338): Pi `agentUserContext: 'excluded'` loads the instruction files
  in the Agent home (`lease.canonicalHome`) and below it, as Claude does with
  its `CLAUDE.md`, and still excludes user-level resources and every directory
  above the home. The ordinary Pi launch config is v10 with `agentHome`; v9 is
  refused, and an excluded Agent task without a sealed canonical-home lease is
  refused before spawning. No manifest entry.

Service installation and upgrade:

- #1334 and #1339 (#1328): `ServiceInstallationOptions.daemonStores()` lists
  every daemon store a service process owns; upgrade, rollback and recover
  stop all of them under an owner lease and the store gate of each. The stop
  reclaims a store a crashed daemon left behind instead of reporting
  `store_busy`. New code `daemon_stores_invalid`. Additive (manifest
  `client-service-daemon-stores`). The precheck prints
  `{ "stores": ServiceStoreVerdict[] }`, receipts and errors hold
  `ServiceStoreVerdict`, a directory store is snapshotted as a whole tree, the
  precheck output is checked more strictly, and a failed copy is the new code
  `snapshot_failed`. Breaking in client (manifest
  `client-service-store-verdicts`).
- #1326 (#1316): `byok-agent upgrade check --from <version> [--json]` and
  `checkUpgradeFrom` list every breaking manifest entry released after a
  version and check that the installed `@byok-sdk/*` packages share the
  client's version. The client tarball ships every released manifest since
  0.31.0 in `upgrade-history/`. Additive (manifest
  `client-upgrade-check-from`).

keys:

- #1313 (#1310): `WindowsCredentialManagerSecretStoreOptions.systemRoot`, the
  absolute Windows system directory PowerShell is started from. Omitted, the
  store reads `process.env.SystemRoot` once at construction. Additive
  (manifest `keys-windows-credential-system-root`).

Examples (K8):

- #1331 (#1318) and #1336 (#1320): K8 history rows from an external history
  authority carry an optional `reply`, and K8 gains the owner call
  `cancelHostIntent(key)`. Additive (manifest `k8-history-reply`).

Tests and research:

- #1314 (#1311): the epoch-2 KEM rotation test waits for the rotation to
  settle before it asserts the log. Test only.
- #1333 (#1329): the Windows per-user autostart probe and its research note
  [2026-11-02-windows-user-autostart-probe.md](../researches/2026-11-02-windows-user-autostart-probe.md).
  The probe workflow was removed in the same PR.

Records:

- #1312 records 0.34.0 as published, rebaselines the upgrade manifest on
  0.34.0 and adds the 0.34.0 store fixture.

Wire and persistence. `packages/protocol` and `packages/core/src` do not
change since `v0.34.0`. The v5 corpus still has 342 envelope lines and 30
HTTP lines, and `v5.releases.json` registers that corpus for 0.35.0 next to

## Upgrade notes for Hosts and deployments

The upgrade manifest (`packages/client/upgrade-manifest.json`, shipped in the
client package) lists each Host-visible API, config and example change from
0.34.0 with its impact, summary and migration link. The CHANGELOG 0.35.0
section also holds the behavior-only `approveTools` change. The
[Host upgrade checklist](host-upgrade-0.35.0.md) covers a Host that moves from
0.34.0 to 0.35.0; a Host on 0.30.2 to 0.33.0 applies the
[0.34.0 checklist](host-upgrade-0.34.0.md) first. In short:

**No wire cut.** 0.35.0 speaks wire v5 like 0.34.0, so no drain is needed for
the wire. Pin all nine packages to exactly 0.35.0 together.

**Host code.** Move `PI_PACKAGE_DIR` into `runtimes.pi.packageDir` (absolute)
and drop it from `runtimeEnvironment.pass` and the environment. Replace
`progressEventsAreMessages` with `progressMessageBoundary`, and forward every
declared member when wrapping a Session. Read `ServiceStoreVerdict` from the
service precheck, receipt and error, and handle the new codes
`snapshot_failed` and `daemon_stores_invalid`.

**Runtime selection.** A Host that used `approveTools` to keep a server on
Codex pins the runtime explicitly; automatic selection now picks Claude over
Codex.

**Pi behavior.** Under `agentUserContext: 'excluded'` Pi loads the Agent
home's own `AGENTS.md`.

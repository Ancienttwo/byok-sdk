## Release flow

1. The owner decided on 2026-11-03 that every remaining PR goes into this
   release. 0.35.1 was prepared but not published, and the remaining PRs carry
   breaking changes, so the release is the MINOR 0.36.0 and carries the

2. After this PR merges, release validation runs once on the merged SHA
   (`ci.yml` with `release_sha`), and the owner publishes the same artifacts.
   This PR dispatches no validation and creates no tag or GitHub Release.

Publication needs separate owner authorization, after the release matrix
passes on the exact `release_sha`.

## Source and scope

`git log --first-parent v0.35.0..de9c7960e` lists 15 commits, each one PR
merge. The train merges three accepted heads with `git merge --no-ff`: the K8
chain tail #1372 (which carries #1355, #1361, #1360, #1359 and #1363), #1345
and #1379. The changes are grouped by area.

Client:

- #1345 (#1337): `ServiceDefinition.windows` is the union
  `ServiceWindowsOptions`. `{ scope?: 'machine'; winswBin; installDir? }` is
  the WinSW Windows Service as before, and `{ winswBin }` still compiles. The
  new `{ scope: 'user'; stop: ServiceProgram }` autostarts at the user's logon
  from a Startup `.cmd` and a batch launcher under `<storeDir>\service`, with
  no SCM registration and no administrator. A `stop` program that exits
  non-zero is the new `ServiceUnitError` code `service_stop_failed`. Breaking
  in client (manifest `service-windows-user-scope`). `byok-agent install` on
  Windows still installs only the WinSW service.
- #1348 (#1342): `byok-agent status`, doctor and the support bundle no longer
  report a store file as replaced or as changed during the read when only its
  metadata changed (its ctime). A replaced file or changed bytes still fail.
- #1351 (#1350): a failed or interrupted service upgrade rolls back a Host
  directory store whose accepted path ends in `/`, `/.` or `/./`; before,
  restore failed with `EINVAL` on Linux and `recover()` stayed pending.
- #1353 (#1335): Grok no longer declares `isolation.userContext`; a Host that
  gates on it reads `false` for Grok, as for Codex.
- #1368 (#1365): the `device` diagnostics check summary names the reason when
  the device identity cannot be read. The `DiagnosticsSnapshot` type is
  unchanged.
- #1367 (#1366): operational health hardens its `storeDir` once per tracker
  instead of running icacls on every write, which changed the ctime of
  `device.json` and `control.token` on Windows (the likely source of #1342).

Protocol:

- #1379 (#1374): `validateResultOutcome` takes `({ contract, schema },
  outcome)`; the `(schema, outcome)` form is gone. For the SDK-defined
  `bot-turn-outcome.v1` contract it runs the contract rules after the schema
  check: a repeated `ask_user` option id (`duplicate-option-id`) or a string
  that is blank after `trim()` outside `confirmable_action[*].draft`
  (`blank-text`) fails with the new `ResultOutcomeCheck` reason
  `contract-mismatch`. The device applies it on `submit_result`, so the model
  corrects the outcome in the same Turn. Breaking in protocol (manifest
  `result-outcome-contract-rules`); the wire and the corpus do not change.

Keys:

- #1370 (#1364): the Windows Pi projection ACL query no longer loads
  `System.Web.Extensions` or `JavaScriptSerializer`. The cold-query median in
  CI is about 0.45s, down from 2.65s.

Examples (K8 and H), all in the manifest entry `k8-l-test-host`, breaking
because of #1374:

- #1347 (#1325): K8 exports `./l-test-host`, an L test Host built only from the
  published packages, and runs its routine and delivery vectors on it.
- #1355 (#1319): an external team snapshot Bot can carry
  `participation: 'suspended'`; the Bot takes no new work and its open work
  ends as for an archived Bot.
- #1361 (#1357): `BotCollaboration.setModels(models)` replaces the Host's
  model templates at run time, and construction and a restart re-project them
  onto existing Bots. A Bot whose template is missing blocks each Turn with
  `Unavailable model: <name>` instead of refusing the snapshot.
- #1360 (#1356): K8 `BotOptions.hostIntentMessages` sends an Agent message of a
  Host intent to the Host's message handler of the same name.
- #1359 (#1321): the owner command `create_room` and the external rooms mode
  (`rooms: 'external'`).
- #1363 (#1358): H re-projects the scope config's model templates at each
  `sync` and each Bot routine command.
- #1372 (#1362): the H store option `hostIntentMessages`, and K8 exports
  `./rules/message`.
- #1379 (#1374): K8 refuses an outcome that breaks the `bot-turn-outcome.v1`
  rules whole (the K4 intent ends `outcome_failed`); its action-level
  `Duplicate option id` refusal is removed.

Release records, docs and CI:

- #1352: the 0.35.0 publication record, and the upgrade manifest rebaselined
  on 0.35.0 with the new archive `upgrade-history/0.34.0-0.35.0.json`. Both
  files ship in the client tarball.
- #1376: the 0.35.1 preparation, never published. This PR replaces its
  release notes and Host checklist with the 0.36.0 ones.
- #1354: ADR-046; #1380 (#1377): the main merge policy ADR (docs only).
- #1322: the architecture refresh, ArchContext model and archimap (docs and
  tooling only).
- #1382 (#1378), #1384 and #1388: CI job selection, the retired package
  identity scan, and the Worker consumer imports read without acorn (CI
  only).

Wire and persistence. `packages/core/src` does not change since `v0.35.0`.
`packages/protocol` changes only `validateResultOutcome` and its contract
rules (#1374). The v5 corpus still has 342 envelope lines and 30 HTTP lines,
and `v5.releases.json` registers that corpus for 0.36.0 next to 0.34.0 and
0.35.0. There is no new Postgres migration and no SQLite schema change:
0.36.0 opens the stores 0.35.0 wrote.

## Upgrade notes for Hosts and deployments

The upgrade manifest (`packages/client/upgrade-manifest.json`, shipped in the
client package) lists each Host-visible API, config and example change from
0.35.0 with its impact, summary and migration link. The
[Host upgrade checklist](host-upgrade-0.36.0.md) covers a Host that moves from
0.35.0 to 0.36.0; a Host on an earlier release applies the
[0.35.0 checklist](host-upgrade-0.35.0.md) first. In short:

**No wire cut.** 0.36.0 speaks wire v5 like 0.35.0, so no drain is needed for
the wire. Pin all nine packages to exactly 0.36.0 together.

**Host code.** Narrow `ServiceDefinition.windows` on `scope` before reading
`winswBin`, and add `service_stop_failed` to an exhaustive switch over
`ServiceUnitErrorCode`. Call `validateResultOutcome({ contract, schema },
outcome)` with the offer's contract id, and add `contract-mismatch` to a
switch over `ResultOutcomeCheck` reasons.

**K8.** A Host that vendored K8 copies the changed `src/rules` files, the
Layer 2 files `src/host.ts` and `src/index.ts`, and the Layer 3 vectors
([VENDOR.md](../../examples/bot-collaboration/src/VENDOR.md)).

**Grok.** A Host that gates on `isolation.userContext` now reads `false` for
Grok.

# 0.48.0 candidate (2026-11-28, UTC)

0.48.0 is the MINOR after [0.47.1](v0.47.1.md). It keeps wire v8.

## Version set and release gates

All nine public packages move together to 0.48.0 (`core`, `protocol`,
`client`, `server`, `cloud`, `cloud-dataplane`, `ui-runtime`,
`bot-collaboration`, and `keys` under `@byok-sdk`). All nine still report
0.47.1 on npm `latest`. Publication requires separate authorization,
exact-SHA release validation, and registry readback.

The 0.47.1 → 0.48.0 upgrade manifest contains three breaking and seven
additive entries. Existing server databases, daemon journals, provider
stores, device pairings, and Pi durable SQLite replicas carry forward in
place. [Upgrade manifest](../../packages/client/upgrade-manifest.json) ·
[Release process](README.md#publishing)

## Host upgrade order

1. Upgrade Node.js to 24.22.3 or later on Hosts and daemon machines before
   installing the SDK. Rebuild Node SEA launchers with a supported Node
   executable.
2. Back up local stores and run the candidate's read-only store precheck
   before switching. If a store changes during the check, take a fresh
   precheck before accepting the upgrade.
3. Upgrade the Host, server, and daemons to 0.48.0. Replace removed Pi model
   defaults, review changed thinking levels, re-prepare inputs for Pi 1.7.0,
   and rebind Host accounting rulings to the new runtime identity.
4. If the Host reads Antigravity quota, pass `allowPrintMode: true` to
   `AgyAdapter.accountUsage()` or the local `runtimes.usage` request. Update
   any usage-window labels that match the old `Remaining` suffix. For Codex
   `nativeInteractions`, require Codex 0.107.0 or later.

[Host upgrade checklist](host-upgrade-0.48.0.md) ·
[Store compatibility precheck](../upgrade-manifest.md#store-compatibility-precheck)

## Runtime updates

- The official Pi closure and pinned keys catalog move from 1.6.0 to 1.7.0.
  Stored profiles with removed or changed catalog entries reopen as manual
  with their saved configuration and thinking level. Pi-durable 1.6.0 and
  1.6.1 SQLite replicas open in place.
  [Host steps](host-upgrade-0.48.0.md#pi-170-closure-2585) ·
  [Refs #2585](https://github.com/Ancienttwo/byok-sdk/issues/2585)
- The client vendors OAR 0.140.0, up from 0.131.0. The SDK keeps its own Pi
  launcher and RPC client, and Pi model listing uses the SDK helper.
  [PR #2587](https://github.com/Ancienttwo/byok-sdk/pull/2587)
- Antigravity CLI 1.5.18 is qualified, and quota reads now require explicit
  print-mode opt-in. The SDK removes Codex secret answer fields from the
  matching native output before recording and projection.
  [Host steps](host-upgrade-0.48.0.md#oar-01381-2521) ·
  [Refs #2521](https://github.com/Ancienttwo/byok-sdk/issues/2521)
- The OAR 0.136.0 changes included in this cut give OpenCode 2.x a full model
  catalog with display names, providers, and effort levels. Claude declines
  MCP elicitation requests promptly. Codex can ask structured questions
  outside plan mode when `nativeInteractions` is enabled. The adapter
  refuses that mode below 0.107.0 or when it cannot recognize the version.
  [Host steps](host-upgrade-0.48.0.md#oar-01360-2512-2513) ·
  [Refs #2512](https://github.com/Ancienttwo/byok-sdk/issues/2512) ·
  [Refs #2513](https://github.com/Ancienttwo/byok-sdk/issues/2513)
- Hosts can compare installed runtimes against OAR's bundled suggested
  minimums offline, or fetch and validate a fresh manifest on their own
  schedule. The advice is independent of compatibility floors and Host
  policy. [Host steps](host-upgrade-0.48.0.md#suggested-runtime-versions-2524) ·
  [Refs #2524](https://github.com/Ancienttwo/byok-sdk/issues/2524)
- `CursorAdapter` is an opt-in phase 1 integration for macOS and Linux.
  It uses `cursor-agent login` under the device user, supports model and
  effort selection, and has fake-CLI coverage. Live qualification remains
  open. Phase 1 declines credentialed task MCP servers and Host-selected
  service tiers. [Host steps](host-upgrade-0.48.0.md#cursor-agent-cli-2514) ·
  [Refs #2514](https://github.com/Ancienttwo/byok-sdk/issues/2514) ·
  [Refs #2579](https://github.com/Ancienttwo/byok-sdk/issues/2579)

## Service tiers

Hosts can select a Codex or Claude service tier on wire v8 and authorize
fallback to the default tier. Check the advertised device and harness
capabilities first. Both adapters verify the applied tier before the first
prompt and report it in a `service_tier` activity event.
[Host steps](host-upgrade-0.48.0.md#host-selected-service-tier-2523) ·
[Refs #2523](https://github.com/Ancienttwo/byok-sdk/issues/2523)

## Host MCP

- The server can opt in to `host-mcp-task-context` and verify Host tool
  assertions through `verifyHostMcpTaskAssertion`. Deployments with multiple
  server processes can supply a shared atomic replay authority.
  [Host steps](host-upgrade-0.48.0.md#host-mcp-task-context-2559) ·
  [Refs #2559](https://github.com/Ancienttwo/byok-sdk/issues/2559)
- Supported adapters project Host-toolset calls with the canonical MCP
  server and tool identity. Measurement and UI consumers can match on this
  identity. DSH continues to emit native observations.
  [Host steps](host-upgrade-0.48.0.md#host-toolset-observations-2564) ·
  [Refs #2564](https://github.com/Ancienttwo/byok-sdk/issues/2564)

## Task-scoped skills wire

#2580 adds `requiredSkills` to wire v8 Agent offers. The `skill-selection`
capability gates delivery, and `RuntimeCapabilities.skills` reports runtime
support. This release ships the wire and server contract ahead of client
support. The device registry and task-scoped projection are tracked in
#2576 and #2577 under #2563.
[Host steps](host-upgrade-0.48.0.md#task-scoped-skills-wire-2575) ·
[Refs #2575](https://github.com/Ancienttwo/byok-sdk/issues/2575) ·
[Parent #2563](https://github.com/Ancienttwo/byok-sdk/issues/2563)

## K8 Bot skills

#2583 adds Host-owned `skills` to Bot profiles and team snapshots. K8
combines template and Bot skill IDs for Turns, with template IDs first and
duplicates removed. The combined list is capped at 16. Daily dreams omit
required skills. A Turn that requires skills still needs a device that
advertises `skill-selection`.
[Host steps](host-upgrade-0.48.0.md#bot-profile-skills-2578) ·
[Refs #2578](https://github.com/Ancienttwo/byok-sdk/issues/2578)

## Fixed

The client, keys, and server store prechecks report that the store changed
when a source file vanishes during the copy, including the case where the
main file disappears and the temporary copy would otherwise look like an
empty database. [Refs #2530](https://github.com/Ancienttwo/byok-sdk/issues/2530)

## Protocol compatibility

The 0.48.0 registration pins 523 envelope and 43 HTTP lines. #2570 appends
five envelope lines and one HTTP line for service tiers. #2580 appends four
envelope lines and one HTTP line for task-scoped skills. The 0.47.1 prefixes
and hashes remain pinned at 514 envelope and 41 HTTP lines. The published
0.45.0 decoder remains the v8 baseline. [Protocol compatibility](../protocol.md#freeze-rule)

## Known issues

- Cursor live qualification remains open, including logged-in operation and
  model and effort readback. [Refs #2579](https://github.com/Ancienttwo/byok-sdk/issues/2579)
- ACP `terminal/create` requests retain peer-supplied `env` values in session
  records. [Refs #2571](https://github.com/Ancienttwo/byok-sdk/issues/2571)
- Claude plan-mode behavior still needs a logged-in probe.
  [Refs #2513](https://github.com/Ancienttwo/byok-sdk/issues/2513)
- Existing launchd services that still need the 0.46.1 plist update require
  `install()` or `repair()`. Install Windows `windows-user` services from a
  non-elevated process. [Launchd repair](v0.46.1.md#residual-boundary) ·
  [Windows user services](v0.45.1.md)

## Changes since rc.2

- **Agent message draft lane (#500, PRs #505 and #506):** a display-only third
  lane beside the latest-value and reliable lanes. The daemon mirrors the text
  it accumulates for the closing reply into strict `agent.message.draft`
  frames (at most 16 KiB each, UTF-8 byte offsets, one `overflow` frame at the
  offer's `messageEgress.maxBytes`). Frames flow only when the task has
  `messageEgress`, the server advertises the new `agent-message-draft` flag
  and the runtime declares `RuntimeCapabilities.messageDraft` (Pi only; Claude
  Code and Codex send no frames). Cloud keeps one bounded snapshot row per
  task (`AgentMessageDraftStore`, required in `CloudStores`; Postgres
  migration `0026_agent_message_draft.sql`, forward-only) with the 10 minute
  activity TTL, and exposes `readTaskAgentMessageDraft`. The server streams
  `tasks.messageDraft(taskId, deviceId, agentRef, { after, signal })` as
  `append` / `overflow` / `gap` / `ended` / `discarded` events. Nothing enters
  the reliable spool, the mailbox or the activity tail; the accepted Agent
  message stays the only product truth. Wire major stays 3. Design:
  [500-agent-message-draft-lane.md](https://github.com/Ancienttwo/byok-sdk/pull/505);
  contract: [spec, Agent message draft lane](../spec.md#agent-message-draft-lane).
- **Claude closing reply (#501, PR #504; PR #508):** the Claude adapter
  declares `progressEventsAreMessages`, so a run that repeats its answer in a
  later model call publishes it once. `Session.progressStartsMessage(event)`
  lets an adapter that emits one message as several `progress` events keep
  every part in one closing reply; Claude joins the text blocks of one message
  by `message.id`.
- **Pi dependency guidance and auth probe (#507):** Pi dependency errors direct
  hosts to reinstall dependencies or use `sdkHelperHost` with
  `copyPiRuntimeAssets`. The `authPresent` probe keeps its implementation:
  it reads `auth.json`, `settings.json` and `models.json`, never resolves env
  references and never executes `!command` keys; new tests assert that it
  spawns no child process, and the security guide now lists all three files.
- **cloud-dataplane build (#503):** the two tsup configs no longer race on
  `clean`; the package `build` script removes `dist` once before `tsup`, so a
  release pack cannot miss `dist/runtime.js`.

## Fixes since rc.1

- **Default scratch root (#493, PR #498):** a canonical `<storeDir>/tmp` that is
  too long for runtime Unix sockets no longer fails daemon construction. The
  daemon then uses `/private/tmp/byok-scratch-<storeDir hash>` on macOS and
  `/tmp/byok-scratch-<storeDir hash>` on Linux. `ScratchRootPathError` states
  the byte count and the platform limit. The hash uses the canonical store
  path, so aliases share the same fixed root and restart cleanup. A scratch
  root owned by another user is refused before chmod.
- **Busy code on `TaskResult` (#496, PR #498):** the embedded server's
  `tasks.get().result` and `handle.result()` carry the K6 home-busy `code`.
- **Documentation (#496):** this note and the #399 migration note now list the
  `resolveRuntimeLaunch` rename, scratch release ownership, `crashed` as a
  terminal phase, the removed `status().connected` / `.revoked` fields and the
  new `byok-agent-result-mcp` bin.

## Summary

0.27.0 is the first **wire v3** (protocol major 3) train. `PROTOCOL_VERSION`
is 3. A v2 daemon and a v3 server do not interoperate in either direction, so
the devices and the Host must upgrade together after a drain (see
[Upgrade and migration for Hosts](#upgrade-and-migration-for-hosts)).

The train replaces result extractors with the schema-bound `submit_result`
outcome channel (K7, #468), unifies fresh Agent submission in
`executions.submit` / `submitAgentExecution` (K5, #470) and makes the older
`dispatch({ agentRef })` / `enqueueAgentOffer` lanes resume-only (#484). It
types home-busy declines (K6, #471), moves the daemon's HTTP reads onto the
protocol schemas (#386), gates selection fields at admission (#480), lets an
embedded Host inject its device credential backend (#487), and stops long
timers from firing at 1 ms (#492). The cloud gets one mailbox byte authority
(#411), a wake-based long poll (#410) and unified retention maintenance (#412).
The client gets one daemon lifecycle model (#391, #394), content-free durable
records (#395), Host-visible outbound settlement (#397, made v3-only by #494)
and unified artifact
retention (#399). keys delivers the pi-rpc provider key over private IPC
(#385). The stable train adds the display-only Agent message draft lane:
`agent.message.draft`, `server.tasks.messageDraft` and migration 0026 (#500).

Almost every package has pre-1.0 breaking cuts. Read
[Breaking changes since 0.26.1](#breaking-changes-since-0261) before you
upgrade.

## Wire v3 and the K-series

### K7: `submit_result` outcome channel on wire v3 (#468, PR #488)

- Result-document offers carry `{mode: 'result-document', contract, schema}`.
  The SDK-reserved `byokagentresult` MCP server exposes only `submit_result`
  with that frozen schema. The daemon validates and fsyncs the outcome before
  it returns a staged receipt. Only a successful runtime with a staged outcome
  produces `task.complete.document`; failure, cancellation and interruption
  never deliver staged data. Success without a submission fails non-retryably.
- `DaemonConfig.resultDocument` and `ResultDocumentExtractor` are removed.
  Supplying a removed daemon config field raises
  `DaemonConfigFieldRemovedError` with the removed `field`. Durable Pi uses the
  same staging channel.
- Host submit refuses a result-document `terminalProjection` whose schema is
  missing, outside the supported subset or over 16 KiB, before any receipt,
  attempt or mailbox row is written.
- Prepared SummaryJobs put the exact `terminalProjection` in both the
  preparation request and the offer, and freeze one result tool. The durable
  prepared record version moves from 10 to 11; older records are refused
  without migration.
- `createPostgresCloudStores` is now async and refuses pending old-major
  envelopes (`PostgresMailboxProtocolUnsupportedError`) before composition.
  The embedded SQLite store refuses them with
  `SQLITE_MAILBOX_PROTOCOL_UNSUPPORTED`; daemon recovery offers and pending
  terminals use `DaemonJournalProtocolUnsupportedError`.
- A v2-only `conn.hello` and a `v: 2` envelope are refused; no offer is
  delivered. There is no v2 reader and no result-document capability
  negotiation.
- Details: [K7 migration and release note](k7-wire-v3.md).

### K5: unified fresh execution `executions.submit` (#470, PR #474)

- `ByokServer.executions.submit(input)` and
  `ByokCloud.submitAgentExecution(tenant, input)` take
  `AgentExecutionInput` and return `EnqueuedOffer`.
- Removed with no aliases: `recurring.submit`, `submitRecurringExecution`,
  `RecurringExecutionInputSchema`, `dispatchFreshAgentEgress`, public
  `enqueueFreshAgentEgressOffer`, and the types `RecurringExecutionInput`,
  `FreshAgentEgressDispatchInput` and `AgentEgressFreshSessionDispatchInput`.
- Required: Host-owned `taskId`, exact `deviceId`, `runtime` or `harnessId`
  (exactly one; `harnessId` cannot be combined with `dispatchSelection`,
  #480), `agentRef`, `egressPolicy` and `terminalProjection`. `messageEgress`
  is optional; message context and a registered `agentMessage.consume` are
  required only when it is selected, and context without `messageEgress` is
  rejected. The payload rejects `sessionRef`.
- Resubmitting a delivered `taskId` throws `agent_task_already_exists`.
  Recover through exact `tasks.offer(taskId)` (cloud:
  `readTaskOffer(tenant, taskId)`) readback. A registered offline device is
  enqueued normally.
- Details: [#470 note](470-executions-submit.md).

### #484: non-egress Agent offers are resume-only (PR #490)

- `dispatch({ agentRef })` without `egressPolicy` and `enqueueAgentOffer`
  require the exact `sessionRef` being resumed. Without it the server throws
  `Agent resume dispatch requires an exact sessionRef; use executions.submit
  for fresh execution` and cloud throws `ByokCloudError`
  `coordination_input_invalid`, both before any task, receipt or mailbox write.
- `DispatchInput` is `LegacyDispatchInput | AgentResumeDispatchInput`, and
  `AgentDispatchInput.payload` requires `sessionRef`. The wire keeps
  `sessionRef` optional on `task.offer_for_agent`.

### K6: typed home-busy decline (#471, PR #473)

- A home-busy `task.decline` carries `agent_home_writer_busy` or
  `agent_home_reader_busy` in the optional `code`. Cloud terminal results and
  canonical `tasks.deviceTerminal` envelopes preserve it. Classify busy by
  `code`, not by display reason.
- The embedded server's `TaskResult` carries the same `code`, so
  `tasks.get().result` and `handle.result()` expose it (#496).
- The CHANGELOG entry says "Protocol version remains 2"; that was true when
  #473 merged. K7 later moved the wire to 3, and this train ships both.

### Protocol decoder cutover and compatibility evidence (#386)

- **#491:** the daemon decodes its HTTP reads with the protocol schemas only.
  `EventsPollResponse.events` is `unknown[]`
  (`EventsPollResponseSchema.events` is `z.array(z.unknown())`); decode each
  entry with `parseMessage` (or `decodeEnvelope` for a raw line). Token
  renewal decodes `/byok/challenge` and `/byok/token` with
  `ChallengeResponseSchema` / `TokenResponseSchema`; a failing body throws
  the new `AuthResponseInvalidError` (`route`, `cause`) and keeps the prior
  credential. A token `expiresAt` that is not an ISO 8601 timestamp with `Z`
  or a numeric offset now fails renewal instead of being stored.
- **#447, #401, #458:** wire compatibility is checked against published
  decoders from one `WIRE_ADDITIONS` table, with append-only envelope and HTTP
  corpora. `WireAddition` is a closed union with a required
  `kind: 'envelope' | 'http'`.
- **#480 (with the #486 CHANGELOG correction):** `dispatchSelection` and
  `requiredToolsets` are gated rows on `task.offer_for_agent`,
  `task.offer_for_agent_with_egress`, `task.offer_for_agent_with_egress_fresh`
  and `task.offer_prepared`. A cloud offer carrying either field is refused
  before any mailbox write unless the device durably advertised
  `dispatch-selection` / `toolset-selection`. `MessagesSendResponse.outcomes`,
  `MessagesSendResponse.ingress`, `MessagesSendResponse.capabilities` and
  `EventsPollResponse.ingress` were declared strip-safe for the published
  0.25.0 / 0.26.1 decoders. Under wire v3, #494 makes send-response
  `outcomes` and events-page `ingress` required; send-response `ingress` and
  `capabilities` stay optional in the schema, and the client requires
  `ingress` on an answer that accepts a `conn.hello` (see below).
- **#494 (#397 v3 cleanup):** wire v3 has no v2 responder, so the v2
  settlement fallbacks are gone. `EventsPollResponseSchema.ingress` and
  `EventsPollResponseSchema.capabilities` are required, and
  `MessagesSendResponseSchema.outcomes` is required. The client also refuses
  an answer that accepts (or deduplicates) a `conn.hello` without `ingress`,
  and a rejected outcome without its `reason`. Each is an unusable response on
  the existing route-failure path, and the batch is retained for retry.
  Counts-only bisection, `DEFAULT_ACTIVITY_INGRESS` and the `'unspecified'`
  `OutboundRefusalReason` are removed (`'unknown'` still marks an unrecognized
  reason). Unregistered v3 HTTP corpus lines were corrected in place under the
  pre-registration exception in the
  [release process notes](README.md#protocol-compatibility-baseline): before
  the first v3 release is registered, a line no registered entry covers may be
  corrected when a pre-release v3 tightening makes it undecodable.
- Under wire v3 the v2 corpora and v2 registry are read-only negative
  evidence. The `byok-protocol-previous` alias pins 0.26.1 as a rejection
  oracle only.

## Breaking changes since 0.26.1

Each item is taken from the CHANGELOG entry of the change; follow its link or
migration document for the full contract.

### protocol

- Wire major 3 (#468). See K7 above.
- `EventsPollResponse.events: unknown[]` (#386, PR #491). See above.
- `@byok-sdk/protocol/constants` replaces the preparation-version subpath;
  import `INPUT_PREPARATION_WIRE_VERSION` from `/constants` (#398, PR #453).
  See [#398 entry dependency closure](398-entry-dependency-closure.md).
- `WireAddition` is a closed union with required `kind` (#386, #480).
- Required v3 response fields (#397 v3 cleanup, PR #494): events-page `ingress`
  and `capabilities`, send-response `outcomes`; `MessageSendOutcomeSchema.reason`
  decodes to `OutboundRefusalReason`. `DEFAULT_ACTIVITY_INGRESS` and the
  `'unspecified'` reason are removed.
- The unreleased `noHold` events-poll flag (`EVENTS_POLL_NO_HOLD_PARAM`),
  added by PR #402 after 0.26.1, is removed before release. `POST
  /byok/messages` answers an accepted `conn.hello` batch with the optional
  `capabilities` advertisement.

### server

- `executions.submit` replaces `recurring.submit` (#470); `dispatch({
  agentRef })` without `egressPolicy` is resume-only (#484).
- SQLite ownership uses `PRAGMA locking_mode=EXCLUSIVE`; the #403 sibling lock
  is removed. `ByokServer.stop()` is deleted; use `await server.close()`. A
  second connection throws `SqliteOwnershipError` (`SQLITE_DATABASE_OWNED`)
  after the 5-second busy grace (#414, PR #442). See `packages/server/README.md`.
- Embedded one-shot wake queue (`wake: { consume }`, `wakes.schedule /
  cancel / pending`). SQLite schema 5 adds wake authority; explicit
  `v4-to-v5` adoption with all writers stopped and a backup. Target-v4
  selectors are deleted; old builds refuse schema 5 (#420, PR #452).
- One TTL presence lease: pass `deviceId` on every `dispatch()`; the SDK never
  picks a target, and unknown or revoked targets throw `device_not_found`
  (#413, PR #443). See
  [docs/migrations/413-single-presence-lease.md](../migrations/413-single-presence-lease.md).
- `taskEventRetentionMs` above `2_147_483_647` is refused at construction
  (#492).
- Unified retention maintenance and `maintenance.runNow()` (#412), store-sourced
  `stats()` and `HubStats.inboundRefusals` (#415).

### cloud

- `submitAgentExecution` replaces the fresh egress and recurring lanes (#470);
  `enqueueAgentOffer` is resume-only (#484).
- `ByokCloudOptions` and `CloudRootStores` require `mailboxWake`;
  `longPollIntervalMs` and `DEFAULT_LONG_POLL_INTERVAL_MS` are removed (#410,
  PR #455).
- A refused offer append throws `TaskOfferAppendRefusedError`
  (`task_offer_append_refused`, with `taskId` and the store refusal in
  `cause`) from every `enqueue*Offer` path and the server's `dispatch` (#387,
  PR #472).
- Selection admission gates (#480), the retired result-document flag (#468)
  and outbound settlement (`onOutboundSettled`, #397).
- Custom stores: `TaskAttemptStore.countByStatus` and
  `TaskAttemptListQuery.active` are required (#415, PR #440).
- `collectRetired`, `expireReservations`, replay `deleteExpired`,
  `ByokServer.mailbox` and hosted `runTenant` calls move to the unified
  `collectExpired` / `ByokCloud.runMaintenance` contract (#412, PR #456). See
  [412 retention maintenance](../migrations/412-retention-maintenance.md).

### core and cloud-dataplane

- Mailbox bytes have one authority, the retained rows (#411, PR #424).
  `MailboxAppendInput.admission` is required; a `limited` append is refused
  with `storage_quota_exceeded` or `storage_entitlement_missing`.
  `QuotaStore.applyMailboxDelta`, `MailboxUsageDeltaInput` and
  `TenantStorageUsage.mailboxBytes` are removed; `MailboxStore.readUsage` is
  added. `POST /byok/messages` answers 507 when a reply cannot be appended.
- New migrations, in order: `deploy/sql/0023_mailbox_usage_index.sql` (#411),
  `0024_mailbox_wake.sql` (#410) and
  `0025_drop_storage_usage_mailbox_bytes.sql` (#387, PR #475). 0025 makes an
  application rollback to 0.26.1 or earlier need the pre-upgrade backup, or the
  column re-added with every writer stopped (`deploy/runbooks/cloud-cleanup.md`).
- `createPostgresCloudStores` is async and fences old-major pending rows (#468).
- Hosted retention policy reads/writes move to `PostgresRetentionPolicyStore`
  (#412).

### client

- One daemon lifecycle model (#391, #394, PR #427): `daemon.start()` resolves
  after local startup; read `status().lifecycle` or `{kind: 'lifecycle'}`
  events and wait for `{phase: 'running', connection: 'open'}`. Halts are
  typed (`DaemonHaltError`, `DAEMON_HALT_REASONS`). `waitForConnection`,
  `isConnected`, `isRevoked`, `getTerminalError` and `onTerminalError` are
  removed, and so are the `status().connected` and `status().revoked` fields.
  `byok-agent start` exits 0 / 78 (halt) / 1 (crash).
- Content-free durable records (#395, PR #445): `byok-agent start` stdout is
  JSON Lines `DaemonRecord`s; `tasks --follow` requires a running daemon.
- Outbound settlement (#397, PR #436): awaited `onOutboundSettled` replaces
  quarantine and accepted/rejected callbacks; `progressBatch.maxBatchBytes`
  and `DEFAULT_ACTIVITY_MAX_*` are removed (the cloud default is
  `DEFAULT_ACTIVITY_BOUNDS`); `handleInboundEnvelope` returns a
  discriminated `InboundResult`.
- v3 settlement (#397 v3 cleanup, PR #494): `OutboundSettlement` is a
  discriminated union whose rejected case has a required `reason`.
  `ConnectionManager.getIngressBudget()` throws before the first
  advertisement, `TaskRunnerDeps.getIngressBudget` is required, and
  `ProgressBatcher` takes its ingress source without a default. Audit-log lines
  written by older daemons with reason `'unspecified'` no longer parse:
  `readAuditRecords` skips them and compaction no longer treats them as
  terminal records.
- Runtime observations (#392, PRs #409, #439, #446): `DaemonStatus.runtimes` and control
  `runtimes` are `RuntimeObservation[]`; control `runtimeIds` is removed.
- Unified artifact retention (#399, PR #437): `hostedJournal.storagePolicy`
  becomes `storage: { budget, retention, ... }`; every adapter start requires
  `ExecutionScratch`; custom `LocalTaskJournal` implementations add prune
  methods. `PreparedRuntimeOperation.resolveRuntimeLaunch` takes
  `scratch: ExecutionScratch` in place of `projectionRoot: string`. See
  [docs/migrations/client-retention-399.md](../migrations/client-retention-399.md).
- `resultDocument` / `ResultDocumentExtractor` removed (#468).
- `EventsPollResponse.events: unknown[]`, `AuthResponseInvalidError` and the
  `expiresAt` tightening (#386).
- Windows: the `jobObject` seam on `ClaudeProcessClientOptions` and
  `PiRpcClientOptions` returns `assign(pid): Promise<{ release(): void }>`
  (PR #433).
- Device credential custody (#487, PR #489): `DeviceStore` requires an
  injected `DeviceCredentialBackend`; the internal
  `InMemoryDeviceCredentialStore` test double is gone from product code. See
  Additions for the new public surface.

### keys

- `buildPiProviderProjection(profile, runtimeEntry)` requires `runtimeEntry`.
  The former default `'pi-rpc'` now projects the IPC marker `byok:rpc-ipc` for
  a keyed profile; `'pi-prepared'` keeps `$PI_PROVIDER_API_KEY` (#385, PR #407).
- The rpc launch config moves to `byok.pi.rpc-launch` version 5 with
  `credentialSource`. Pi subagents are unavailable in the BYOK pi-rpc lane
  (`byok_subagent_credential_unavailable`).

## Fixes and other changes

- **Timers (#492):** a token whose `expiresAt` is more than about 24.8 days
  away no longer renews at once; proactive renewal steps in capped intervals.
  A server-supplied `limits.maxDurationMs` above that range no longer fails
  the task immediately.
- **Client observer crash boundary (#384, PR #460):** a throwing
  `onOperationalOutcome` uses the `notify()` / `onCrashed` path; detached
  drains do not leak unhandled rejections.
- **Client crash after start:** an unexpected error after `daemon.start()`
  resolved is a crash through one path (`{phase: 'crashed'}`).
- **Same-home admission (#476, PR #478):** an offer for a home whose
  finishing Attempts are releasing their lease waits once for them, then
  recounts from the lease registry before it reserves or declines.
- **Crashed-daemon process groups (PR #406):** on POSIX a restarted daemon
  ends the owned runtime process groups of a crashed run before lease
  reclaim, from an owned-process ledger under `<storeDir>`, and refuses to
  start while one survives.
- **Server presence and stats (#388, PR #403):** presence is a TTL lease and
  stats are bounded; the SQLite sibling lock it added was replaced by #414.

## Upgrade and migration for Hosts

This section is for Host integrators such as Salesko. It lists what changes
for a Host that uses each API; which of these APIs a given Host uses is not
verified here.

### Coordinated wire-v3 upgrade

v2 daemons and v3 servers do not interoperate. Devices and the Host must
upgrade together:

1. On the old SDK, stop submitting new executions. Let pending server mailbox
   entries be processed and acknowledged; settle in-flight executions and
   confirm every daemon pending terminal.
2. Stop writers and keep the existing state and a backup. Upgrade the embedded
   server or hosted cloud/dataplane first, then the daemon clients. A Topology
   L application upgrades both sides together after draining.
3. A v2-only hello is refused and receives no offer. Pending old-major rows
   stop startup (`SQLITE_MAILBOX_PROTOCOL_UNSUPPORTED`,
   `POSTGRES_MAILBOX_PROTOCOL_UNSUPPORTED`,
   `DaemonJournalProtocolUnsupportedError`) without rewriting them. Use the
   old SDK to finish draining, or provision a new state directory and enroll
   again under the Host's resubmission policy.

Source: [K7 coordinated upgrade](k7-wire-v3.md#coordinated-upgrade).

### Execution submission

- Replace `enqueueFreshAgentEgressOffer`, `dispatchFreshAgentEgress` and
  `recurring.submit` / `submitRecurringExecution` with
  `executions.submit(input)` (server) or `submitAgentExecution(tenant, input)`
  (cloud). Build `input` with `AgentExecutionInputSchema.parse`, persist it,
  then submit; recover after a lost response through `tasks.offer(taskId)` /
  `readTaskOffer(tenant, taskId)` and resubmit exactly the persisted input.
- `dispatch({ agentRef })` without `egressPolicy` and `enqueueAgentOffer` now
  need the exact `sessionRef`. A caller that started fresh work this way moves
  to `executions.submit`; a real resume keeps its call and passes `sessionRef`.
- Offers that carry `dispatchSelection` or `requiredToolsets` need devices
  advertising `dispatch-selection` / `toolset-selection` (#480).
- Result-document executions: put a schema in `terminalProjection`
  (`{mode: 'result-document', contract, schema}`, at most 16 KiB, supported
  subset), instruct the model to call `submit_result`, and remove
  `DaemonConfig.resultDocument` and `ResultDocumentExtractor`. Prepared
  SummaryJobs carry the exact `terminalProjection` in both the preparation
  request and the offer; prepared record version 10 is refused.
- Home-busy declines: switch to `code` (`agent_home_writer_busy` /
  `agent_home_reader_busy`).

### Protocol and auth

- `EventsPollResponse.events` is `unknown[]`. A Host that reads events pages
  directly decodes each entry with `parseMessage` or `decodeEnvelope`.
- Token `expiresAt` must be an ISO 8601 timestamp with `Z` or a numeric
  offset; anything else fails renewal with `AuthResponseInvalidError`.
- Import `INPUT_PREPARATION_WIRE_VERSION` from `@byok-sdk/protocol/constants`
  (#398).

### Server and cloud composition

- `taskEventRetentionMs` must be a positive integer of at most
  `2_147_483_647`; a larger value is refused at construction.
- Inject `mailboxWake` (#410): Node/Postgres Hosts run migration 0024, create
  one `createPostgresMailboxWake` per process on a session-mode DSN (one more
  Postgres connection per process), and await its `close()`; Workers/Hyperdrive
  Hosts create `createInProcessMailboxWake({ fallbackMs: 1_000 })` per
  invocation.
- Await `createPostgresCloudStores` (#468). Its read-only startup fence pages
  through pending outbox rows on each composition, so per-request Worker
  compositions scan all pending rows each time; account for this cost when
  sizing the mailbox (see [K7](k7-wire-v3.md)).
- Replace the retention calls with `collectExpired` / `runMaintenance` (#412).
- Catch `TaskOfferAppendRefusedError` and match `error.cause` for
  `storage_quota_exceeded` (#387). Issue a storage entitlement before the
  first offer (#411).
- Embedded server: replace `stop()` with `await server.close()`, stop every old
  server and external SQLite connection first (#414), adopt SQLite schema 5
  explicitly with a backup (#420), and pass `deviceId` on every `dispatch()`
  (#413).
- Run the hosted migrations 0023, 0024, 0025 and 0026 in order, after the
  pre-upgrade audit in `deploy/runbooks/cloud-cleanup.md`. Rolling back past
  0025 needs the pre-upgrade backup. 0026 (#500) adds the ephemeral
  `agent_message_draft` table; it is forward-only, and a rollback lets its rows
  expire. A Host that composes `CloudStores` itself supplies the
  `agentMessageDraft` store; `createPostgresCloudStores` and the embedded
  SQLite composition include it.

### Client and device

- Wait for `{phase: 'running', connection: 'open'}` instead of treating a
  resolved `start()` as connected; treat `halted` and `crashed` as terminal
  (each stays until the next `start()`); catch `DaemonHaltError` by `reason`
  (#391, #394). Replace reads of `status().connected` / `status().revoked`
  with `status().lifecycle`. Reinstall services (`byok-agent install`) so
  they run `--service` (#392, #394).
- A Host that packages SDK bins itself classifies the new
  `byok-agent-result-mcp` bin (reserved helper kind `agent-result-mcp`): ship
  it, or re-enter it through `sdkHelperHost` (#468).
- Parse service stdout as JSON Lines `DaemonRecord`s (#395).
- Read `runtimes` observations instead of `runtimeIds` (#392).
- Move `hostedJournal.storagePolicy` to `storage` and supply `ExecutionScratch`
  to standalone adapter starts (#399). Rename the `resolveRuntimeLaunch` input
  `projectionRoot` to `scratch`. See
  [client-retention-399.md](../migrations/client-retention-399.md) for scratch
  release and root ownership.
- The scratch root must be a private real directory with no symbolic-link
  ancestors. Runtime Unix sockets limit it to 61 bytes on macOS and 65 bytes on
  Linux. When canonical `<storeDir>/tmp` does not fit, the daemon uses
  `/private/tmp/byok-scratch-<storeDir hash>` (`/tmp/...` on Linux) (#493). An
  explicit `storage.scratchRoot` must fit; on macOS put it under
  `/private/tmp`, not under `os.tmpdir()`.
- Use `onOutboundSettled` (#397). Under #494 its settlement is the
  `OutboundSettlement` union: switch on `outcome`; only `'rejected'` has a
  `reason`, and it is always present. Drop any handling of `'unspecified'`.
- A Host that composes its own `TaskRunner` passes
  `TaskRunnerDeps.getIngressBudget`, and a direct `ProgressBatcher` caller
  passes its ingress source; there is no default ingress, and
  `ConnectionManager.getIngressBudget()` throws before the first accepted
  handshake (#494).
- Expect audit-log lines from older daemons with reason `'unspecified'` to be
  skipped by `readAuditRecords` (#494).
- A Host or test server that answers the device HTTP API itself must send
  `ingress` and `capabilities` on every events page, `outcomes` on every send
  response (with a `reason` on each rejection), and `ingress` on an answer
  that accepts a `conn.hello`; otherwise the daemon treats the response as
  unusable and retries (#494).
- A Host that needs a non-default macOS keychain passes the same
  `deviceCredentials.macosKeychainPath` to the daemon, cold enrollment reads,
  `createStoredDeviceProofSigner` and repair; an embedded Host that owns its
  custody passes `DaemonOverrides.deviceCredentials` instead (#487).
- A Host that wants to show the reply while the runtime writes it reads
  `server.tasks.messageDraft(taskId, deviceId, agentRef, { after })` (#500).
  Frames appear only for a `messageEgress` task on a Pi runtime; the accepted
  Agent message stays the only product truth. No Host change is required to
  ignore the lane.

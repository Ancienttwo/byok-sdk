# 0.29.0 — published; superseded by 0.30.0

This is the release preparation record, not a publication record. It does not
approve any merge, tag or publish. The npm registry lists all nine packages at
0.29.0 as published (see the registry state below). The sections below record
the state at preparation. They are not updated for the later CI and
publication, except for the #744 upgrade note that the owner added after
publication (D7). Issue #743 marked the scope as complete. All nine public
manifests and their lock records name 0.29.0.

0.29.0 is a MINOR release under the default pre-1.0 policy, with no
exception. Issue #743 states this in its first paragraph:

> 0.29.0 是 MINOR，按 pre-1.0 规则发，不再例外。

In English: 0.29.0 is a MINOR and follows the pre-1.0 rule, with no more
exceptions. The release adds public API and behavior: the
`@byok-sdk/core/sealed-payload` subpath, `writeHomeFile` on the Agent-home
projection hook, per-task Agent memory selection on ordinary offers with a new
device capability, the `AGENT_MEMORY_MCP_SERVER_NAME` export, an optional
`thinkingLevelMap` in keys, Agent memory on Windows x64 and npm-installed
Claude and Codex CLIs on Windows. It has breaking changes in client and keys.
All nine public packages move to 0.29.0. Private packages remain unchanged.

## Changes since 0.28.3

The [CHANGELOG](../../CHANGELOG.md) has one entry for each change. This list
groups the entries by package.

Public packages:

- **core** — the new subpath `@byok-sdk/core/sealed-payload` exports the
  sealed payload v1 byte rules. The root `@byok-sdk/core` entry does not
  change. The wire does not carry sealed content yet (#654 E1a, E1b).
- **client (breaking)** — the task-free projection hook gets
  `writeHomeFile(name, body)`. One call atomically replaces one file at the
  root of the Agent home. A call first removes the temp files that an ended
  process left for the same name (#738).
- **protocol, server, cloud, client** — an ordinary Agent offer can select
  the Agent memory of its task with `agentMemory: 'none' | 'read' |
  'read-write'`. Devices advertise the new capability
  `agent-memory-selection` (#614).
- **client** — the export `AGENT_MEMORY_MCP_SERVER_NAME` (#614).
- **client (breaking)** — Agent memory names are the same on every platform:
  Windows device names, a trailing `.`, ASCII case pairs below `notes` and
  files with more than one hard link are refused (#605).
- **client** — the Agent memory Go helper opens a home on Windows, on a local
  NTFS volume only. The SDK uses it on Windows x64 through the release asset
  (#759) and the admission gate (#761) in the items below (#605).
- **keys (breaking)** — `PiModelConfigSchema` accepts a `pi_model` without
  `thinkingLevelMap`. `piModelConfigFromPinnedCatalog` derives the pinned
  entries that have no map (#636).
- **client** — the SDK release has a Windows x64 Agent memory helper,
  `dist/native/agent-memory-fs/win32-x64.exe`. The helper manifest moves to
  version 2 (#605).
- **client** — Windows x64 admits the memory MCP, the hosted projection and
  `agentMemoryExport` through the SDK helper, on a local NTFS volume only.
  B stays false: a Windows daemon does not advertise `agent-memory-intent.v1`
  (#605).
- **client (breaking)** — on macOS the Agent memory helper admits an Agent
  home only on a local volume (#765).
- **client** — on Windows, the Claude and Codex adapters start a CLI that npm
  installed as a cmd-shim `.cmd`, without a shell (#763).

Copy-and-own examples (not published packages):

- **K4** — routine versions with `updateRoutine` and `versionSwitchDue`
  (#735); occurrence hooks in the occurrence commit, `promoteOccurrence` and
  `concludeOccurrence` (#736); custom harness execution identities (#760); a
  cancelled claimed task settles soon after its device terminal (#762); a
  failed SDK wake call retries from a bounded timer (#766).
- **K8** — Bot routines run on K4 routines, and `CollaborationState` moves to
  version 2 (#737, breaking). The persona consumer writes with
  `writeHomeFile` and runs on Windows (#738). The room seat and input
  coalescing rules move into `rules/` (#733, #734). K8 uses the K4 wake retry
  timer instead of its own 60-second retry (#766).

## Upgrade notes for Hosts

- **Agent memory names.** On every platform, recall, save, intents and
  observation refuse a memory path with a Windows device name (such as
  `notes/con.md`), a segment that ends in `.`, two names below `notes` that
  differ only in ASCII letter case, or a file with more than one hard link.
  Existing notes with these names or links stop being visible to recall and
  export. A `MEMORY.md` with more than one hard link makes capture fail
  (#605).
- **Per-task Agent memory.** The `agentMemory` offer field is a gated wire
  addition. Server and hosted cloud refuse it to a device that does not
  advertise `agent-memory-selection`, before the task exists. So an older
  device gets no task that carries the field. `read` or `read-write` is declined
  when the daemon does not admit the memory MCP; the daemon does not change it
  to `none`. A Host that wants memory only when the daemon admits it sends no
  `agentMemory` (#614).
- **`writeHomeFile`.** The names `.byok`, `MEMORY.md`, `notes` and
  `<file>.<pid>-<n>.tmp` belong to the SDK and are refused. Each call is
  atomic for one file only. On Windows, a successful call has flushed the file
  but not its directory, so an OS crash or a power loss can bring back the old
  bytes; a delivery of the same revision and hash repairs a lost file (#738).
  `AgentHomeProjectionApplyInput` has the new required member
  `writeHomeFile`. Code that builds this input itself, for example a test
  double, must add the member to compile. A Host that only implements the
  hook needs no change (D7).
- **keys downgrade.** 0.28.3 and earlier refuse a `pi_model` without a map.
  Before a downgrade, give each such profile a complete map or delete it.
  Otherwise the older SQLite store fails `list()` and each read of that
  profile, and the older truth store fails every read and write of the
  registry (#636).
- **keys type.** `PiModelConfig['thinkingLevelMap']` is optional in the type.
  TypeScript code that reads the map as a required field does not compile.
  Check for an absent map first (#636).
- **Sealed payload.** `@byok-sdk/core/sealed-payload` is a new subpath. Its
  bundle imports `ByokCoreError` from the root entry, so both entries throw
  one error class. No wire message carries sealed content in this release
  (#654).
- **K8 (example).** The Host refuses a `CollaborationState` version 1 ledger
  with a clear error and writes no migration. The earlier code refuses a
  version 2 ledger. Back up the ledger before the upgrade. To roll back,
  restore that backup or start a new ledger. Read the CHANGELOG entry for the
  documented behavior changes (#737).
- **K4 (example).** After `promoteOccurrence` or `concludeOccurrence`, the
  Host must call `drain()`. The core then sends the intent and checks a
  version switch. An occurrence that the Host never promotes or concludes
  blocks the version switch (#736). A fresh execution template must name
  exactly one of `runtime` and `harnessId`; K4 now refuses a template with
  both, or with a value that the protocol schemas do not accept (#760).
- **Helper assets.** Helper manifest version 2 records the digest algorithm
  of each entry. A product asset folder that an older SDK copied fails with a
  manifest mismatch, also on macOS. Run `copyAgentMemoryHelperAssets` or
  `copySdkNativeAssets` again with the new SDK and ship the new folder.
  `copySdkNativeAssets({ platform: 'win32', arch: 'x64' })` also copies the
  helper and needs the helper build (#605).
- **Windows Agent memory.** On Windows x64, with an Agent home and the default
  `agentMemoryMcp: 'auto'`, every ordinary Agent task gets the SDK memory
  tools when the SDK helper resolves. An adapter without MCP toolset support
  then declines the task. Set `agentMemoryMcp: 'off'` to keep the earlier
  behavior. `agentMemoryIntents` now needs a resolvable SDK helper, and
  without it the daemon fails at construction. The Agent home must be on a
  local NTFS volume; another volume fails with `unsafe_root` (#605).
- **macOS network volumes (breaking).** An Agent home that is already on a
  network volume (SMB, NFS, AFP or another mount without `MNT_LOCAL`) is now
  refused with `unsafe_root`. Memory recall and save, the hosted projection
  and the task-free export fail there, and the daemon no longer advertises
  `agent-memory-intent.v1`. Move the Agent home to a local volume (#765).
- **Windows npm shims.** The adapters run a native `.exe` or `.com`, or a
  cmd-shim 4.1.0 or later shim of a `#!/usr/bin/env node` bin. They refuse
  other shims, for example pnpm, yarn or `#!/bin/sh` shims, as
  `not-executable`. A missing command or node gives `not-found`. Both adapters
  decline such an offer as not retryable (#763).
- **K4 and K8 wake retry (example).** A failed `schedule` or `cancel-wake` call
  retries from a process timer, at most 10 times in about 5 min. After that,
  only later drains retry the row. A K8 Host retries sooner than before and
  stops timed wake retries after about 5 min (#766).

## Qualification and remaining limits

Local results are in the preparation PR. They cover only the checks that the
preparation changes: version authority, release graph, registry contract and
protocol golden checks. The full workspace suite did not run locally. GitHub
CI runs the affected checks for the preparation PR.

Hosted qualification is pending. Ordinary PR CI runs only the affected
checks. The complete Linux, macOS and Windows matrix runs only through an
explicit `ci.yml` release dispatch with `release_sha` equal to the approved
main SHA. Earlier-SHA, skipped or unexecuted checks are not passes.

Open limits:

- The owner decided that the AiphaBee acceptance of 0.29.0 covers macOS only.
  The Windows code relies on the `windows-latest` legs of required CI, as for
  0.28.3 (#743, D5).
- B stays false for Agent memory (#605). A Windows write is atomic under a
  process crash, but the SDK makes no claim for an OS crash or a power loss.
  The power-loss experiment waits for a Windows environment from the owner.
- On macOS the helper checks only the volume of the Agent home itself. A
  network mount nested inside the home is not checked in this release (#765).
- Real-provider and real Windows Hermes and Grok runs wait for a Windows
  environment from the owner (#608, #609).
- The `submit_result` success rate on real runtimes needs paid calls and owner
  approval for each run (#610).
- No live provider run, real-user memory restore or downstream product
  acceptance is claimed.

Prepared from main `0952829a4fb4aba089f5aa65cb86066e54fe724b`. These notes
cover the changes since [0.45.1](v0.45.1.md), the current stable npm release.

## Version set and release gates

The release aligns `@byok-sdk/core`, `@byok-sdk/protocol`, `@byok-sdk/client`,
`@byok-sdk/server`, `@byok-sdk/cloud`, `@byok-sdk/cloud-dataplane`,
`@byok-sdk/ui-runtime`, `@byok-sdk/bot-collaboration`, and `@byok-sdk/keys` at
0.46.0.

The 0.45.1 → 0.46.0 upgrade manifest has **two breaking entries,
`pi-160-closure` and `dsh-session-log-upload-off`**, and no additive entries.
A breaking entry requires a MINOR under the pre-1.0 policy.
[Upgrade manifest](../../packages/client/upgrade-manifest.json) ·
[Version policy](../spec.md#pre-10-package-version-policy)

0.46.0 keeps wire v8. Its compatibility registration pins the same 514
envelope and 41 HTTP corpus lines as 0.45.0 and 0.45.1. The published
`@byok-sdk/protocol@0.45.0` tarball is the v8 decoder baseline, and the
published 0.44.1 tarball remains the v7 rejection oracle.
[Protocol compatibility evidence](README.md#protocol-compatibility-baseline)

The reviewed registry plan records 0.45.1 as the prior `latest` for all nine
packages. Candidate validation uses exact-SHA CI tarballs. Publication
requires successful release validation on the approved commit, separate
authorization, and registry readback.

## Host upgrade order

Unlike 0.45.0, this upgrade needs no store reset or re-pairing. Existing
0.45.0 and 0.45.1 server databases, daemon journals, provider stores, and device
pairings carry forward in place.

1. Drain queued and in-flight Pi preparations on 0.45.x. Keep a copy of any
   `pi-durable` replica you may need to resume on 0.45.x.
2. Upgrade the Host, server, and daemons to 0.46.0.
3. Prepare Pi inputs again with Pi 1.6.0 and replace any selection of a model
   removed from the catalog.
4. Optionally remove the Host `undici` 8.12.4 override and refresh the
   lockfile.
5. Run DSH tasks only on a DSH build that honors `sessionLogUpload: 'off'`,
   such as the qualified `0.2.2-rc.1`.

## Pi 1.6.0

The official Pi runtime pin moves from 1.5.2 to 1.6.0.
[#2098](https://github.com/Ancienttwo/byok-sdk/issues/2098) ·
[#2442](https://github.com/Ancienttwo/byok-sdk/pull/2442)

- The Pi 1.6.0 closure changes `closureDigest`. Inputs prepared with 1.5.2
  fail with `preparation_runtime_identity_mismatch`. Prepare them again with
  1.6.0 before dispatch.
- The keys catalog follows pi-ai 1.6.0. Lookups for the 40 removed entries
  from vendors and APIs in the keys catalog return `not_in_catalog`. Select a
  current model or supply an explicit manual `pi_model` configuration.
- `pi-durable` 1.6.0 opens replicas from 0.45.x and Pi 1.5.2 without a schema
  migration. The downgrade boundary is one-way: replicas with `pi.tool` v4 or
  `pi.generation` v3 fail to resume on 0.45.x with `task_too_old`.
- Pi 1.6.0 pins `undici` 8.12.4. Hosts can remove the `package.json` override
  added for #2098 and check that Pi resolves `undici` 8.12.4.

MCP toolset search is qualified for SDK-built Pi 1.6.0 in the ordinary lane on
macOS arm64 with `agentUserContext: 'inherit'`, the default SDK launcher, the
bundled Pi entry, the Node distribution helper, and SDK authorization `auto` or
`all`. Admission matches this exact combination.

## DSH session-log upload off

DSH sessions opened by the SDK, including root sessions, native child
sessions, and resumes, now run with `sessionLogUpload: 'off'`. Official
DeepSeek requests no longer carry `dsh_session_log`, and the saved session
gets no delivery-accepted watermark. DSH's separate `dsh_plugin_packages`
request field and other provider metadata are unchanged, so this does not
turn off all DSH telemetry. If DSH cannot confirm that the uploader is off,
the open fails non-retryably before any model request with an
`UnsupportedOptionError` cause (`option: 'sessionLogUpload'`). The qualified
DSH `0.2.2-rc.1` honors the setting. No Host option is added.
[Host steps](host-upgrade-0.46.0.md#dsh-session-log-upload-off) ·
[#2446](https://github.com/Ancienttwo/byok-sdk/issues/2446) ·
[#2451](https://github.com/Ancienttwo/byok-sdk/pull/2451)

## OAR 0.129.1

The client vendors `@botiverse/oar` 0.129.1 (0.45.x shipped 0.124.0) as
snapshot `packages/client/vendor/oar/c0c8b28`, projected from the fork branch
`byok/0.129.1` at `ac2459d3`. The move went through 0.128.1 first.
The 0.128.1 → 0.129.1 step adds no Host-visible change: upstream #1094,
#1116, and #1117 are inert in the SDK.
[#2445](https://github.com/Ancienttwo/byok-sdk/issues/2445) ·
[#2449](https://github.com/Ancienttwo/byok-sdk/pull/2449) ·
[#2451](https://github.com/Ancienttwo/byok-sdk/pull/2451)

Host-visible changes since 0.124.0, all introduced by 0.128.1:

1. Account usage `rateLimited` reflects only account-wide limits for Claude
   and Codex. A model-scoped or oauth-apps window at 100% no longer sets it,
   and Claude's unlimited Extra Usage counts as headroom. Grok usage returns
   `reauth_required` only for ACP `-32000`; other errors, such as TLS or proxy
   failures, now reject.
2. Claude account usage `plan` can report the validated `.claude.json`
   `oauthAccount.planDisplayName`, for example "Claude Max", when the stored
   account matches. It is read from the explicit reader environment.
3. DSH `listModels` returns `unauthenticated` instead of `ok` with an empty
   list when the default provider lists no models and reports no failure.
4. A DSH session rejects `steer` while idle locally with `no_active_turn`,
   rejects an overlapping `prompt` with `busy`, and reports `runtime_exited`
   instead of `error` for controls after the bridge exits.
5. A Codex abort refusal goes through `codexControlRefusal`. It carries the
   native error and maps `thread not found` to `session_not_found`.
6. Within one process, DSH session launches and model listings
   (`listModels`) on the shared SDK `DSH_HOME` serialize cold profile
   initialization. A waiting call honours caller abort and the startup or
   query timeout deadline, and spawns nothing after cancellation. `detect()`
   and launches from other processes are outside this lock. Upstream #1051
   (JSONC inline prompt configuration) and #1107 (DSH bridge local
   session-file `persistence.stat` lookup) are not carried.
7. A Codex turn with `codexErrorInfo: "other"` whose body has context-overflow
   wording, for example `prompt is too long`, reports `unknown` instead of
   `invalid_request`. The text-derived classification carries `fromText`.

## Fixed

All three known issues listed for 0.45.0 are fixed.

- After `stop()` exceeds its shutdown grace deadline, a restart on the same
  `Daemon` instance restores the local control listener. The control token
  file is replaced atomically when the listener rebinds, and sealed terminal
  replay and single-owner lease protection are unchanged.
  [#2437](https://github.com/Ancienttwo/byok-sdk/issues/2437) ·
  [#2440](https://github.com/Ancienttwo/byok-sdk/pull/2440)
- The best-effort zombie reap wait bounds both its poll sleep and the macOS
  `ps` probe timeout by the remaining `reapGraceMs` budget. On Linux the
  synchronous `procfs` read cannot be cut short by the remaining time, so the
  budget is not a hard deadline there. POSIX process-liveness tests use
  `(pid, start)` identity.
  [#2435](https://github.com/Ancienttwo/byok-sdk/issues/2435) ·
  [#2441](https://github.com/Ancienttwo/byok-sdk/pull/2441)
- Pi now resolves `undici` 8.12.4 through its own pin. See [Pi 1.6.0](#pi-160).
  [#2098](https://github.com/Ancienttwo/byok-sdk/issues/2098) ·
  [#2442](https://github.com/Ancienttwo/byok-sdk/pull/2442)
- The 0.45.1 `windows-user` fix is included: on a non-elevated desktop the
  lifecycle no longer fails when another user's, a Session 0, or an elevated
  `cmd.exe` command line is unreadable, `install()` records the current user's
  SID, and `inspectStoreServiceState` reports `unknown` instead of `stopped`
  for a different user. Hosts upgrading from 0.45.0 re-run `install()` to add
  the SID to their record.
  [#2452](https://github.com/Ancienttwo/byok-sdk/issues/2452) ·
  [#2453](https://github.com/Ancienttwo/byok-sdk/pull/2453)

## Protocol compatibility

The published `@byok-sdk/protocol@0.45.0` decoder is pinned as the Wire v8
baseline. The suite compares the published envelope and HTTP JSON Schemas with
the current schemas, decodes the v8 corpus with the published package, and
requires each new gated addition to use a flag unknown to 0.45.0.

## Host changes

### Embedded input image upload

A trusted embedded Host can call `server.blobs.uploadInputImage({ bytes,
contentType })` without a device credential or listener. Pass the returned
`InputImageBlobRef` in `images` to `server.dispatch`, in `payload.images` to
fresh `server.executions.submit`, or in `images` to `TaskHandle.steer` after the
task starts. The device must advertise `input-images`, and the runtime session
must support images.

```ts
const image = await server.blobs.uploadInputImage({ bytes, contentType: 'image/png' });
const task = await server.dispatch({ ...dispatchInput, images: [image] });
// After the device starts the task:
await task.steer('Compare this image', { images: [image] });
```

The upload checks PNG, JPEG, GIF, or WebP signatures against the declared MIME
type. The limit is the smaller of `INPUT_IMAGE_MAX_BYTES` (20 MiB) and the
server's `maxBlobSizeBytes`. Dispatch, fresh submit, and steer check that the
refs match committed metadata in the embedded tenant. Re-uploading the same
image refreshes its orphan grace period. Plaintext refs do not pin blobs, so
maintenance can collect them after grace even if a task has accepted the ref.
[Server image guide](../../packages/server/README.md#task-input-images) ·
[Refs #2395](https://github.com/Ancienttwo/byok-sdk/issues/2395)

### Offline provider credential recovery

When retiring a provider store, stop its writers and call
`listProviderProfileSecretNames(path)` from `@byok-sdk/keys` on the offline
database. It returns candidate entry names from recognized layouts without
reading credential values. Unknown layouts and database sidecars cause it to
refuse the read. Before deleting an entry, exclude names still used by active
stores in the same credential scope, confirm ownership, and obtain the user's
approval. Use the original `SecretStore` scope for cleanup. A credential with
no database row needs separate inventory review.
[Credential recovery steps](../../packages/keys/README.md#recover-provider-credentials-from-an-offline-store) ·
[Refs #2397](https://github.com/Ancienttwo/byok-sdk/issues/2397)

### Result MCP identifiers

Import `AGENT_RESULT_MCP_SERVER_NAME` and `AGENT_RESULT_TOOL_NAME` from
`@byok-sdk/client`. Match them against `event.mcp?.server` and `event.mcp?.tool`
when identifying result submissions. This replaces hard-coded helper names or
matching adapter-specific `event.tool` strings.
[Refs #2393](https://github.com/Ancienttwo/byok-sdk/issues/2393)

### Memory-change evidence on TaskResult

Read `agentHomeMemoryChange` from `await task.result()`. The optional field
carries the reader's terminal evidence as `unchanged`, `reader-attributed`,
`unattributed`, or `unmeasured`. The two changed outcomes include the relative
paths. Writer results omit the field, as do reader terminals without evidence.
Treat an absent field as unavailable evidence.
[Refs #2394](https://github.com/Ancienttwo/byok-sdk/issues/2394)

### Enrollment clear precheck

Call `inspectDeviceEnrollmentClear(options)` from `@byok-sdk/client` with the
same store and credential-provider options as `clearDeviceEnrollment`. Use
`store_owned` to explain that the store is owned or being reclaimed, and
`store_not_bound` to explain that the enrollment or staged pairing belongs to
another store. The precheck reads the current state without a lease or writes.
Use `ok: true` as a point-in-time hint and handle refusal from the clear itself,
which checks again under its lease.
[Refs #2398](https://github.com/Ancienttwo/byok-sdk/issues/2398)

### Undici override for Hosts

`@earendil-works/pi-coding-agent` 1.5.2 still pins undici 8.12.3. With npm
11.16, merge the global 8.12.4 override and the dependency chain into the
Host root `package.json`. If the root directly depends on `@byok-sdk/client`,
use this form.

```json
{
  "overrides": {
    "undici": "8.12.4",
    "@byok-sdk/client": {
      "@earendil-works/pi-coding-agent": { "undici": "8.12.4" }
    }
  }
}
```

If a workspace depends on the client, use its actual package name in the
chain and repeat for each such workspace.

```json
{
  "overrides": {
    "undici": "8.12.4",
    "<workspace-package>": {
      "@byok-sdk/client": {
        "@earendil-works/pi-coding-agent": { "undici": "8.12.4" }
      }
    }
  }
}
```

If `package-lock.json` already has an 8.12.3 entry at
`node_modules/@earendil-works/pi-coding-agent/node_modules/undici`, remove that
entry and its installed copy before regenerating the lock. Run
`npm install --ignore-scripts`, `npm ci --ignore-scripts`, and
`npm ls undici --all` from the Host root. Check that `npm ci` succeeds and
`npm ls` exits 0 with only 8.12.4 and no `invalid` or `ELSPROBLEMS`, then
rebuild shipped artifacts.
[Lock cleanup and Bun, pnpm, and Yarn settings](host-upgrade-0.44.0.md#undici-in-the-host-dependency-tree) ·
[Refs #2391](https://github.com/Ancienttwo/byok-sdk/issues/2391) ·
[Refs #2098](https://github.com/Ancienttwo/byok-sdk/issues/2098)

### Steer validation and uploader retry

Embedded steer checks image metadata in the server. The cloud kernel always
checks that the image names a committed tenant blob. If the embedded image
uploader fails to load, the current call reports `blob_upload_failed` and the
next call can load it again on the same server instance.
[Refs #2400](https://github.com/Ancienttwo/byok-sdk/issues/2400)

### OAR 0.120.0

OpenCode v1 and v2 ACP startups that share a canonical data directory queue
within one SDK process. The SDK resolves directory aliases using the owned
child’s filtered environment. It uses `XDG_DATA_HOME` when set or the native
home’s `.local/share` otherwise. The lock lives in memory. The SDK creates
neither a directory nor a lock file for this queue. Sessions can run in
parallel once their respective `initialize` calls finish.

Queueing, spawn, and `initialize` share a 60-second startup budget. If the
budget runs out in the queue, the SDK reports a `RuntimeExecutionFailure` with
`phase: 'start'` and `retry: 'retryable'`. Use your existing retry policy for
startup failures. A cancelled waiter leaves the queue before spawning a child.

The `@byok-sdk/client/adapters` model catalog can now return optional
`RuntimeModelEntry.serviceTierDetails` for Codex. Each detail includes its
native tier `id` and, when available, a `displayName` and `description`. Read
these for display and continue to select tiers by ID. Details follow
`serviceTiers` order and keep the first entry for each ID.
[Codex model catalog service tiers](../adapter-capabilities.md#codex-model-catalog-service-tiers)

The SDK continues to probe runtime versions independently. OAR’s
`installation()` cache is outside that projection. Claude retains caller-owned
stream-json handling, reports process exit before refusing pending interrupts,
and preserves record redaction. The upstream Cursor peer bump, Claude
`skills()` view change, and OpenCode skills provenance changes are outside the
SDK projection.

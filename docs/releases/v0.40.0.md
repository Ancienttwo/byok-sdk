## Changes since 0.39.0

The client upgrade manifest contains one breaking entry, for the Koffi 3.3.7 Windows native-asset literals, and eleven additive entries. Hosts packaging Windows native assets must rebuild them and update literal pins. ACP `tool_use` events now wait for settled input. The wire remains v5; its corpus adds three envelope rows and the HTTP corpus is unchanged. There is no new `deploy/sql` migration; the hosted Bot example adds a `dream_state` table through its own store migration. Other changes include native-session dreaming, Host memory and activity APIs, Linux Secret Service credential storage, and runtime updates.

## Not in 0.40.0

SDK key custody for OpenCode is tracked by [#1547](https://github.com/Ancienttwo/byok-sdk/issues/1547), with draft [#1551](https://github.com/Ancienttwo/byok-sdk/pull/1551); it is not in this release. The SDK holds no OpenCode key. A model that needs one, such as OpenCode Go, takes it from the device environment (login shell or `runtimeEnvironment.pass`) or OpenCode's own native login.

## Known limitations

- OpenCode has no qualified platform or combination in this release: its adapter declares `platforms: []`. Qualification requires a later release to add platforms.
- Task-scoped Host MCP is not qualified for OpenCode; `auto` tool authorization is unsupported.
- Native-session dreaming is device opt-in on macOS or Linux with a Pi memory lane and configured `sessionDir`, subject to the capability gates described in the Host guide.

## Upgrade notes for Hosts and deployments

Follow the [Host upgrade checklist](host-upgrade-0.40.0.md), including its Windows native-asset rebuild and hosted Bot store migration steps. Review the manifest and the release's platform and rollback boundaries before upgrading.

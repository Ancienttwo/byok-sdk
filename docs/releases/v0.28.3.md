## Security updates

- **Pi host in CommonJS bundles (client).** A CJS bundle of the Pi host no
  longer lets Pi's nested undici own the process-wide `fetch` dispatcher.
  Pi 1.3.0 depends on exactly undici 8.10.2. That version is in the range of
  the undici advisories of 2026-10-15, which 8.12.2 fixes. In an ESM graph,
  Node's own undici loads first and keeps the dispatcher. In a CJS bundle,
  Pi's copy loaded first and served every `fetch` in the process. The SDK
  entries now read the `Headers` global before they import the Pi host, so
  Node's copy keeps the dispatcher, as in ESM. A product that imports Pi
  itself must make the same read. The client README says how (#729). The
  SDK's own Pi host was not affected when it ran as ESM.
- **Not fixed by the SDK.** Pi's own undici copies (the nested 8.10.2 and the
  copy that its CLI bundle inlines) stay until a Pi release moves them. Node's
  own undici on the Node builds that `engines.node` admits is a Node runtime
  matter: v26.10.0 carries 8.10.2. No Node floor change is decided. openai
  7.19.0, which Pi's pi-ai 1.3.0 uses, declares undici as an optional peer
  dependency. So on openai's node x509 path, the Host's own tree decides which
  undici copy loads. A copy older than 7.30.1 (or, on the 8 line, older than
  8.12.2) has the advisories. #700 is closed with these items open. The Pi and
  Node items are in `docs/researches/2026-10-22-700-undici-copies.md` (#725). The
  openai item is in a #700 comment.
- **Hermes custody launcher (client, keys).** The launcher starts Hermes, and
  reads the provider key, only after the adapter writes one byte to its stdin.
  The adapter writes the byte after it adopts the launcher (on Windows, into
  the kill-on-close job). So neither the key nor Hermes exists outside the
  owned process tree (#714, #718).
- **Hosted surface threat model (docs).** `docs/security.md` now states, for
  each data category, what the Host operator, Postgres, R2, logs and backups
  can read, and how the category is deleted. A canary test checks the
  plaintext locations on real Postgres and S3 (#732).

## Upgrade notes for Hosts

- **Hermes: client and keys from one release.** The custody launcher protocol
  changed (#714). A keys 0.28.3 launcher with an older client waits for a byte
  that never comes. The start then fails after 20 s with the misleading
  "hermes gateway did not report ready in time". A keys 0.28.2 launcher with
  client 0.28.3 passes the byte to Hermes as one blank stdin line. Install
  client and keys from the same release.
- **Hermes on Windows.** The Hermes descriptor still declares only `darwin`
  and `linux`. So on Windows, runtime detection refuses Hermes with
  `platform_unsupported`, and the daemon declines a Hermes offer with
  `retryable: true`. Real-provider and real Windows Hermes runs are open
  (#608).
- **CommonJS and SEA Hosts.** A CJS bundle that runs Pi must define
  `import.meta.url` from `__filename`. It is the only `import.meta` property
  that a CJS Host must define (#709, #726). In a SEA, that define makes a "run
  main when `import.meta.url` matches `argv[1]`" check true. Guard the check
  with `isSea()` from `node:sea` (#717). On Windows, a CJS or SEA Host must
  pass `nativeAssetRoot`, so that koffi's loader does not run (#726). A product
  that imports Pi itself must read the `Headers` global before that import
  (#729). The client README and the SEA recipe README give the details.
- **Reliable egress resends.** A resend of a held `agent.egress.reliable` or
  `agent.content.receipt` record that arrives after the cloud recorded it now
  settles as `duplicate`, not `accepted`. It adds 1 to the client
  `outbound.duplicate` counter and to the server `dedupDrops` counter. In one
  daemon run, `observer.onInboundCommitted` fires once for each record (#698).
- **Grok.** `compatInstructions: 'disabled'` is opt-in and applies to every
  session of the adapter. It is not an isolation guarantee: Grok still loads
  `$GROK_HOME/AGENTS.md`, `$GROK_HOME/rules/` and `extra_rule_dirs`, and the
  Claude and Cursor skills, hooks and MCP servers (#634). A
  resumed Grok memory reader with a persona now fails with "persona resume is
  not qualified", as a writer does (#609).
- **Agent memory under `auto`.** When `agentMemoryMcp: 'auto'` does not admit
  the memory MCP, `status().agentMemoryMcp` reports `unavailable`, and the
  file-based memory guidance stays. A Host with its own memory writer sets
  `off` (#614).
- **Hosted data (cloud-dataplane).** `task.complete` writes no
  `object_reference` row for its artifact. Maintenance then deletes the
  artifact about 1 day after upload, unless the product adds a reference.
  `revokeDevice` deletes the `device` row, but the `pairing-completion:v1:`
  receipt keeps the device name until tenant erasure (#654).
- **Wire.** No wire change. The v3 corpus stays at 158 envelope lines and 17
  HTTP lines.

# 0.44.0 — release candidate

Prepared from main `22ce5e201aa27468a32322c917514a43f1328ce0`. The owner approved
the MINOR and start of preparation on 2026-11-18. The previous published
release is [0.43.0](v0.43.0.md).

## Version set and release gates

All nine public packages carry 0.44.0: `@byok-sdk/core`, `@byok-sdk/protocol`,
`@byok-sdk/client`, `@byok-sdk/server`, `@byok-sdk/cloud`,
`@byok-sdk/cloud-dataplane`, `@byok-sdk/ui-runtime`, `@byok-sdk/bot-collaboration`
and `@byok-sdk/keys`. `@byok-sdk/cloud-do` remains archived.

The 0.43.0 → 0.44.0 manifest has **108 breaking and 23 additive entries**.
The breaking changes require a MINOR under the pre-1.0 policy.
[Version policy](../spec.md#pre-10-package-version-policy) ·
[Upgrade manifest](../../packages/client/upgrade-manifest.json)

This is the first wire v7 candidate. Wire v6 and v7 peers cannot communicate.
The v7 registry pins 507 envelope and 40 HTTP corpus lines. The published
0.43.0 tarball remains the v6 rejection oracle.
[Protocol compatibility evidence](README.md#protocol-compatibility-baseline)

The registry plan records 0.43.0 as the previous `latest` for all nine
packages. Publication requires registry readback, successful release
validation on the approved commit and separate owner authorization.
[Registry plan](../../scripts/release/registry-expectations.json) ·
[Release runbook](../../deploy/runbooks/release-responsibility.md#release-checklist)

## Host upgrade order

1. Drain delivery on every device. Finish or abandon open collaboration work
   and export needed history with 0.43.0. Keep the old stores and sidecars.
   Prepare fresh server stores and K4/K8 ledgers. Hosted deployments must
   apply `0040_wire_v7.sql` on a new Postgres database and write Host settings
   afterward. Embedded server deployments must use a new SQLite file with
   schema 10. [Before upgrading](host-upgrade-0.44.0.md#before-upgrading) ·
   [New store](host-upgrade-0.44.0.md#new-store)
2. Update dispatch to use one `target`, read `executor` from the accepted claim,
   and handle `task.steer_refused`. Remove the retired APIs and run the
   candidate's `byok-agent config check` before switching binaries.
   [Wire v7](host-upgrade-0.44.0.md#wire-v7) ·
   [Config checks](host-upgrade-0.44.0.md#daemonconfig-rejects-unknown-fields)
3. Deploy cloud first, then switch the daemon and CLI together. Re-pair every
   device and configure providers. Recreate needed frozen work with v7
   templates in the new ledgers. [During the upgrade](host-upgrade-0.44.0.md#during-the-upgrade)
4. Check pairing, task start and terminal outcomes, store admission, and
   service recovery before restoring traffic. For rollback, restore a matching
   set of 0.43.0 binaries, config, stores and assets, then re-establish device
   enrollment as needed. [After the upgrade](host-upgrade-0.44.0.md#after-the-upgrade) ·
   [Known residuals](host-upgrade-0.44.0.md#known-residuals)

## AiphaBee integration

Bring the Topology L Local Agent and `byok-host` forward together. The SDK
vendors OAR 0.115.0 at `609f347`. [Refs #2376](https://github.com/Ancienttwo/byok-sdk/issues/2376)

### Provider catalogs and helper tools

- Replace the Host's OpenAI-compatible and Anthropic model-list requests with
  `discoverProviderModels(connection, secret)` from `@byok-sdk/keys`. Pass the
  connection's `adapter`, `authMode`, `baseUrl` and `providerKind`. It returns
  `{id, name}` rows sorted by ID. Handle the SDK's typed model-list errors.
  [Refs #2385](https://github.com/Ancienttwo/byok-sdk/issues/2385)
- Handle the result helper through `event.mcp` with
  `server: 'byokagentresult'` and `tool: 'submit_result'`. This replaces
  matching the Claude-specific `event.tool` string in chat outcome handling.
  [Refs #2386](https://github.com/Ancienttwo/byok-sdk/issues/2386)

### Runtime catalogs and account usage

- In `byok-host`, call supported `RuntimeAdapter.listModels()` and
  `accountUsage()` on demand in process, including before pairing. Use catalog
  `effortLevels`, `defaultEffort` and `effortUnavailableReason` to build the
  picker. Handle missing readers and usage states such as `reauth_required`
  and `access_token_expired`. Keep quota and auth health local. For a Host
  that uses control IPC, `runtimes.models` and `runtimes.usage` forward the
  same reads.
  [Refs #2379](https://github.com/Ancienttwo/byok-sdk/issues/2379)

### Effort, model and images

- Set `target.effort` from the selected model's menu and `target.modelId` on
  the `harness` lane when choosing a model per task. These options require the
  device's `task-execution-options` flag. Prepared and durable Pi lanes refuse
  effort. Treat unsupported options and model refusal as non-retryable and
  leave the selection visible so the user can change it.
  [Refs #2377](https://github.com/Ancienttwo/byok-sdk/issues/2377) ·
  [Refs #2378](https://github.com/Ancienttwo/byok-sdk/issues/2378) ·
  [Refs #2383](https://github.com/Ancienttwo/byok-sdk/issues/2383)
- Upload images first and pass 1–16 committed tenant blob refs with media
  type on dispatch or steer. Check `input-images` and the chosen runtime's
  image support. The opened session determines whether it can accept images.
  This applies to plain and sealed input. For hosted upload retries using
  the same idempotency key, replay the same content to recover the committed
  `BlobRef`. A different body with that key is refused.
  [Refs #2377](https://github.com/Ancienttwo/byok-sdk/issues/2377) ·
  [Refs #2380](https://github.com/Ancienttwo/byok-sdk/issues/2380) ·
  [Refs #2382](https://github.com/Ancienttwo/byok-sdk/issues/2382) ·
  [Refs #2383](https://github.com/Ancienttwo/byok-sdk/issues/2383)

### Subagent events

- Accept `subagent_start` and `subagent_end` and group child progress, tools,
  errors and usage by `agentPath`. Root events omit it. Settle the task from
  root events and show child usage separately from the root terminal total.
  Claude reports context tokens and window. On POSIX, Codex abort cleans up
  the turn's background processes while keeping attached MCP alive.
  [Refs #2377](https://github.com/Ancienttwo/byok-sdk/issues/2377) ·
  [Refs #2381](https://github.com/Ancienttwo/byok-sdk/issues/2381) ·
  [Refs #2383](https://github.com/Ancienttwo/byok-sdk/issues/2383)

### Windows runtime setup

- Use normal runtime detection for Claude Code 2.x installed through npm.
  The Windows resolver accepts npm's cmd-shim when the package bin is a native
  executable. [Refs #2384](https://github.com/Ancienttwo/byok-sdk/issues/2384)

## Undici override for Hosts

`@earendil-works/pi-coding-agent` 1.5.2 still pins undici 8.12.3. That version
is affected by six npm advisories, including the high-severity
GHSA-mqg3-3v4r-cm32. The patched 8.x version is **8.12.4**.
[High advisory](https://github.com/nodejs/undici/security/advisories/GHSA-mqg3-3v4r-cm32) ·
[npm package](https://www.npmjs.com/package/undici/v/8.12.4) ·
[Refs #2098](https://github.com/Ancienttwo/byok-sdk/issues/2098)

For npm, merge the [root or workspace dependency-chain override and lockfile
steps](host-upgrade-0.44.0.md#undici-in-the-host-dependency-tree) into the Host
configuration. Verify that `npm ls undici --all` exits 0 and lists only 8.12.4.
For Bun use `"overrides": { "undici": "8.12.4" }`; for pnpm use
`"pnpm": { "overrides": { "undici": "8.12.4" } }`; for Yarn use
`"resolutions": { "undici": "8.12.4" }`. Merge the setting with the Host's
existing config, reinstall, check every resolved copy and rebuild.
[Dependency tree checks](host-upgrade-0.44.0.md#undici-in-the-host-dependency-tree)

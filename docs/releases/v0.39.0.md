## Source and scope

`git log --first-parent v0.38.0..268e8d0f4` lists 19 commits: #1450, #1442,
#1443, #1458, #1456, the train merge #1466, #1468, #1470, #1472, #1479, #1478,
#1480, #1483, #1486, #1488, the train merge #1489, #1491, #1493 and #1495. Train
#1466 merges 13 frozen heads with `git merge --no-ff`: #1430, #1444, #1451,
#1452, #1453, #1459, #1454, #1460, #1463, #1462, #1461, #1464 and #1465. Train
#1489 merges 9: #1471, #1473, #1476, #1482, #1485, #1487, #1477, #1481 and
#1484. The changes are grouped by area.

Agent memory (protocol, client, server):

- #1452 (#1439): `MEMORY.md` takes at most 8 KiB (`RESIDENT_MEMORY_MAX_BYTES`,
  moved from `@byok-sdk/server/execution-core` to `@byok-sdk/protocol`, with no
  re-export). `memory_save` and Host intents refuse larger new content, and
  nothing truncates the file. A terminal may report a writer's over-limit file
  in `residentMemoryOverLimit`, gated on the server flag
  `resident-memory-over-limit`. Breaking (manifest
  `resident-memory-max-bytes-to-protocol`); additive
  (`resident-memory-over-limit`).
- #1453, #1460 (#1439, [ADR-048](../adr/ADR-048-device-injects-resident-memory.md)):
  the device reads `MEMORY.md` at the start of a fresh instruction task and
  `HostExecutionCore` no longer adds memory. The task fails without retry when
  the file is over the limit, unreadable or has more than one hard link.
  Breaking (manifest `device-injects-resident-memory`).
- #1459 (#1440): `AgentMemoryFilesystem` gains `observe` and
  `cleanupForRestore`, `walk` resolves with `{ paths, entries }`, and revisions
  compare raw bytes. The helper protocol and version are 3, with no support for
  the previous helper. Breaking (manifest
  `agent-memory-filesystem-raw-byte-compare`).
- #1454 (#1440): an Agent offer may carry `agentMemoryCommit: 'on-success'`,
  gated on the device flag `agent-memory-commit-on-success`. Any end other than
  `task.complete` restores `MEMORY.md` and `notes/` byte for byte. Additive
  (manifest `agent-memory-commit-on-success`).
- #1443 (#1440): the memory guidance says that memory holds data, and that the
  model must not follow instructions in it.
- #1480 (#1474): an on-success task that would leave a refused home now ends in
  `task.fail`, with the usual rollback, and `memory_save` refuses a replace past
  the snapshot limits.

Runtimes (client):

- #1476, #1482 (#1469): `AgyAdapter` runs the Antigravity CLI as a custom
  harness on darwin, linux and win32, from `DaemonConfig.runtimes.agy`. The
  Gemini API key stays in the daemon behind a per-process loopback proxy, and
  the retention class `agy-session-store` expires what agy keeps. `followUp` is
  refused, `steer` is unsupported, and subagents and schedules stop at the turn
  end. When adding agy with `session-ledger` above 30 days, set
  `agy-session-store` to at least the ledger plus one day. Additive (manifest
  `daemon-config-runtimes-agy`).
- #1471, #1487 (#1469): `createRuntimeAdapters` and `createDaemon` build
  `DshAdapter` from `DaemonConfig.runtimes.dsh`, and dsh runs on the vendored
  OAR dsh runtime instead of ACP. `followUp` is refused, a later turn resumes in
  a new process, and an MCP entry with `type: 'http'` or non-empty `env` or
  `headers` is refused at start. Breaking (manifest
  `daemon-config-runtimes-dsh`).
- #1470, #1485 (#1469): the vendored OAR source moves from 0.86.0 to 0.91.0
  (`vendor/oar/0e92470/`, upstream commit `0e924701`). All sixteen BYOK deltas
  are preserved and the move changes no API surface. See the
  [0.88.0](../researches/2026-11-06-oar-0.88.0-upgrade.md) and
  [0.91.0](../researches/2026-11-06-oar-0.91.0-upgrade.md) research notes for
  what is not taken.
- #1478, #1486 (Hermes): all-mode tool reminders fire for Hermes, `tool` and
  `tool_use.input` change shape, and permission requests are refused with
  `reject_once`. No manifest entry: no snapshot item changed.
- #1486, #1488 (Grok, dsh): a Grok task that stops on a permission request
  fails as semantic and non-retryable. All-mode tool reminders fire for Grok,
  whose `tool_use.input` is now the native `rawInput` object. No manifest entry:
  no snapshot item changed.
- #1483: a native Codex `error` frame with `willRetry: true` produces no `error`
  event.
- #1493: an agy session whose process-table read fails at the stop still closes
  and disposes.
- #1495: the `agy-session-store` TTL bound applies only to a daemon with an agy
  session store, so a config without agy is not refused for it.

Host toolsets and assertions (client):

- #1473 (#1469): a Host toolset server no longer receives
  `BYOK_HOST_TOOLSET_CONTEXT`, `BYOK_STORE_DIR` or `BYOK_PRODUCT_ID`. In a task
  run the daemon appends a context file path as the last argument, and
  `requestTaskAssertion` takes `{ contextFile, audience, timeoutMs? }`. Breaking
  (manifest `host-toolset-context-file`).
- #1472: the reserved `byokagentmessage`, `byokagentresult` and
  `byokagentmemory` MCP entries carry no `env`; their context is in a mode `0600`
  file in the Execution's scratch directory.
- #1442 (#1437): `requestDeviceAssertion` and `requestTaskAssertion` wait up to
  90 s for the daemon by default.

Windows (client, keys):

- #1463, #1462 (#1445): the device credential store and
  `WindowsCredentialManagerSecretStore` call Credential Manager in process
  through koffi. A packaged Windows Host must pass `nativeAssetRoot`, and
  `commandRunner` and `systemRoot` are gone from the keys options. koffi 3.2.0 is
  an optional dependency of keys, pinned to the client's version. The entry
  format is unchanged, so a rollback reads the entries. Breaking (manifest
  `windows-credential-koffi`, `keys-windows-credential-manager-koffi`).
- #1430, #1444 (#1423): with `toolAuthorization.fileScope`, Pi rpc and prepared
  tasks run scoped on Windows instead of declining before claim. No manifest
  entry: no snapshot item changed.

Examples:

- #1461 (#1446): K8 freezes a room Turn with read-only Agent memory.
- #1465 (#1446): K8 carries Bot history in `history`, a `buildHandoffPack`
  result, and `RetentionLimits` gains a required `handoff`.
- #1451 (#1449): `room-seat:` projection values carry the optional

- #1481 (#1475, [ADR-049](../adr/ADR-049-host-owned-bot-dreaming.md)): K8 Bots

  #1465 and #1451.

Protocol:

  calls it for a Host. Additive (manifest `protocol-build-handoff-pack`).
- #1477 (#1475): `buildDreamInstruction` builds the instruction of a dream task.
  Nothing calls it for a Host. Additive (manifest
  `protocol-build-dream-instruction`).

Retention (client):

- #1456 (#1455): a session ledger whose filename also matches terminal evidence

Wire and persistence. The wire stays v5 (`PROTOCOL_VERSION = 5`).
`agentMemoryCommit` on `task.offer` and `residentMemoryOverLimit` on
`task.complete`, `task.fail` and `task.cancelled` are gated additions in
`WIRE_ADDITIONS`, behind the device flag `agent-memory-commit-on-success` and
the server flag `resident-memory-over-limit`. The v5 corpus gains eight envelope
lines, six for the terminals and two for the offer: it has 351 envelope lines and
30 HTTP lines, and `v5.releases.json` registers that corpus for 0.39.0 next to
0.34.0 through 0.38.0. There is no new Postgres migration and no SQLite schema
change. The Pi closure stays at 1.5.0, and the digest-bound Pi launch configs
keep their versions.

## Not in 0.39.0

- agy steer, a structured signal for dsh background work and Hermes `rawInput`

- An SDK-side dream scheduler. `buildDreamInstruction` is a pure function, and

- The 0.38.0 exclusions are otherwise unchanged (see the
  [0.38.0 notes](v0.38.0.md#not-in-0380)).

## Known limitations

- dsh is closed at the root turn end, so background subagents and jobs stop
  there and their unfinished work is lost (#1492). agy subagents and schedules
  stop at the turn end too.
- A Host-owned MCP server that needs env cannot run under dsh or agy. dsh
  persistence of MCP entries is unaudited, so a token must not move into `args`.
- During an agy session, tools that agy starts can spend quota through the
  proxy, but cannot take the key.
- Grok's `grep`, `list_dir`, `monitor` and `use_tool` are unprobed, so their paths
  and commands may still go unclassified. A V4A `patch` on Hermes names no path
  until its result, so a V4A write outside the workspace raises no reminder.
- The device does not declare `agent-memory-commit-on-success` on Windows, and a
  device configured for durable Pi declines the field.
- A daemon crash before the restore can leave an over-limit `MEMORY.md` in place.
- The durable Pi lane stays darwin and linux only.
- The 0.38.0 limitations are otherwise unchanged (see the
  [0.38.0 notes](v0.38.0.md#known-limitations)).
- The PR CI ran checks selected by changed paths and skipped the full macOS
  client suite. The release matrix runs it on the exact `release_sha`.

## Upgrade notes for Hosts and deployments

The upgrade manifest (`packages/client/upgrade-manifest.json`, shipped in the
client package) lists each Host-visible API, config and example change from
0.38.0 with its impact, summary and migration link. The
[Host upgrade checklist](host-upgrade-0.39.0.md) covers a Host that moves from
0.38.0 to 0.39.0; a Host on an earlier release applies the
[0.38.0 checklist](host-upgrade-0.38.0.md) first. In short:

**No wire cut.** 0.39.0 speaks wire v5 like 0.38.0, so no drain is needed for
the wire. Pin all nine packages to exactly 0.39.0 together.

**Host and device together.** An older Host core with a newer device shows the
model `MEMORY.md` twice, at most 8 KiB more, without an error.

**Packaged Windows Host.** Pass `nativeAssetRoot` to
`readDeviceEnrollmentStatus`, `readDeviceEnrollmentIdentity` and
`createStoredDeviceProofSigner`, and pass a koffi from `loadSdkKoffiAsset` to the
keys store. An npm install needs no change.

**dsh and Host toolsets.** Move a dsh MCP entry to stdio `command` and `args`,
and do not rely on `followUp`. Make a Host toolset server accept the extra last
argument, and pass it as `contextFile`.

**K8.** A Host that vendored K8 copies the files its manifest entry names. Bots
dream by default: set cheap templates or pass `dreaming: false`, and route
`wake.consume` to `bot.consume`
([dreaming](../../examples/bot-collaboration/README.md#dreaming-1475)).

## Security fix: `.byok` case variants in the file scope (#1426)

#1427 fixes #1426, which is disclosed publicly in that issue.

- **Affected releases.** 0.32.0 through 0.37.0. The file-scope guard (#1231)
  and the scoped Pi file tools (#1238) both first shipped in 0.32.0;
  `git tag --contains 70ea894ab` lists `v0.32.0` through `v0.37.0`.
- **Conditions.** All three hold: the daemon configures
  `toolAuthorization.fileScope`; the task runs on Pi with the SDK's scoped
  file tools (`read`, `write`, `edit`, `find`, `grep`, `ls`); and the Agent
  home is on a case-insensitive volume, as the macOS APFS default is.
- **Impact.** A path such as `.BYOK/…` or `.Byok/…` passed the guard and
  opened `<home>/.byok/`, so the scoped tools read and wrote it without an
  approval. `.byok/` holds the home lease, the projection records,
  `runtime-sessions`, the agent-memory intents and the egress journal.
- **Fix.** The guard matches `.byok` without ASCII case, and checks the
  canonical target again, so an alias that only canonicalization reveals is
  refused too. Both refusals are the existing `internal_path`. The rule is
  the same on every platform, so on Linux a name such as `.BYOK` is now
  refused as well. In 0.38.0 the one path under `.byok` that a scoped
  tool may use is a memory-reader task's own run directory (#1422).
- **What the Host does.** Upgrade to 0.38.0. No config change is needed.

## Superseded first source candidate

The first source candidate, main `9519c6810` (#1429), failed release
validation (`ci.yml` run 41840658411) on Service upgrade (windows-latest), and
is superseded by this preparation. It was not tagged or published. The owner
chose to fix first. The two failures had different causes:

- Attempt 1: the upgrade smoke counted a Windows service restart only when
  the pid changed, and Windows gave the replacement daemon the pid that
  `taskkill /F` had just freed. A harness defect, no product change (#1433,
  fixed by #1435). The same attempt also failed the dataplane suites against
  real Postgres on the known mailbox-wake timing flake, unrelated to the
  product; they passed in attempt 2.
- Attempt 2: `byok-agent pair` against a running service used the generic
  10 s control request timeout. On Windows the `enrollment.pair` handler runs
  at least 13 serial OS credential operations, each compiling the credential
  bridge first, so the pairing succeeded while the CLI reported
  `control request "enrollment.pair" timed out` and exited 1. The defect is
  present in 0.37.0 (#1434, fixed by #1436).

Attempt 3 was cancelled. The fixes, and the ADR-043 clarification #1432, are
on main below this preparation.

## Source and scope

`git log --first-parent v0.37.0..316604bf9` lists 12 commits: #1413, #1415,
#1419, #1424, #1427, the train merge #1420, #1428, #1431, the superseded first
source candidate #1429, #1432, #1435 and #1436. The train merges two accepted
heads with `git merge --no-ff`: #1418 (which carries #1417) and #1416. The
changes are grouped by area.

Examples:

- #1417 (#1405): K8 `cancelTurn` and `cancelDelegation` are idempotent and
  return `TurnCancelResult` and `DelegationCancelResult`, in the shape of
  `cancelHostIntent` and read from the ledger: `cancelled`, `cancel_pending`
  or `already_settled`. `cancelDelegation` on a resolved delegation resolves
  `already_settled` instead of rejecting. The refusals carry codes:
  `DelegationError` (`unknown_delegation`, `not_cancellable`) and
  `HostIntentError` (`unknown_intent`, `already_settled`, `not_stuck`). A Bot
  Turn that `failStuckIntent` settles records `settleCode: 'outcome_failed'`.
  Breaking (manifest `k8-idempotent-owner-cancels`).
- #1418 (#1407): K8 `inputRoot(key, botId)` is a read-only query for whether
  an `input` committed. In the same manifest entry
  ([input root](../../examples/bot-collaboration/README.md#input-root-1407)).

Protocol, client and cloud:

- #1416 (#1404): an Agent-home projection may carry an optional
  `hostRevision`, owned by the Host. The daemon orders projections by
  `(profileRevision, hostRevision)`, an absent `hostRevision` being 0. A
  payload carrying it needs the new device flag
  `agent-home-projection-host-revision`, and the Cloud refuses it for a device
  that did not advertise the flag. Additive (manifest
  `agent-home-projection-host-revision`).

Client:

- #1428 (#1422): with `toolAuthorization.fileScope` configured, a
  memory-reader task runs on the Pi rpc and prepared lanes on darwin and
  linux instead of declining before claim with `file_scope_unsupported`. Its
  Agent home is read-only (a write is `file_scope_denied` / `read_only`), and
  its run directory `<home>/.byok/runs/<name>` (on resume, the one its
  session handoff recorded) is a writable `run` root. Every other path under
  `.byok` stays `internal_path`; the #1426 checks apply the exception only to
  a path inside the `run` root. The durable lane still refuses memory-reader
  offers. The `fileScope` root ids `home` and `run` are reserved and refused
  when the policy is constructed (`FileScopePolicyError`, code
  `invalid_file_scope`). The digest-bound Pi launch configs move to
  `byok.pi.rpc-launch` version 11 and `byok.pi.durable-launch` version 4,
  and `byok.pi.prepared-launch` from 7 to 8 since it carries the same grant
  (#1431), so the daemon and the Pi hosts must come from the same SDK
  version. No manifest entry: no snapshot item changed.
- #1427 (#1426): the security fix above.
- #1436 (#1434): `byok-agent pair` against a running service waits up to
  10 minutes for `enrollment.pair` instead of the generic 10 s control
  request timeout, so a pairing that succeeds no longer reports
  `control request "enrollment.pair" timed out` and exits 1. Other control
  requests keep the 10 s timeout. The `bin:byok-agent` closure budget moves
  from 2140833 to 2140928 bytes. No manifest entry: no snapshot item changed.
- #1419 (#1410): on Windows the Hermes gateway ownership check reads the
  process table through Windows Script Host (cscript.exe, JScript and WMI)
  instead of Windows PowerShell, whose cold start could pass the 15 s limit.
  Windows PowerShell starts only when Windows Script Host cannot run the
  script; the client then logs one `[byok/hermes-adapter]` warning per
  process.
- #1424 (#1421): the device setup page, the `fileScope` doc comment and the
  config schema description state the delivered file-scope boundary for tool
  authorization. Comments and docs only; no behavior change.

Release records, docs and tests:

- #1413: the 0.37.0 publication record, and the upgrade manifest rebaselined
  on 0.37.0.
- #1415: the retention reader-run oversized-tree test no longer depends on
  runner speed (test only).
- #1429: the first source candidate, superseded (see above).
- #1432: ADR-043 scopes the Agent home read-write of `mode: 'home'` and
  `mode: 'workspaces'` to writer tasks; a memory-reader's home is read-only,
  as #1428 implements (docs only).
- #1435 (#1433): the upgrade smoke counts a Windows restart after
  `taskkill /F` by the daemon's `uptimeMs`, not by a new pid (test only).

Wire and persistence. The wire stays v5 (`PROTOCOL_VERSION = 5`).
`hostRevision` on `agent.home.projection` is a gated addition in
`WIRE_ADDITIONS`, behind the device flag
`agent-home-projection-host-revision`. The v5 corpus gains one envelope line
for it: it has 343 envelope lines and 30 HTTP lines, and `v5.releases.json`
registers that corpus for 0.38.0 next to 0.34.0, 0.35.0, 0.36.0 and 0.37.0
(342 envelope lines). There is no new Postgres migration and no SQLite schema
change. The Agent-home ordering record keeps version 1 and stores
`hostRevision` only when the applied payload carried it. The Pi closure stays
at 1.5.0.

## Upgrade notes for Hosts and deployments

The upgrade manifest (`packages/client/upgrade-manifest.json`, shipped in the
client package) lists each Host-visible API, config and example change from
0.37.0 with its impact, summary and migration link. The
[Host upgrade checklist](host-upgrade-0.38.0.md) covers a Host that moves from
0.37.0 to 0.38.0; a Host on an earlier release applies the
[0.37.0 checklist](host-upgrade-0.37.0.md) first. In short:

**No wire cut.** 0.38.0 speaks wire v5 like 0.37.0, so no drain is needed for
the wire. Pin all nine packages to exactly 0.38.0 together.

**File scope.** A daemon that configures `toolAuthorization.fileScope` gets
the #1426 fix by upgrading; no config change is needed for it. A `fileScope`
root with the id `home` or `run` is now refused when the policy is
constructed: rename it before the upgrade (#1422). Memory-reader offers that
used to decline with `file_scope_unsupported` now run under the scope.

**K8.** A Host that vendored K8 copies `src/host.ts`, `src/index.ts`,
`src/delegation.ts`, `src/rules/delegation.ts` and `src/rules/turn.ts`, reads
the cancel results, and switches on `error.code` instead of message prefixes
([idempotent owner cancels](../../examples/bot-collaboration/README.md#idempotent-owner-cancels-1405)).

**Agent-home projection.** A Host that changes its rendering of the home
without a new `profileRevision` may raise `hostRevision`, after its devices
run 0.38.0 and advertise `agent-home-projection-host-revision`. A Host that
never sends it is unchanged.

The [pre-1.0 policy](../spec.md#pre-10-package-version-policy) requires a MINOR for breaking changes, new public APIs and forward migrations. The Hermes runtime removal (#1876, `feat!`), the task-attempt identity cut and the new Bot collaboration package therefore require 0.42.0 after 0.41.0. Wire remains v6. The [upgrade manifest](../../packages/client/upgrade-manifest.json) spans 0.41.0 to 0.42.0 with 15 breaking entries and 15 additive entries.

`@byok-sdk/bot-collaboration` joins the release set for its first npm publication (#1845, #1910). That first publication needs the owner's separate authorization. The [registry expectations](../../scripts/release/registry-expectations.json) record `previousLatest: 0.41.0` for the nine existing packages and `priorPublication: none`, `previousLatest: null` for the new package. Publication must verify its package-document absence; a failed registry read does not prove absence.

The [release checklist in #1918](https://github.com/Ancienttwo/byok-sdk/issues/1918) tracks the remaining review, a green full nightly on the freeze commit, owner approval of the exact release commit, accepted release-validation tarballs and AiphaBee's validation of those tarballs. Source preparation does not satisfy those gates. Publication, tagging, a GitHub Release and Host rollout remain separate owner actions. This draft records no publication or production acceptance.

## Changes since 0.41.0

- **Bot collaboration is a package.** Hosts replace vendored K8 code with `@byok-sdk/bot-collaboration` and its four public entries (`.`, `./host-kit`, `./rules`, `./testing`); the Host guide covers removed example exports, autonomy, hosted passes, would-do migrations and reply delivery after successful Turn outcomes (#1845, #1910).
- **Task attempts require an Agent identity.** `reserveAgentOffer` replaces `TaskAttemptStore.open`, Agent references become required, embedded SQLite advances to v9, and Postgres needs migration 0038, the explicit `retireAgentlessTasks` operation and migration 0039 in that order (#1780).
- **Keys and Pi routing.** OpenCode Go has its own provider kind and explicit Pi provider declaration; existing keys profile stores require `migrateProviderProfileStore`, preserving profiles and credential-store references (#1547, #1551, #1586).
- **Runtime API cuts.** Hermes runtime adapter exports are removed (#1854, #1876); Hosts also remove `versionPolicySource` and runtime failure `category`, handle the expanded memory-refusal union, and replace old Codex retention-class literals.
- **Embedded Host lifecycle.** Hosts gain `pairEmbedded`, `whenOpen`, `whenTaskSettled`, `clearDeviceEnrollment`, `resolveSdkHosting`, service payload metadata and Host payload verification; `LoopbackListener.close()` waits for all dispatched handlers (#1838-#1842).
- **Runtime sessions.** Claude and Grok run through OAR 0.101.0 (#1945, #1956) with their own-turn follow-up handling, Grok is qualified at 1.0.77, OpenCode supports Host MCP toolsets on its qualified macOS and Windows lines, and Pi 1.5.2 changes the preparation closure identity (#1632, #1853, #1863, #1864, #1884).
- **Packaged Pi and Agent memory.** Bun products with shipped assets can run background Pi subagents and workflows; Agent memory helper protocol 4 requires `ancestorRoot`, and daemon and helper must upgrade together (#1589, #605, #1652).
- **Host compilation.** Published declarations use runtime extensions so NodeNext and Node16 consumers can resolve the SDK types (#1828).

The [CHANGELOG](../../CHANGELOG.md#0420---2026-11-12-draft-source-candidate) records the full audited cut, including the startup Agent-memory call fix (#1861) and Pi settlement stats fix (#1860).

## Fixes included in the candidate

- **Claude follow-up receipts (#1941, #1952).** A written startup prompt or follow-up waits for stdin completion; a write failure rejects the caller instead of returning success first. A follow-up held behind a Claude-own turn keeps its existing immediate queue acceptance.
- **Bot collaboration test credentials (#1960, #1967).** `openLTestHost` requires an injected `deviceCredentials` backend; import `InMemoryDeviceCredentialBackend` from `@byok-sdk/client/testing` and pass it explicitly. The unpublished testing entry no longer exports `InMemoryDeviceCredentials` and supplies no default backend.
- **Desktop package smoke (#1963).** Signed codec-free ffmpeg comparisons canonicalize temporary copies before hashing, verify the original signature, and reject the stock Electron library as a negative control.
- **Cancelled recovery offers settle (#1944, #1958).** `Daemon.whenTaskSettled` resolves a received offer that a cloud cancellation suppressed as `cancelled` / `not-required` / `none` once the cancellation is journaled. `DaemonTaskSettlement.delivery` gains the member `not-required` (no local terminal envelope or runtime was required); a Host that checks it exhaustively handles the new member. Later waits and redelivery of that task id keep the result without starting a runtime. A Host-supplied journal (`overrides.journal`) must return a safe-integer `seq` on every task row; any other value is rejected as malformed.
- **Cancelled offers survive a restart (#1955, #1968; breaking).** `LocalTaskJournal` gains the required `readTaskCancellation(taskId, identity, afterSeq)`, so a received offer cancelled before admission keeps `cancelled` / `not-required` / `none` after a restart, with no `daemon_interrupted` failure, and redelivery cannot start a runtime. The SDK SQLite journal implements it on its existing envelopes, with no store migration. Custom journals and journal test doubles must add the method; see [Stored task cancellation](host-upgrade-0.42.0.md#stored-task-cancellation).

## Service install prepares kept stores (#1983, #1985)

With no current version, `install()` runs the store preparation `upgrade()` uses before it writes `current`, the installation record or the unit: quiesce daemon stores, run the candidate's required `precheck`, snapshot the listed stores, `migrate` when required, then precheck again. This covers stores kept by an earlier `uninstall()`. A same-id reinstall stays a unit and launcher repair without preparation. A first-install refusal uses upgrade's store error codes and removes staging. Host `migrate` programs must be safe to run again after an interruption, because install has no write-ahead receipt.

A failed preparation or health check restores the stores from `<installRoot>/snapshots/.install-<uuid>`. A failed restore renames that snapshot `.install-repair-<uuid>` and names it in the error; the next first install restores it automatically under the store leases before its precheck. A leftover `.install-<uuid>` is never restored automatically: the next first install refuses with the new `ServiceInstallationErrorCode` `install_snapshot_leftover`, lists every leftover path and starts nothing. After it holds the store leases, a first install reads `current` again and refuses with `installation_exists` if another installation wrote it in between; the refused call keeps every `versions/<id>` directory. `upgrade()` pruning and `uninstall()` keep every `.install-*` directory, and `uninstall()` refuses a symlinked `snapshots/` with the new code `snapshots_symlinked`. See [Service install prepares kept stores](host-upgrade-0.42.0.md#service-install-prepares-kept-stores) and the Known issues below.

## OAR 0.103.0 (#2005, #2006)

OAR 0.103.0: an Antigravity (agy) instruction longer than 185,000 UTF-8 bytes is now refused before agy is called, because agy cuts longer input without saying so; the Host receives task.fail with retryable: false, failure.class "input_too_large" and a reason naming the byte count and the bound. Upstream's account-usage contract additions do not reach any SDK type.

## Service payload installation (#1966, #1969)

`install()` starts the service and runs its health check. A failed install removes the unit, launcher, `current`, installation record and staged version directory, including on same-id reinstall; the error is `install_health_check_failed` with the original cause. A refused different-version install no longer leaves `versions/<id>`. Prepared Host and daemon stores are restored from the install snapshot (#1983), and OS credentials are never cleared. Before pairing, enable service enrollment or provide a Host health check; otherwise pair first. See the [Host installation guide](host-upgrade-0.42.0.md#service-install-requires-a-healthy-start).

`healthTimeoutMs` bounds the health-check wait only, starting after `start()` returns. Unit writes, activation, start and cleanup platform commands are outside that deadline and currently have no time bound ([#1971](https://github.com/Ancienttwo/byok-sdk/issues/1971)). `install()` enforces its deadline even if the Host health check ignores its abort signal; `upgrade()` and `restore()` are unchanged and remain abort-only ([#1977](https://github.com/Ancienttwo/byok-sdk/issues/1977)).

## Runtime versions

OpenCode 2.2.6 is qualified; 2.2.7, which a Host installing the latest OpenCode gets, is not yet qualified: after a resumed turn, 2.2.7 does not send the model the notice that Host MCP tools such as `submit_result` are no longer available, as required by the runtime contract ([#1972](https://github.com/Ancienttwo/byok-sdk/issues/1972)).

## Adapter session limits

agy and dsh accept fractional `interruptTimeoutMs`; the five adapters share consistent session-limit validation (#1679). Hosts using valid existing limits need no configuration change.

## Known issues

**Enrollment clearing with multiple stores ([#1964](https://github.com/Ancienttwo/byok-sdk/issues/1964)).** `clearDeviceEnrollment` and `Daemon.unpair` act on the productId-wide OS credential entry. With more than one store under one `productId` on one machine, clearing one store while another is pairing, or has an unresolved first pairing, can delete the other store's credential or staged pairing key. Do not clear one store in that state. The fix is deferred to the next release cycle.

- [#1940](https://github.com/Ancienttwo/byok-sdk/issues/1940): On a long-lived Claude session, permission and hook request/reply records and session bookkeeping can keep growing outside the retained-frame limit. Hosts must not treat that limit as a bound on the session's total memory use.
- [#1942](https://github.com/Ancienttwo/byok-sdk/issues/1942): If a Grok-own turn starts while an SDK turn's answer is being published, its text and usage can be attributed to that SDK turn. An interrupt in the same window can cancel the Grok-own turn. Hosts must account for this limitation when displaying replies or attributing usage.

- [#1943](https://github.com/Ancienttwo/byok-sdk/issues/1943): A runtime whose `start()` waits for an Agent memory tool result fails at the startup deadline. If activation fails while a memory call is pending, offer cleanup can block.
- [#1944](https://github.com/Ancienttwo/byok-sdk/issues/1944): When an offer declines or fails before any runtime starts and the release of its own scratch throws, `whenTaskSettled` reports `disposal: 'failed'` or `disposal: 'none'` depending on timing. An offer's own scratch is outside the meaning of `disposal`; Hosts must not act on `disposal` in this case.
- [#1946](https://github.com/Ancienttwo/byok-sdk/issues/1946): A failed key replacement, such as an OS credential-store write refusal, leaves the profile marked as having an unfinished key change until a replacement succeeds.
- [#1947](https://github.com/Ancienttwo/byok-sdk/issues/1947): The Desktop configure form keeps a typed key in renderer state while its save is pending.
- [#1948](https://github.com/Ancienttwo/byok-sdk/issues/1948): Desktop start fresh treats an inaccessible store as absent and can report success without proving that the store was cleared.
- [#1949](https://github.com/Ancienttwo/byok-sdk/issues/1949): On Pi, a cache-warming stop can act on a stale idle check, so a cache refresh can still reach the provider after a run settled. A soft interrupt also leaves a running pi-subagents background child active until the task closes.

- [#1957](https://github.com/Ancienttwo/byok-sdk/issues/1957): On ACP runtimes (Grok, agy and OpenCode), after a refused cancel notification, a second interrupt reports accepted without sending a cancel. Hosts cannot treat that acceptance as proof that cancellation was sent.

- [#1962](https://github.com/Ancienttwo/byok-sdk/issues/1962): During service payload installation, case-colliding paths on a case-insensitive volume, or a file swapped for a symlink while the manifest writer runs, can defeat the digests. A `verifyPayload` hook that modifies an already installed version and then throws leaves that version modified.
- [#1965](https://github.com/Ancienttwo/byok-sdk/issues/1965): An enrollment clear can report `clear_failed` after the credential was already deleted.

**Service installation after a failed store restore.** A failed restore of the install snapshot throws an `AggregateError` whose message names the kept snapshot path. Act on that path:

- `<installRoot>/snapshots/.install-repair-<uuid>`: retry `install()`. The next first install restores that snapshot automatically under the store leases, then continues.
- `<installRoot>/snapshots/.install-<uuid>`: the repair rename failed as well, and this directory may hold the only copy of the stores. Restore the stores from it by hand (compare its `snapshot.json` with the current stores), remove the directory, then retry `install()`. Until it is removed, `install()` refuses with `install_snapshot_leftover`.

A Host that installs with `replaceUnmarked` disables the legacy unit before calling `install()`, or retries `install()` after a failed restore before the next reboot or login. The legacy unit stays registered after a failed restore and can start on the partially restored stores; the retried install restores the repair snapshot over anything it wrote.

- [#1992](https://github.com/Ancienttwo/byok-sdk/issues/1992): After a failed store restore, a foreign unit allowed through `replaceUnmarked`, or an SDK-marked unit whose removal also failed, stays registered with the OS. A boot or login can start it on the partially restored stores before `install()` is retried.
- [#2001](https://github.com/Ancienttwo/byok-sdk/issues/2001): Installations that share one install root exclude each other only through the service lifecycle gate. Every installation on one install root must use the same `gateRoot` and the same OS user; other combinations are unsupported in 0.42.0 and can interleave installs.

## Host upgrade and rollback

Follow the [0.42.0 Host upgrade checklist](host-upgrade-0.42.0.md) before switching binaries or packages. Back up stores and stop their users. On the old embedded Host, resolve undelivered resume offers using the exact receipt-to-task identity checks. Remove all version 1 scope-key packages before upgrading; no migration exists for them. For Postgres, settle live Agent-less attempts on 0.41.0 before the 0038/retirement/0039 sequence. For embedded SQLite, inspect and settle Agent-less attempts before opening with v9. Migrate the keys profile store explicitly, rebuild matching helper and Pi assets, and prepare Pi inputs again for the 1.5.2 closure. Add `readTaskCancellation` to every custom `LocalTaskJournal` and its test doubles. A service Host makes its `migrate` program safe to run again, lists every store the candidate can rewrite in `precheck`, and uses one `gateRoot` and one OS user per install root.

Before publication, revert the preparation commit. After publication, ship a new version because npm versions are immutable. A Host rollback restores its pre-upgrade store snapshot and matching binaries/assets together; application downgrade does not reverse SQLite v9, Postgres 0038/0039 or the widened keys schema. Database operations, device distribution and production rollout require their own authorization.

The proposed npm channel is `latest`.

The [pre-1.0 policy](../spec.md#pre-10-package-version-policy) requires a MINOR for breaking changes, new public APIs and forward migrations. The Hermes runtime removal (#1876, `feat!`), the task-attempt identity cut and the new Bot collaboration package therefore require 0.42.0 after 0.41.0. Wire remains v6. The [upgrade manifest](../../packages/client/upgrade-manifest.json) spans 0.41.0 to 0.42.0 with 13 breaking entries and 15 additive entries.

`@byok-sdk/bot-collaboration` joins the release set for its first npm publication (#1845, #1910). That first publication needs the owner's separate authorization. The [registry expectations](../../scripts/release/registry-expectations.json) record `previousLatest: 0.41.0` for the nine existing packages and `priorPublication: none`, `previousLatest: null` for the new package. Publication must verify its package-document absence; a failed registry read does not prove absence.

The [release checklist in #1918](https://github.com/Ancienttwo/byok-sdk/issues/1918) tracks the remaining review, a green full nightly on the freeze commit, owner approval of the exact release commit, accepted release-validation tarballs and AiphaBee's validation of those tarballs. Source preparation does not satisfy those gates. Publication, tagging, a GitHub Release and Host rollout remain separate owner actions. This draft records no publication or production acceptance.

## Changes since 0.41.0

- **Bot collaboration is a package.** Hosts replace vendored K8 code with `@byok-sdk/bot-collaboration` and its four public entries (`.`, `./host-kit`, `./rules`, `./testing`); the Host guide covers removed example exports, autonomy, hosted passes, would-do migrations and reply delivery after successful Turn outcomes (#1845, #1910).
- **Task attempts require an Agent identity.** `reserveAgentOffer` replaces `TaskAttemptStore.open`, Agent references become required, embedded SQLite advances to v9, and Postgres needs migration 0038, the explicit `retireAgentlessTasks` operation and migration 0039 in that order (#1780).
- **Keys and Pi routing.** OpenCode Go has its own provider kind and explicit Pi provider declaration; existing keys profile stores require `migrateProviderProfileStore`, preserving profiles and credential-store references (#1547, #1551, #1586).
- **Runtime API cuts.** Hermes runtime adapter exports are removed (#1854, #1876); Hosts also remove `versionPolicySource` and runtime failure `category`, handle the expanded memory-refusal union, and replace old Codex retention-class literals.
- **Embedded Host lifecycle.** Hosts gain `pairEmbedded`, `whenOpen`, `whenTaskSettled`, `clearDeviceEnrollment`, `resolveSdkHosting`, service payload metadata and Host payload verification; `LoopbackListener.close()` waits for all dispatched handlers (#1838-#1842).
- **Runtime sessions.** Claude and Grok run through OAR 0.99.0 with their own-turn follow-up handling, Grok is qualified at 1.0.77, OpenCode supports Host MCP toolsets on its qualified macOS and Windows lines, and Pi 1.5.2 changes the preparation closure identity (#1632, #1853, #1863, #1864, #1884).
- **Packaged Pi and Agent memory.** Bun products with shipped assets can run background Pi subagents and workflows; Agent memory helper protocol 4 requires `ancestorRoot`, and daemon and helper must upgrade together (#1589, #605, #1652).
- **Host compilation.** Published declarations use runtime extensions so NodeNext and Node16 consumers can resolve the SDK types (#1828).

The [CHANGELOG](../../CHANGELOG.md#0420---2026-11-12-draft-source-candidate) records the full audited cut, including the startup Agent-memory call fix (#1861) and Pi settlement stats fix (#1860).

## Adapter session limits

agy and dsh accept fractional `interruptTimeoutMs`; the five adapters share consistent session-limit validation (#1679). Hosts using valid existing limits need no configuration change.

## Known issues

- [#1940](https://github.com/Ancienttwo/byok-sdk/issues/1940): On a long-lived Claude session, permission and hook request/reply records and session bookkeeping can keep growing outside the retained-frame limit. Hosts must not treat that limit as a bound on the session's total memory use.
- [#1941](https://github.com/Ancienttwo/byok-sdk/issues/1941): A Claude follow-up can be reported accepted while its process is already exiting, before the input write completes. A later write or process failure can leave an accepted follow-up undelivered; acceptance alone does not prove that Claude received it.
- [#1942](https://github.com/Ancienttwo/byok-sdk/issues/1942): If a Grok-own turn starts while an SDK turn's answer is being published, its text and usage can be attributed to that SDK turn. An interrupt in the same window can cancel the Grok-own turn. Hosts must account for this limitation when displaying replies or attributing usage.

- [#1943](https://github.com/Ancienttwo/byok-sdk/issues/1943): A runtime whose `start()` waits for an Agent memory tool result fails at the startup deadline. If activation fails while a memory call is pending, offer cleanup can block.
- [#1944](https://github.com/Ancienttwo/byok-sdk/issues/1944): `Daemon.whenTaskSettled` can wait indefinitely for an offer that a cloud cancellation suppressed after a crash. Use a bounded wait with an abort signal. A scratch cleanup failure can also be reported as `disposal: 'failed'`.
- [#1946](https://github.com/Ancienttwo/byok-sdk/issues/1946): A failed key replacement, such as an OS credential-store write refusal, leaves the profile marked as having an unfinished key change until a replacement succeeds.
- [#1947](https://github.com/Ancienttwo/byok-sdk/issues/1947): The Desktop configure form keeps a typed key in renderer state while its save is pending.
- [#1948](https://github.com/Ancienttwo/byok-sdk/issues/1948): Desktop start fresh treats an inaccessible store as absent and can report success without proving that the store was cleared.
- [#1949](https://github.com/Ancienttwo/byok-sdk/issues/1949): On Pi, a cache-warming stop can act on a stale idle check, so a cache refresh can still reach the provider after a run settled. A soft interrupt also leaves a running pi-subagents background child active until the task closes.

- [#1957](https://github.com/Ancienttwo/byok-sdk/issues/1957): On ACP runtimes (Grok, agy and OpenCode), after a refused cancel notification, a second interrupt reports accepted without sending a cancel. Hosts cannot treat that acceptance as proof that cancellation was sent.

## Host upgrade and rollback

Follow the [0.42.0 Host upgrade checklist](host-upgrade-0.42.0.md) before switching binaries or packages. Back up stores and stop their users. On the old embedded Host, resolve undelivered resume offers using the exact receipt-to-task identity checks. Remove all version 1 scope-key packages before upgrading; no migration exists for them. For Postgres, settle live Agent-less attempts on 0.41.0 before the 0038/retirement/0039 sequence. For embedded SQLite, inspect and settle Agent-less attempts before opening with v9. Migrate the keys profile store explicitly, rebuild matching helper and Pi assets, and prepare Pi inputs again for the 1.5.2 closure.

Before publication, revert the preparation commit. After publication, ship a new version because npm versions are immutable. A Host rollback restores its pre-upgrade store snapshot and matching binaries/assets together; application downgrade does not reverse SQLite v9, Postgres 0038/0039 or the widened keys schema. Database operations, device distribution and production rollout require their own authorization.

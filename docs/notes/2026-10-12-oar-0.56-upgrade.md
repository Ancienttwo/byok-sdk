# OAR 0.56.0 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.54.3`, commit
`b36b439e328d836fd24d838bdadea6d2ecbcaeb5`, with tag `v0.56.0`, commit
`163d551200fde714a224619519df68f5b217495d`. v0.56.0 is the latest release. The
directory moves from `vendor/oar/b36b439` to `vendor/oar/163d551`. Package
manifests and the Bun lockfile need no change.

## Source and maintained boundaries

All 41 selected source files and LICENSE were compared against both upstream
commits. Four paths changed upstream: `contracts/records.ts`,
`contracts/session-options.ts`, `runtimes/codex/open.ts` and
`runtimes/codex/session.ts`. The other 37 source files and LICENSE retain the
same upstream bytes.

Two files enter the inventory because changed selected files import them:
`contracts/turn-outcome.ts` (records) and `shared/additional-directories.ts`
(open). The second imports `node:path`, `contracts/errors.ts` and
`contracts/session.ts`; both contracts were already vendored. The inventory is
now 43 source files and LICENSE. No npm dependency enters the closure.

Thirty-seven source files keep upstream bytes. The six maintained files do not
change as a set. Two of them take upstream changes:

- `open.ts`: take `additionalDirectories` as `runtimeWorkspaceRoots` on
  `thread/start` and `thread/resume`, with the resolved `cwd` first, and the
  open refusal when the reply does not confirm each requested root. Keep the
  approval policy option. The three-way merge was clean.
- `session.ts`: take `outputSchema` on each `turn/start` and the `unsupported`
  queue refusal while a schema is set. The three-way merge had one conflict, on
  the queue gate. Upstream gates queue images there; BYOK leaves image
  admission to the caller. The merged gate adds only the schema refusal.

`app-server-client.ts`, `rpc-control.ts`, `session-kernel.ts` and
`credential-redactor.ts` have no upstream change. Only their change notices name
the new base. The source manifest records both upstream and maintained SHA256
values, and the `delta` text of `open.ts` and `session.ts` names the 0.56.0
change.

The JS bridges, their declaration checks, tests, the real Codex smoke script
and the build provenance copy use the new directory. The changelog, ADR,
third-party attribution and the current Codex source contract in the spec
identify 0.56.0. The 0.26.0 release notes, the README and spec release history
and the 0.54 upgrade note keep their historical source version. The historical 0.24 release provenance link now points to the retained
history in the new vendor directory.

## Behavior

The SDK behavior does not change. The SDK Codex adapter passes neither
`additionalDirectories` nor `outputSchema`. The private bridge declaration
does not expose them, and its type check picks only the options it declares, so
no omission is needed. The raw Codex session in the bridge has no `queue`
member, so the new queue refusal cannot reach SDK callers. SDK events read
native frames only, so `TurnOutcome.structuredOutput` does not reach them.

Upstream 0.55.0 and 0.56.0 also add these options to other runtimes, the
`commands` inventory and process-tree cleanup for Claude and Grok queries.
These modules are outside the selected closure.

To expose either option to SDK callers is a separate public API decision.
Codex returns text only for `outputSchema`; the host parses and validates it.

## Validation

- Targeted OAR session, app-server client, native event projection and owned
  process tests: 4 files, 76 tests passed. New cases cover cwd-first workspace
  roots on start and resume, the refusal and process release when codex does
  not confirm the roots, `outputSchema` on `turn/start`, the queue refusal with
  no `thread/queue/add` write, and no new parameters when neither option is
  given.
- Every upstream/vendor manifest SHA256 was checked against the pinned
  upstream commit, and built provenance assets match their source files.
- `bun run build`, `bun run typecheck`, `bun run check:api-surface`,
  `bun run check:version-authority` and `bun run test:scripts` (68 tests,
  including the OAR JS/declaration bridge checks): passed. The bridge needed
  no new omission.
- `BYOK_TEST_BUN_BIN="$(command -v bun)" bun run test`: the client suite passed
  3,678 cases and skipped 28, with one failure outside the OAR closure. The
  redirected-background case in `fix-pi-durable-shell-exit.test.ts` timed out
  under load. It passed 3/3 alone on this change and 3/3 on `origin/main`. The
  sequential run stops after the client, so the other ten workspaces ran
  separately under the same environment, and all of them passed.
- `bun run check:release-pack` was not run. It refuses a dirty worktree, and
  this change is uncommitted.
- Live Codex provider sessions are outside this validation. The SDK passes
  neither new option to Codex.

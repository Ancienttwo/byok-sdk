# OAR 0.29.0 source upgrade

## P1 boundary

OAR is private source in the client package. It is not an npm dependency.
The old base is tag `v0.25.0` at `a800aa00ba9c754c88ba25f84a6981e757b0f19f`.
The new base is tag `v0.29.0` at `f1a2b88eb63e47de8197514e9329642e2d0ae02c`.
The selected inventory now has 23 TypeScript files and LICENSE.
The JS bridge, declaration check, tests and provenance copy refer to this inventory.

## P2 runtime path

The path does not change. `CodexAdapter` calls the JS bridge, which exports the
private `codexSession`. The kernel sends native records to `CodexProjection`.
The new upstream usage projection adds optional cache token parts to the
`usage` record. BYOK consumers ignore fields they do not read.

## P3 decision

Compare all selected upstream paths before changing the base.
Four selected paths changed upstream:

- `contracts/records.ts`: optional `TokenTotals.cacheRead` and `cacheWrite`.
- `contracts/installation.ts`: optional `ExecutableInstallation.shadowed`.
- `contracts/account-usage.ts`: one comment.
- `runtimes/codex/projection.ts`: reports Codex cache token parts.

`projection.ts` now imports `shared/token-totals.ts`, so the inventory adds it
with upstream bytes. The upstream hunk applies cleanly to the maintained
`projection.ts`. Keep all six maintained BYOK source deltas. Keep the other
17 source files equal to the target upstream bytes.

Upstream policy check: OAR reads each runtime version and gates only a
feature path that needs a newer release (login floors). The BYOK Codex adapter
follows the same rule since the version-advisory change.

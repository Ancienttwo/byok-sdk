# OAR 0.54.3 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.48.0`, commit
`087df160dd64cd020c98a8b089ce8feb01f73590`, with tag `v0.54.3`, commit
`b36b439e328d836fd24d838bdadea6d2ecbcaeb5`. v0.54.3 is the latest 0.54.x
release. The directory moves from `vendor/oar/087df16` to
`vendor/oar/b36b439`. Package manifests and the Bun lockfile need no change.

## Source and maintained boundaries

All 36 selected source files and LICENSE were compared against both upstream
commits. Fourteen paths changed upstream: `contracts/failure.ts`,
`contracts/records.ts`, `contracts/session-options.ts`, `contracts/session.ts`,
`contracts/status.ts`, `contracts/tasks.ts`,
`runtimes/codex/app-server-client.ts`, `runtimes/codex/failure.ts`,
`runtimes/codex/open.ts`, `runtimes/codex/rpc-control.ts`,
`runtimes/codex/session.ts`, `shared/failure-class.ts`, `shared/mcp-servers.ts`
and `shared/session-kernel.ts`. The other 22 source files and LICENSE retain
the same upstream bytes.

Five files enter the inventory because changed selected files import them:
`shared/native-error.ts` (app-server client), `contracts/session-not-found-error.ts`
(rpc-control), `shared/credential-redactor.ts` and `shared/redact-text.ts`
(open and mcp-servers), and `observe/graph.ts` (session kernel; contract types
only). The inventory is now 41 source files and LICENSE. No npm dependency
enters the closure.

`shared/session-credentials.ts` and `shared/seal-session.ts` are not vendored.
Upstream Codex wraps its opener with `withSessionCredentials` and seals the
session, which pulls `sealSession` and the observe views. The BYOK raw adapter
never seals, so `session.ts` builds the same redactor directly.

Thirty-five source files keep upstream bytes. Six files are maintained, as
before, but the set changes. `shared/mcp-servers.ts` returns to upstream bytes,
because upstream removed the `toSorted` line that was its only BYOK delta.
`shared/credential-redactor.ts` becomes maintained: it sorts the spread copy in
place of `toSorted`, twice, for the SDK ES2022 library. Its `URL.canParse`
stays: `@types/node` types it under the ES2022 lib, and the Node 24 engine
floor provides it. Each change notice names the new base, and the source
manifest records both upstream and maintained SHA256 values.

Maintained deltas:

- `app-server-client.ts`: take the request method on each pending entry, the
  undefined-waiter guard and the `nativeErrorCause` cause (`{ method, native }`
  with the native error redacted). Keep the injected transport, deadlines,
  budgets and settlement seams.
- `open.ts`: take `sessionCredentialRedactor(options)` in place of
  `mcpCredentialRedactor`. Keep the approval policy option.
- `rpc-control.ts`: take `SessionNotFoundError` for a `thread/resume` answered
  with -32600 and a message starting `no rollout found for thread id`, the
  `resumeId` parameter and the direct native cause. Keep the timeout and the
  synchronous response capture. The three-way merge had one conflict, on the
  change-notice line.
- `session-kernel.ts`: take the record redactor, the record-derived graph
  through `withSessionRecord`, `link()` returning `session_linked`, the removal
  of `node()` and `settle` with the native request body. `redact` joins the
  existing `hooks` object instead of a second positional parameter. Order:
  redact, then the fatal byte budget on the redacted record, then retention and
  graph, then the required consumer and observers with that record.
- `session.ts`: one `sessionCredentialRedactor(options)` per open. Its
  `redactValue` is the kernel hook. It also redacts errors from the open path
  and from `prompt`, `steer`, `queue`, `abort` and `dispose`, as upstream's
  guard does. `options.resume` reaches `openThread`. The `kernel.node` calls are
  removed. A foreign thread's notification enters the graph through the
  record's `sessionId`, and fold `link` commands become `kernel.link` events on
  the derived frame. Native-first frames keep empty events.
- `credential-redactor.ts`: the ES2022 `sort` delta above.

The JS bridges, their declaration checks, tests, real Codex smoke script and
build provenance copy all use the new directory. The spec, changelog, ADR and
third-party attribution identify 0.54.3. The 0.26.0 release notes and the 0.48
upgrade note keep their historical source version. The historical 0.24 release
provenance link now points to the retained history in the new vendor directory.

## Behavior

Session credentials are now redacted in retained records, in what the required
record consumer receives (so in SDK events built from them) and in Codex
session errors. The rule is upstream's. It covers env and MCP stdio env values
whose name's last `_` word is a credential word (`KEY`, `APIKEY`, `TOKEN`,
`SECRET`, `PASSWORD`, `PASSWD`, `PASSPHRASE`, `CREDENTIAL(S)`, `COOKIE`, `PWD`)
or is `PGPASSWORD`, MCP HTTP auth and credential-named headers, and URL
passwords. A value needs at least eight characters and must not be a path. BYOK
passes the complete filtered environment, so provider keys in it are covered.
The native process input, wire requests and server-request handler parameters
stay unchanged. The byte budget measures the redacted record.

A Codex resume of a missing thread now rejects with `SessionNotFoundError`. Its
message keeps the `codex thread/resume failed: …` prefix, and its cause is
`{ method, native }`. Other failed opens keep plain errors, whose cause is now
the native diagnostic directly. The SDK Codex adapter still maps an open failure
as before; this upgrade does not change that classification.

The contracts add `FailedTurn`, `session_linked`, `input_queued`,
`tool_call_input_delta`, `turn_active.inputId` and the `failure` and `message`
of a `runtime_refused` `input_dropped`. `runtimes/codex/projection.ts` keeps
its bytes, so of these the Codex fold emits only `session_linked`, on derived
frames. SDK events read native frames only, so none of these kinds reach them.
The session graph keeps its observable shape: foreign thread ids become nodes,
and only reported collaboration lineage becomes edges.

## Validation

- Targeted OAR session, app-server client, native event projection and owned
  process tests: 4 files, 71 tests passed. New cases cover the missing resume
  target (-32600 with the verified message) and the two near misses that stay
  plain errors, redaction in retained records and in the required consumer
  with unchanged native input, redaction of open-path, spawn and control
  errors, the byte budget on the redacted record, and the record-derived graph.
- Final validation ran in an isolated worktree based on main commit
  `2aa91ecb`, with Bun 1.4.2 and Node 24.18.0. After rebasing onto `ac52d3d9`,
  the acceptance gate reran build, typecheck, both checks, `test:scripts` and
  `bun run test` without `BYOK_REQUIRE_BUN`: one long-poll timing case in
  `unknown-message-type-tolerance.test.ts` timed out under load and passed 9/9
  alone; every other workspace passed.
- `bun run build`, `bun run typecheck`, `bun run check:api-surface` and
  `bun run check:version-authority`: passed.
- `BYOK_TEST_BUN_BIN="$(command -v bun)" BYOK_REQUIRE_BUN=1 bun run test`:
  the client suite passed 3,656 cases and skipped 27, with two failures outside
  the OAR closure. The `node` host form in `pi-host-payload.test.ts` fails
  because this host's Homebrew Node 24 links `@rpath/libnode.137.dylib` and
  cannot run when copied. `BYOK_REQUIRE_BUN=1` turns that skip into a failure,
  and a bare copy of the binary reproduces the dyld error. A claude-native
  trace read in `task-runner-cancel-native.test.ts` raced under load and passed
  56/56 when run alone. The sequential run stops after the client, so the other
  workspaces ran separately under the same environment: 3,817 Vitest cases
  passed and 133 skipped, plus 15 cloud-do Node cases.
- `bun run check:release-pack` was not run. It refuses a dirty worktree so that
  `sourceGitSha` names the packed contents, and this change is uncommitted.
- `bun run test:scripts`: 68 tests passed, including the OAR JS/declaration
  bridge checks. The bridge needed no new omission.
- Every upstream/vendor manifest SHA256 was checked against the pinned
  upstream commit, and built provenance assets match their source files.

The fake Codex fixture answers a missing resume with code -32000, so the SDK
adapter test of that path still sees a plain error. Upstream pins -32600 for
Codex 0.162.0. Live Codex provider sessions and optional Docker dataplane
suites are outside this validation.

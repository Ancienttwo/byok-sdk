# OAR 0.45.1 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.44.0`, commit
`98be973dea8e7f745507ab4039059f9bac6c2ee4`, with tag `v0.45.1`, commit
`7dc98e08f9c0ba99158ddada29cb0d4c80ef7dc6`. The directory moves from
`vendor/oar/98be973` to `vendor/oar/7dc98e0`. Package manifests and the Bun
lockfile need no change.

## Source and maintained boundaries

All 35 selected source files and LICENSE were compared against both upstream
commits. Eight paths changed upstream: `contracts/records.ts`,
`contracts/session-options.ts`, `contracts/session.ts`,
`runtimes/codex/app-server-client.ts`, `runtimes/codex/open.ts`,
`runtimes/codex/projection.ts`, `runtimes/codex/rpc-control.ts` and
`runtimes/codex/session.ts`. The other 27 source files retain the same upstream
bytes. The selected import closure adds no files or npm dependencies.

Twenty-nine source files retain upstream bytes. The existing six maintained
files keep their BYOK deltas. Each change notice names the new base, and the
source manifest records both upstream and maintained SHA256 values.

Three-way merging needed local resolutions in three files:

- `app-server-client.ts`: keep injected spawn, explicit env/cwd and count
  budgets; take the launch-argument ordering and corrected sandbox comment.
  The owned spawn still owns stderr and tree termination.
- `open.ts`: take service-tier params on start and resume alongside the
  existing caller-selected approval policy.
- `session.ts`: take launch arguments alongside the caller-selected sandbox,
  explicit filtered environment and adoption wait. Pass the requested tier
  to the upstream open-error helper.

The JS bridges, their declaration checks, tests, real Codex smoke script and
build provenance copy all use the new directory. The spec, changelog and
third-party attribution identify 0.45.1. Published rc.1 release notes keep
their historical 0.44.0 source version. The historical
0.24 release provenance link now points to the retained history in the new
vendor directory.

## Behavior

The raw adapter accepts `launchArgs` after the sandbox `-c` overrides and
before `--listen stdio://`. It accepts `serviceTier` on start and resume,
checks the native reply before publishing the session and records native
`service_tier` events on open and settings updates. Native null means
`default`; an absent field is no evidence. A substituted or unreported
requested tier refuses the open and kills the owned process. An open RPC
failure identifies the unconfirmed requested tier.

BYOK's private declaration bridge exposes neither new option. Ordinary SDK
task launch behavior and SDK events stay the same. Upstream's model lister,
executable diagnostics, derived Session queries and observe implementation
remain outside the selected closure. The 0.45.1 concurrent-message observe
fix therefore does not enter this raw adapter.

  process tests: 4 files, 60 tests passed. New cases cover launch arguments,
  tier readback on start/resume, null opt-out, settings updates, substituted
  or missing native evidence, and failed open RPC cleanup.

- Every upstream/vendor manifest SHA256 was checked against the pinned

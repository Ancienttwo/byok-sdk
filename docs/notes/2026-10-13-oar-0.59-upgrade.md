# OAR 0.59.1 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.57.0`, commit
`0804b915ef511d2880e07d5329450c2484d8d62e`, with tag `v0.59.1`, commit
`bb98cbc1e383ea7192da0c87ce777d799669a7a9`. v0.59.1 is the latest release. The
directory moves from `vendor/oar/0804b91` to `vendor/oar/bb98cbc`. Package
manifests and the Bun lockfile need no change.

## Source and maintained boundaries

All 44 selected source files and LICENSE were compared against both upstream
commits. Four paths changed upstream: `contracts/session-options.ts`,
`runtimes/codex/open.ts`, `runtimes/codex/rpc-control.ts` and
`runtimes/codex/session.ts`. The other 40 source files and LICENSE retain the
same upstream bytes.

Files enter the inventory only through imports of the selected files, and
all of them keep upstream bytes:

- `contracts/session-unavailable-error.ts` (rpc-control). It has no imports.
- `shared/session-options.ts` (open). Its type-only import of
  `contracts/runtime.ts` brings eight type contracts: `runtime`, `login`,
  `install`, `inventory`, `update`, `list-models`, `brand` and
  `provider-auth`. All are `import type`, so the esbuild metafile for the
  client and adapters entries gains no module from them.
- `shared/input-images.ts` (session), for the restored image gates. It imports
  `node:fs`, `node:path` and contract types only. It is the one new module in
  the metafile.

The inventory is now 55 source files and LICENSE. Fifty source files keep
upstream bytes. Five are maintained: `app-server-client.ts`, `open.ts`,
`rpc-control.ts`, `session.ts` and `session-kernel.ts`. No npm dependency
enters the closure.

Three maintained files take an upstream change:

- `open.ts`: take the `checkSessionName` refusal in `codexThreadOpen` and the
  new `codexThreadName`. A new thread gets the given name. A resumed thread
  gets it only when the resume reply shows no name. The merge was clean.
  `open.ts` stays maintained only for the caller-owned approval policy.
- `rpc-control.ts`: take `resumeError`. A -32600 resume refusal is still a
  `SessionNotFoundError` for a missing rollout. It is now a
  `SessionUnavailableError` for an archived thread (`archived`) or one with
  another active writer (`in_use`). `openThread` accepts `thread/name/set`,
  and `nameThread` sends it. The BYOK timeout and synchronous response capture
  stay. The merge was clean.
- `session.ts`: take the `nameThread` call after the resume effort check. The
  three-way merge had one conflict, in the imports. Upstream changes the
  `./open.js` import next to the app-server-client import, where BYOK adds
  `type SpawnLineProcess`. The merged block keeps that type and adds only
  `codexThreadName`.

## Deltas returned to upstream

The owner's directive is to follow upstream and keep only deltas that SDK
ownership requires. Three deltas go:

- The client and bridge typecheck library rises from ES2022 to ES2024
  (`packages/client/tsconfig.json`, `scripts/api-surface/tsconfig.oar-bridge.json`).
  The emit target stays ES2022 and cloud-do stays on ES2022. The Node 24
  engine floor provides `toSorted` and `Promise.withResolvers`.
  `shared/credential-redactor.ts` now keeps upstream bytes, and `session.ts`
  takes the upstream `Promise.withResolvers` for the resume effort report. All
  221 emitted client declaration files are byte-identical before and after,
  and the API goldens match.
- `session.ts` takes the upstream image gates again: `inputImagesRefusal` on
  prompt, steer and queue. The bridge passes text only, so the gate sees no
  images and returns null.
- `shared/session-options.ts` keeps upstream bytes instead of a trimmed copy.

PROVENANCE.md now opens with the five remaining deltas, each with its
invariant, and keeps the earlier steps as history.

`app-server-client.ts` and `session-kernel.ts` have no upstream change. Only
their change notices name the new base. The source
manifest records both upstream and maintained SHA256 values, and the `delta`
text of each maintained file states its current delta.

The JS bridges, their declaration checks, tests, the real Codex smoke script
and the build provenance copy use the new directory. The ADR, third-party
attribution and the current Codex source contract in the spec identify 0.59.1.
The 0.57 upgrade note and the changelog keep their historical source version.
The historical 0.24 release provenance link points to the retained history in
the new vendor directory.

## Behavior

The SDK behavior does not change. The SDK Codex adapter never passes `name`,
and the private bridge declaration does not expose it. Without a name,
`codexThreadName` returns null and `nameThread` sends no request. The bridge
passes text-only prompt and steer, so the restored image gates return null.
Codex open, turn and queue requests from the SDK are unchanged.

A resume that codex refuses as archived or held by another writer now throws
`SessionUnavailableError` instead of a plain `Error`. Its message and cause are
the same. The bridge re-exports only `SessionNotFoundError`, and the SDK Codex
adapter tests only that class. So such a resume still fails as a retryable
infrastructure start failure with the same reason text.

The adapter bundle gains `shared/input-images.ts`, whose `node:fs` calls run
only when an input carries images.

Upstream 0.58.0 to 0.59.1 also adds `ListModelsOptions.cwd`, a Pi theme fix
and session names for Claude and Pi. These modules are outside the selected
closure.

# OAR 0.62.1 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.59.1`, commit
`bb98cbc1e383ea7192da0c87ce777d799669a7a9`, with tag `v0.62.1`, commit
`bf55fd68f19749cab8ed2d5a234238af7adbd4b0`. v0.62.1 is the latest release. The
directory moves from `vendor/oar/bb98cbc` to `vendor/oar/bf55fd6`. Package
manifests and the Bun lockfile need no change.

## Source and maintained boundaries

No selected path changed upstream. All 55 selected source files and LICENSE
have the same upstream bytes at both commits. Every manifest `upstreamSha256`
matches the file at `v0.62.1`. The import closure does not change, and no new
file enters the inventory.

The five maintained files keep their BYOK deltas: `app-server-client.ts`,
`open.ts`, `rpc-control.ts`, `session.ts` and `session-kernel.ts`. Only their
change notices name the new base, so only their `vendoredSha256` values change.

The JS bridges, their declaration checks, tests, the real Codex smoke script
and the build provenance copy use the new directory. The ADR, third-party
attribution and the current Codex source contract in the spec identify 0.62.1.
PROVENANCE.md records the step in its history. The historical 0.24 release
provenance link points to the retained history in the new vendor directory.

## Behavior

The SDK behavior does not change. The vendored code is the same except for the
change-notice comments.

Upstream 0.60.0 to 0.62.1 changes the MCP tool server (`mcp/http.ts`,
`mcp/serve-tools.ts`), Claude context usage and projection, and the Grok, Pi
and Pi Durable runtimes. These modules are outside the selected closure.

## Validation

All commands ran with `TMPDIR=/tmp/oar062`, after
`bun install --frozen-lockfile`.

- A script compared each of the 56 manifest entries with `git show
  v0.62.1:<sourcePath>`. No `upstreamSha256` differs. The files that keep
  upstream bytes are byte-identical to v0.62.1. Five files are maintained.
- `git diff --quiet bb98cbc v0.62.1` reports no change for any selected
  `sourcePath`.
- Client OAR app-server client, Codex session, Codex events, owned line process
  and process-tree tests: 5 files, 89 tests passed.
- The built `dist/assets/provenance/oar/bf55fd6/` LICENSE, PROVENANCE.md and
  source-manifest.json match their source files.
- `bun run build`, `bun run typecheck`, `bun run test`,
  `bun run check:api-surface` (9 goldens match),
  `bun run check:version-authority` and `bun run test:scripts` (including the
  OAR JS/declaration bridge checks): passed.
- `bun run smoke:codex-app-server` needs `BYOK_REAL_CODEX=1`, Codex
  authentication and provider turns. It did not run.

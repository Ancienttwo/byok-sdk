# Pi 1.3.0 and OAR 0.67.0 upgrade

The owner asked on 2026-10-18 whether the latest OAR supports Pi 1.3, and to
upgrade both if it does. OAR v0.67.0 (2026-10-17, commit
`c264f17040dd9513b43300886a80f3f6eddde7b1`) pins `pi-ai`, `pi-coding-agent`,
`pi-durable` and `chord` at 1.3.0. Its `packages/oar` peers are `^1.3.0` and
`~1.3.0`.

## Pi pins

All nine official packages move from 1.2.0 to exactly 1.3.0 (upstream commit
`71023aec1546d6d677a65669c5665c0927ce0dd0`). The root, client and cloud-do
manifests change together. `piRuntimePin` is 1.3.0.

- `bun.lock` resolves one instance of each of the nine packages, all 1.3.0.
  There is one `pi-ai` copy, as the OAR 0.67.0 host note requires.
- `collect-official-pi-closure.mjs` verified the registry signature, the
  Sigstore provenance and the tarball integrity of all nine packages. The new
  closureDigest is
  `7950a1f4a0e34241c861ca5d9ba566ad3255ed493b8b5c17c39f32587962bede`.
- Upstream now pins its internal dependencies exactly. The closure keeps the
  same nine package names.
- Export assets: only `template.js` changed (80260 to 80492 bytes).
- The provider env list from pi-ai 1.3.0 is unchanged. Only the generated
  header names the new version.
- The todo build input `pi-ai/dist/utils/typebox-helpers.js` keeps the same
  bytes. `build-todo-assets.mjs --refresh-official-pi` updated its version.

## API review

The review compared the `.d.ts` files of 1.2.0 and 1.3.0 for all nine
packages, and then the changed JS where the SDK depends on behavior.
pi-agent-core, pi-mcp, pi-tui and pi-telemetry have no declaration or JS
change. chord renames records to objects, handles to refs and epochs to code
versions; the SDK uses only `BACKGROUND_CONTEXT`, `Context` and `JsonValue`,
which do not change.

### Resumed sessions drop new extension tools (fixed)

Pi 1.3.0 restores the transcript's active tools when a default-tools session
resumes (`agent-session.js`: the condition moves from
`_initialActiveToolNames === undefined` to `_usesDefaultTools`). In 1.2.0,
`createAgentSession` always set `initialActiveToolNames`, so the restore never
ran. The SDK MCP extension registers host toolset tools at load time. On
1.3.0, a tool that the resumed transcript did not declare therefore stayed
inactive.

A probe confirmed this. The previous transcript declared the four default
tools and `mcp_A`. The extension of the new open registered `mcp_A` and
`mcp_B`.

| Pi | Active tools after resume |
|---|---|
| 1.2.0 | `bash, edit, mcp_A, mcp_B, read, write` |
| 1.3.0 | `bash, edit, mcp_A, read, write` |

`resetResumedPiTools` (`src/bin/pi-session-runtime.ts`) applies the OAR 0.67.0
fix (#416). Before `session_start`, it sets the current native default tools
and the default-active extension tools. Pi still applies `excludeTools` and
exposure rules. The RPC host calls it when no `tools` or `noTools` option is
given; the team operator host passes `noTools` and is unchanged. The subagent
print host calls it too, because it can open an existing session file. A new
session is unchanged. `pi-resumed-tools.test.ts` covers the three cases; with
a no-op helper, two of them fail.

### Other changes

- `resolveCliModel` now reports a bare model id that more than one provider
  offers as `ambiguous`, instead of picking by catalog order. It also takes an
  optional `inlineApiKey`. The keys-profile lane always passes `--provider`,
  so it cannot be ambiguous. A device-auth launch or a subagent child that
  gives a bare id can now fail with the upstream message; it names the
  candidates.
- `parseModelPattern` is removed and `findExactModelReferenceMatch` takes a
  readonly array. The SDK uses neither.
- pi-ai no longer has `dist/utils/assistant-message-frame.js`, and its root no
  longer exports it. The SDK did not use it. The compile closure of the
  prepared lane lists one file less.
- A tool call whose arguments are not valid JSON now carries
  `argumentsError` and fails validation. Before, it ran with the fields
  parsed so far.
- The `kimi-coding` built-in moves to OpenAI Chat Completions at
  `https://api.kimi.com/coding/v1`. Keys projections use their own provider
  ids (`byok-sdk-<profileRef>`) with an explicit `api` and `baseUrl`, so the
  built-in change does not reach them. The keys catalog still lists the Kimi
  Anthropic endpoint, which upstream did not remove.
- pi-durable adds an optional SQLite table prefix. Without a prefix, the
  table and index names do not change. A probe created a store with 1.2.0 and
  opened it with 1.3.0: the schema stayed at version 1 and did not change. A
  new 1.3.0 store has the same names and the same SQL apart from whitespace.
  The Durable Object adapter now shares one operation queue per storage
  object.
- pi-durable rebuilds the model context so that only the baseline system
  message moves to the front after a compaction. pi-codemode limits live
  workers to two across sessions. The SDK has no code that depends on the old
  behavior.

## OAR source

The vendored source moves from v0.66.0 (`vendor/oar/beea52c`) to v0.67.0
(`vendor/oar/c264f17`). Of the 55 selected source files and LICENSE, only
`contracts/records.ts` changed upstream: one JSDoc comment on
`tool_call_ended.exitCode`. It keeps the upstream bytes. The five maintained
files keep their deltas; only their change notices name the new base. Every
`upstreamSha256` in the manifest matches `git show v0.67.0:<sourcePath>`.

OAR 0.66.1 fixes Windows npm and pnpm `.cmd` shim launches in its executable
manager. The SDK does not vendor that module. The SDK has no cross-spawn,
`shell: true` or `.cmd` rewriting, so it has no path of the same class.

## Tests that change

- `pack-and-smoke.test.mjs`: the identity authority admits only the pinned
  official version, and the repo pin test reads the real manifest and lock.
  Their pinned version and the coding-agent integrity move to 1.3.0, as in the
  1.1.0 and 1.2.0 upgrades. The synthetic installed-closure test is unchanged.
- `pi-host-payload.test.ts`: the installed version is 1.3.0.
- `pi-input-preparation.test.ts`: the upstream commit is the 1.3.0 commit, and
  the exact compile closure no longer lists the deleted
  `utils/assistant-message-frame.js`.
- `pi-runtime-identity-indirect.test.ts`: the synthetic indirect version must
  be newer than the pin, so it moves from 1.3.0 to 1.4.0.
- OAR tests and bridges import from the new vendor directory.
- `api-surface/entries.json`: an existing `opaque import()` in the two Pi
  runtime host bundles moves up seven lines. No public surface changes.

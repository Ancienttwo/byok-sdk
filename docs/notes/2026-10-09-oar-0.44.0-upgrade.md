# OAR 0.44.0 source upgrade

Rule, as for 0.37.0: follow OAR. Take the upstream bytes. Keep only the BYOK
deltas the manifest names.

## P1 boundary

OAR is private source in the client package. It is not an npm dependency.
The old base is tag `v0.37.0` at `0be506ff7ee86f315dafda0c2d48de1a6cac5d62`.
The new base is tag `v0.44.0` at `98be973dea8e7f745507ab4039059f9bac6c2ee4`.
The vendor directory moves from `vendor/oar/0be506f` to `vendor/oar/98be973`.
The selected inventory now has 35 TypeScript files and LICENSE.

Eleven selected paths changed upstream: `contracts/records.ts`,
`contracts/session-options.ts`, `contracts/session.ts`,
`runtimes/codex/app-server-client.ts`, `runtimes/codex/open.ts`,
`runtimes/codex/projection.ts`, `runtimes/codex/rpc-control.ts`,
`runtimes/codex/session.ts`, `shared/mcp-servers.ts` and
`shared/session-kernel.ts`. Seven new files enter the import closure:
`contracts/failure.ts`, `contracts/errors.ts`, `shared/control-input.ts`,
`shared/failure-class.ts`, `runtimes/codex/failure.ts`,
`runtimes/codex/input-delivery.ts` and `runtimes/codex/tool-denials.ts`.
`shared/environment.ts` is imported only by the upstream client line that
BYOK does not take, so it is not vendored. The other omissions are the same
as before.

`createSessionKernel` has one production user, the vendored Codex session.
So the new empty-input refusal reaches only Codex.

## P2 runtime path

`CodexAdapter.prompt()` and `steer()` call the raw session through the JS
bridge. The bridge passes the text only: no `inputId`, no images, no
`disallowedTools`.

- Prompt `""`: `rpcControl` records the request, then `emptyInputRefusal`
  answers `rejected` / `unsupported` before the gate and before any write.
  The adapter maps a non-accepted prompt to an infrastructure error. The
  protocol allows an empty string instruction, so such a Codex task now fails
  to start. Before, the SDK sent a `text` item with empty text to codex.
- Steer: the plan reads `expectedTurnId` when it is built, as upstream does.
  The steer acceptance record runs only with an `inputId`. The bridge sends
  none, so BYOK steers create no `input_dropped` event.
- Turn end: `projection.ts` now classifies a failed turn from
  `turn.error.codexErrorInfo`. The adapter reads only frames with
  `origin=byok-native`, so the derived class does not reach BYOK events.
- Open: `prepareCodexToolDenials` sends `config/read` only when
  `disallowedTools` is not empty. The bridge never sets it.

## P3 decision

- Upstream bytes: the three changed contracts and the seven new files.
- `projection.ts` drops its BYOK delta and keeps upstream bytes. The delta
  existed to stop prose classification. Upstream now classifies from the
  structured `codexErrorInfo`. A status word without `turn.error` is still
  `unknown`. The existing test "keeps raw failed-turn reason without
  classifying it" still passes unchanged.
- `git merge-file` merged the six other maintained files:
  - `open.ts`, `rpc-control.ts`, `session-kernel.ts`, `mcp-servers.ts`: the
    conflicts are the change-notice line next to a new upstream import, plus
    the ES2022 `sort` line in `mcp-servers.ts`, which takes the upstream
    string check.
  - `app-server-client.ts` (3 hunks): keep the BYOK injected spawn and the
    explicit `Record<string, string>` environment. Do not take
    `sessionEnvironment`: the caller passes the complete filtered
    environment, and the BYOK rule is no ambient merge. Omit `resources`,
    because the owned LineProcess has no resources reader.
  - `session.ts` (5 hunks): keep the BYOK signature, kernel hooks and raw
    session object. Narrow `options.env` to `Record<string, string>`, so a
    null removal cannot enter the explicit environment. Take the upstream
    steer plan with the BYOK `null` image gate. Omit `resources`.
- `AdapterSession.resources` is optional upstream. The bridge type check
  names `resources` as an intentional omission. Adding it needs a reader on
  the owned transport (`src/adapters/process-tree.ts` already reads the
  table) and its own decision.
- The change notices in the six maintained files name `98be973`.

## Behavior changes

- Codex prompt, steer or queue with empty text and no images: `rejected`,
  code `unsupported`, reason `empty input: give text or images`. No RPC.
- Raw Codex session records: a failed turn carries the structured failure
  class, and the HTTP status where codex gives one. An accepted steer with
  an `inputId` that an interrupt drops before codex echoes it gives an
  `input_dropped` event.
- `redactError` also redacts every error down the `cause` chain.
- `CodexAdapter` events do not change for non-empty input.

## Assertion review

One assertion changes. `oar-app-server-client.test.ts` pins the list of
maintained files. `runtimes/codex/projection.ts` leaves the list, because it
now keeps upstream bytes. The test title says six, not seven. Other tests
change only import paths and the manifest root.

New tests in `oar-codex-session.test.ts`:

- A failed turn is classified from `codexErrorInfo`: a named value
  (`usageLimitExceeded` → `quota`) and a transport variant with an HTTP
  status (429 → `rate_limited`, `status: 429`).
- An empty prompt and an empty steer are rejected `unsupported`, and no RPC
  is written for them.
- Of two accepted steers, the one codex did not echo before an interrupted
  `turn/completed` is reported as `input_dropped`.

# OAR 0.66.0 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.62.1`, commit
`bf55fd68f19749cab8ed2d5a234238af7adbd4b0`, with tag `v0.66.0`, commit
`beea52cef61391351234edc025a481875035e68c`. v0.66.0 is the latest release. The
directory moves from `vendor/oar/bf55fd6` to `vendor/oar/beea52c`. Package
manifests and the Bun lockfile need no change.

## Source and maintained boundaries

Five selected paths changed upstream:

- `contracts/runtime.ts`
- `contracts/session-options.ts`
- `runtimes/codex/tool-denials.ts`
- `shared/mcp-servers.ts`
- `shared/session-options.ts`

None of them is a maintained file. All five take the v0.66.0 bytes. The other
50 selected source files and LICENSE have the same upstream bytes at both
commits. The new imports (`RESERVED_MCP_SERVER_NAMES` and `hasMcpCredentials`
from `shared/mcp-servers.ts`) point to a file that is already in the inventory.
The import closure does not change, and no new file enters the inventory.

The five maintained files keep their BYOK deltas: `app-server-client.ts`,
`open.ts`, `rpc-control.ts`, `session.ts` and `session-kernel.ts`. Upstream did
not change them. Only their change notices name the new base, so only their
`vendoredSha256` values change.

The JS bridges, their declaration checks, tests, the real Codex smoke script
and the build provenance copy use the new directory. The ADR, third-party
attribution and the current Codex source contract in the spec identify 0.66.0.
PROVENANCE.md records the step in its history.

## Behavior

`open.ts` calls `checkMcpServerNames`. From 0.64.0, that check refuses the
server names `__proto__`, `__defineGetter__`, `__defineSetter__`,
`__lookupGetter__` and `__lookupSetter__` with an `UnsupportedOptionError` on
`mcpServers`. A Codex session open with such a name now fails before spawn. The
SDK Codex adapter builds its server list from `Object.entries` of a record, so
such a name occurs only from a record with an own `__proto__` key. A new test
in `oar-codex-session.test.ts` covers this refusal.

`tool-denials.ts` refuses a `disallowedTools` entry for a reserved server name.
The SDK Codex adapter does not pass `disallowedTools`, so this does not reach
SDK sessions.

`shared/session-options.ts` and `contracts/runtime.ts` add the
`mcpServerCredentials` refusal key and the `McpToolsListChanged` type. The Codex
fork does not call `refuseSessionOptions`, so this does not change SDK behavior.

Upstream 0.63.0 to 0.66.0 also changes the antigravity runtime, `serveMcpTools`
and its HTTP server, and adds per-runtime package entries with lazy ACP
loading. These modules are outside the selected closure.

## Validation

All commands ran with `TMPDIR=/tmp/oar066`, after
`bun install --frozen-lockfile`.

- A script compared each of the 56 manifest entries with `git show
  v0.66.0:<sourcePath>`. Every `upstreamSha256` matches. Fifty-one entries are
  byte-identical to v0.66.0. Five files are maintained.
- `git diff --stat v0.62.1 v0.66.0` over the selected `sourcePath` values
  reports the five files above and no other file.
- `bun run build`, `bun run typecheck`, `bun run check:api-surface` (9
  goldens match) and `bun run check:version-authority`: passed.
- The built `dist/assets/provenance/oar/beea52c/` LICENSE, PROVENANCE.md and
  source-manifest.json match their source files.
- Client OAR app-server client, Codex session (with the new reserved-name
  test), Codex events and owned line process tests, with the Codex adapter
  test: passed.
- The first `bun run test` had 62 failures in 26 client files, mostly
  `Test timed out` under load. A rerun of those files and the OAR tests had 5
  failures in 5 files. A second rerun of those 5 files passed (140 tests). On
  `origin/main` the same 5 files also had 1 timing failure, in
  `admission-deadline.test.ts`.
- The first `bun run test:scripts` failed one check: "long-path IPC fixtures
  leave no fixed-root scratch directories". It ran after the loaded test run.
  A rerun passed (105 tests). It also passed on `origin/main`.
- `bun run smoke:codex-app-server` needs `BYOK_REAL_CODEX=1`, Codex
  authentication and provider turns. It did not run.

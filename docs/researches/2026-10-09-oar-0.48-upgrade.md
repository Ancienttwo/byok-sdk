# OAR 0.48.0 source upgrade

The client vendors OAR source rather than depending on its npm package. This
upgrade replaces tag `v0.45.1`, commit
`7dc98e08f9c0ba99158ddada29cb0d4c80ef7dc6`, with tag `v0.48.0`, commit
`087df160dd64cd020c98a8b089ce8feb01f73590`. No 0.48 patch tag exists, so
v0.48.0 is the latest 0.48.x release. The directory moves from
`vendor/oar/7dc98e0` to `vendor/oar/087df16`. Package manifests and the Bun
lockfile need no change.

## Source and maintained boundaries

All 35 selected source files and LICENSE were compared against both upstream
commits. Five paths changed upstream: `contracts/records.ts`,
`contracts/session.ts`, `contracts/tool-output.ts`,
`runtimes/codex/projection.ts` and `shared/session-kernel.ts`. The other 30
source files and LICENSE retain the same upstream bytes.

`contracts/session.ts` now imports `contracts/context-breakdown.ts`. That file
enters the inventory with upstream bytes. It has no imports. The inventory is
now 36 source files and LICENSE. No npm dependency enters the closure.
Upstream 0.48.0 adds optional `@earendil-works/pi-durable` and
`@earendil-works/chord` peers for its own Pi Durable runtime. No selected file
imports them.

Thirty source files retain upstream bytes. The six maintained files keep their
BYOK deltas. Each change notice names the new base, and the source manifest
records both upstream and maintained SHA256 values.

Only one maintained file changed upstream:

- `session-kernel.ts`: take the upstream `globalThis.crypto.randomUUID` and
  drop the `node:crypto` import. Keep the fatal byte budget, the `hooks`
  parameter and the required consumer. The three-way merge had one conflict,
  on the `createSessionKernel` signature.

`app-server-client.ts`, `open.ts`, `rpc-control.ts`, `session.ts` and
`mcp-servers.ts` have no upstream change. Only their change-notice line
differs from the prior vendored bytes.

The JS bridges, their declaration checks, tests, real Codex smoke script and
build provenance copy all use the new directory. The spec, changelog, ADR and
third-party attribution identify 0.48.0. The 0.25.0 release notes and the
0.45.1 upgrade note keep their historical source version. The historical 0.24
release provenance link now points to the retained history in the new vendor
directory.

## Behavior

The derived Codex fold changes in three places:

- `turn/started` gives a `turn_active` reading.
- `item/commandExecution/outputDelta` gives `tool_call_progress.outputDelta`.
  The chunk no longer appears as `output`.
- `serverRequest/resolved` gives `app_request_cancelled` with the string
  request id.

Upstream assumes that OAR answers no Codex request. This fork answers server
requests. So the derived fold also reads a `serverRequest/resolved` that
follows a BYOK reply as `app_request_cancelled`. Derived frames do not reach
SDK events. The BYOK event projection and the native interaction bridge read
the native frames only. The native bridge withdraws a request on
`serverRequest/resolved` only while that request is still pending.

The generic Session contract adds an optional `contextBreakdown()` member.
Upstream implements it for Claude only. The raw Codex session has no such
member. The declaration bridge check names it as an intentional omission,
like `resources`.

Upstream Pi Durable, OpenCode v2, installer plans, the Claude context reader
and the observe changes remain outside the selected closure. Ordinary SDK task
launch behavior and SDK events stay the same.

## Validation

- Targeted OAR session, app-server client, native event projection and owned
  process tests: 4 files, 63 tests passed. New cases cover the native frame
  order and the derived `turn_active`, `outputDelta` and
  `app_request_cancelled` readings.
- Final validation ran in an isolated worktree based on main commit
  `4c3078a7`, with Bun 1.4.2 and Node 26.10.0.
- `bun ci`, `bun run build`, `bun run typecheck`,
  `bun run check:api-surface` and `bun run check:version-authority`: passed.
- `BYOK_TEST_BUN_BIN="$(command -v bun)" BYOK_REQUIRE_BUN=1 bun run test`:
  passed. The workspace Vitest suites passed 7,355 cases and skipped 160
  according to their environment gates; the cloud-do Node suite passed 15
  more cases. Two earlier runs on a heavily loaded host each failed on
  timing-sensitive tests outside the OAR closure: one 10 s timeout in
  `pi-export-assets.test.ts`, and two count checks in cloud-do
  `wake-inbox.test.ts`. Each file passed when run alone, and the third full
  run passed.
- `bun run test:scripts`: 68 tests passed, including the OAR JS/declaration
  bridge checks. The declaration check now names `contextBreakdown` as an
  intentional omission.
- Every upstream/vendor manifest SHA256 was checked against the pinned
  upstream commit, and built provenance assets match their source files.

Local check logs are in ignored `_ops/oar-0.48/checks/`. Live Codex provider
sessions and optional Docker dataplane suites are outside this validation.

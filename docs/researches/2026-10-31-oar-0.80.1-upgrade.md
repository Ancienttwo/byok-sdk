# OAR 0.80.1 selected-source upgrade

## Scope and trace

Replace OAR 0.75.0 (`51b83c96811735b3a9f045ab20bab7cd20e61cdf`) with the
upstream v0.80.1 tag (`044633e9be0dfbae6d171591ef03ea31593e9fb5`). OAR remains
selected SDK-owned source, not an npm dependency. Pi stays 1.4.0.

The vendor directory moves from `packages/client/vendor/oar/51b83c9/` to
`packages/client/vendor/oar/044633e/`. The selected closure grows from 86 to
92 source files plus LICENSE. Six upstream files enter the closure:
`contracts/control.ts`, `contracts/goal.ts`, `contracts/placement.ts`,
`runtimes/codex/goal.ts`, `shared/acp/initialize.ts` and `shared/acp/input.ts`.
Sixteen files carry BYOK changes; 76 keep upstream bytes. Every hash, the
maintained inventory and the license are recorded in `source-manifest.json`
and `PROVENANCE.md`.

## Decisions

- Adopt the ACP connection split. `shared/acp/initialize.ts` owns the
  handshake; `shared/acp/input.ts` owns draining EOF. `client-app.ts` gains
  the routed request target and wire-phase notification routing while the
  BYOK cancelled permission answer stays. `records.ts` passes the new
  wire-arrival phase through.
- Adopt the placement/release, goal and control contracts as types and the
  Codex `goal_changed` event projection. The SDK still exposes no placement
  selection, shared ACP session or goal control.
- Adopt exit reasons on the `exited` response, from the app-server client
  through the kernel and the event projection.
- Adopt the 0.80 process-table observation API. The source is maintained for
  one Node compatibility reason: `InvalidProcessTableError` declares its
  `reason` field explicitly instead of using a constructor parameter property,
  because the client test suite loads vendor TypeScript through Node 24's
  strip-only loader. The observation, parsing and kill behavior keeps upstream
  bytes.
- Keep the BYOK wrapper for `runtimes/codex/session.ts`. It still owns the
  injected spawn, explicit env, sandbox choice, redactor, native-first
  recording, caller-owned server-request lifecycle and open steps. Native goals
  are omitted from the signature and no goal tools are enabled. `openThread`
  no longer kills on failure upstream, so the session owns open-failure
  cleanup; it starts the kill without awaiting a quiescence promise that a
  failed owned-tree disposal cannot settle, leaving the adapter's close to
  report `RuntimeStartupDisposalFailure`.
- Keep the one-process `shared/acp/session.ts` wrapper. The upstream shared
  connection pool (`routing.ts`, `shared-session.ts`, `shared-wire.ts`) and
  lifecycle helpers are not vendored.
- Keep process diagnostics SDK-owned. `shared/acp/errors.ts` drops upstream's
  optional native diagnostic bundle and its executable-manager dependency.
- Do not vendor new runtimes or install/login helpers.

## Verification

Root build and typecheck exit 0. The dedicated client suite passes every file
after the maintained process-tree compatibility fix: 436 files, 5,563 tests
and 126 skips. A concurrent root `bun run test` was also attempted while the
host load average was above 6; its client leg timed out six files on worker
startup and fixture deadlines (the run took 23 minutes against the dedicated
run's 6.4). Those six files passed on rerun (201 tests, 1 skip), and every
non-client workspace passes under the root filter. Validation is therefore
composite coverage, not a claim that the first root invocation exited 0. The
private bridge check passes all five tests, including the exact vendor
declaration check. API surface matches
all nine public goldens and the entry-closure budgets are re-pinned to the

The local host had a stray `/private/tmp/package.json` declaring
`"type": "module"`. Extensionless CommonJS test fixtures created under `/tmp`
therefore loaded as ESM. It was moved aside for the run; this is host state,
not a repository change. No release, live-provider turn or Windows acceptance
was performed. Local logs are under ignored `_ops/oar-0.80.1-upgrade/`.

# OpenCode 2.3.0 qualification evidence (#1972, #1593)

Date: 2026-11-13 UTC. SDK subject: `9cc5d6f6a070810b5122e7bd087f06436e838c6b`. This records the runtime evidence for the version-policy change; the earlier 2.2.6 evidence remains in the [platform qualification note](2026-11-09-opencode-platform-qualification.md).

## Loopback runtime contract

On macOS 26.5 arm64 with Bun 1.4.3 and Node 24.18.0, the `@opencode/cli-darwin-arm64@2.3.0` executable from the npm tarball ran against the loopback provider. The qualified and latest modes each passed 8 tests with 12 capability-based skips. Both covered the Host MCP call and namespace removal on resume, project instructions, declared egress, same-session resume and different-cwd refusal, permission refusal, interruption of a running shell tool, and disposal.

```sh
BYOK_RUNTIME_CONTRACT=qualified BYOK_CONTRACT_OPENCODE2_BIN=<absolute-opencode-2.3.0-path> \
  bun run --filter @byok-sdk/client test:runtime-contract -- src/__tests__/runtime-contract/opencode2.contract.ts
BYOK_RUNTIME_CONTRACT=latest BYOK_CONTRACT_OPENCODE2_VERSION=2.3.0 BYOK_CONTRACT_OPENCODE2_BIN=<absolute-opencode-2.3.0-path> \
  bun run --filter @byok-sdk/client test:runtime-contract -- src/__tests__/runtime-contract/opencode2.contract.ts
```

The Windows x64 [CI job](https://github.com/Ancienttwo/byok-sdk/actions/runs/43417536058/job/131859254191) passed on the same subject. It installed the qualified 1.19.5 and 2.3.0 releases and ran `opencode1.contract.ts` and `opencode2.contract.ts` against the loopback provider, including the lifecycle and Host MCP cases. The macOS and Windows loopback results use no provider credential or paid call.

## Native free-model canary

On the same macOS arm64 host, the existing local #1593 observer drove the SDK adapter with the 2.3.0 executable and `opencode/deepseek-v4.1-flash-free`. On 2026-11-13 it observed matching native model readback, `OC_CANARY_OK` on the first turn, and `OC_RESUME_OK` after resuming the same native session. After the first completion, there were zero new runtime processes, live owned roots, or `serve --service` processes. A resume from a different workspace was refused with `phase: 'start'`, `retry: 'non-retryable'`, and a reason saying the session lives in the original workspace and resumes only there.

The prior observer checked `category: 'authority'`, which #1758 removed in commit `fc5c5d924`. For this run only, its local assertion was updated to check the current phase, retry and reason; the observer was not committed. The native permission prompt did not produce a permission request, so native permission refusal is **not demonstrated**. To observe the remaining gates, the local observer continued after recording that failure: immediate cancellation and repeated disposal left zero new runtime processes, live owned roots and services. Because cancellation was immediate, this does not establish that a shell tool had started. The observer's overall result was unqualified due to the missing native permission observation. The loopback contract separately proves permission refusal, cancellation of a running tool and disposal on both platforms.

The canary used SDK-owned scratch and closed its sessions; it did not observe the deferred 24-hour scratch sweep. Native OpenCode session files are outside SDK cleanup scope. The canary did not provoke a pre-output rate-limit fallback.

## 一分钟判定

salesko-new 若同时满足：① runtime 只用 bundled `ClaudeAdapter`（没写过自定义 `RuntimeAdapter`）；② hosted 部署没有直接 import `@byok-sdk/cloud-postgres`——则升级 = 改版本号 + 跑 migration，零代码迁移。broker（`@byok-sdk/example-salesko-connector-broker`）只依赖 `@byok-sdk/keys`（维持 0.1.0）与 zod，本版无感。

## Breaking 面（两条，均有守卫）

### 1. `RuntimeAdapter` 契约原子更替（自定义 adapter 才受影响）

- direct-start 权限移除：adapter 现在提供 frozen descriptor + per-offer 无副作用 `prepare` + prepared operation + 无凭证 immutable operation manifest。
- **没有迁移坡道**：无 0.3 alias、无 overload、无可选 prepare 钩子、无 direct-start fallback。自定义 adapter 一次改到位，TS 会在改到位之前拒绝编译。
- bundled Pi/Claude/Codex 已随包迁移完；protocol-v1 wire 字节与 runtime id（`pi | claude | codex`）不变，设备侧无感知。
- 连带行为变化：Pi/Claude/Codex 的语义准入（unsupported selection / policy / instruction / launcher / toolset / session intent）前移到 `task.claim` **之前**——不支持的任务意图现在 decline 时**不产生** workspace/进程/session 副作用。若 salesko 有依赖「claim 后再失败」的 UI 分支，检查 decline 路径的展示。
- `Session.close()` 变为 typed、有界的 quiescent-disposal receipt；bundled adapter 负责终止整棵进程树。若 salesko 侧有手动 kill 兜底逻辑，可以删掉，改为消费 close receipt 里的本地处置失败信息。

### 2. `@byok-sdk/cloud-postgres` → `@byok-sdk/cloud-dataplane`（hosted 部署才受影响）

- 包名与 umbrella namespace（`cloudPostgres` → `cloudDataplane`）同时改名，旧名不留 alias；≤0.3.0 的已发布版本继续可用，但新版本只发在新名下。
- migration 语义不变：host 拥有执行时机。tarball 现自带 `dist/sql`（0.4.0 共 6 个，与 byok 仓 `deploy/sql` 逐字节对齐，pack 侧有双向 content-addressed 校验）——2026-08-12 handoff 清单 #3 的 vendoring 负担（sha256 表 + 不可就地编辑注记）可以退役，直接用包内目录跑 `migrate(pool, dir)`。
- 0.4.0 含 `deploy/sql/0006_device_presence_toolsets.sql`：升级后 hosted presence 表需要这次 migration，否则 toolset inventory 面不生效。

## salesko 直接受益的新能力

1. **Toolset inventory 公布**：daemon 在 `conn.hello.configuredToolsets` 与 presence 心跳里公布已配置的逻辑 toolset id（如 `salesko.connectors`），hosted `listPresence()` 直接可见。仅逻辑 id、上限 64、不携带 command/args/env/secret。设备能力指示（Phase C pairing UX 一类）从此有第一方信号源；dispatch 权威仍在 daemon 本地 registry（presence 只做 discovery，不做 authority）。
2. **`readTaskResult()`**：`@byok-sdk/cloud` 新增 typed terminal 读模型——state/summary/sessionRef/artifactRefs/document/reason/retryable/recordedAt 一次拿全，替代手解 `readTerminalReceipt` 的 raw envelope（2026-08-12 handoff 清单 #2 的 hosted 收口）。语义：`undefined` = 尚无 terminal 事实；declined 任务无 receipt，查 `readTaskAttempt` 的 attempt status；`document` 缺失 = legacy daemon 或未配 extractor，key 不存在而非 null。
3. **Windows 加固**（若 salesko 有 Windows 设备端）：ownership-probe 断连不再中断 daemon 启动、adapter smoke 保留 Windows temp/system-tool 权限、进程树终止时 `taskkill` 失败降级为 close receipt 而非崩溃。

## 升级步骤（建议顺序）

1. `@byok-sdk/*` 依赖统一升 `0.4.0`（`@byok-sdk/keys` 保持 `0.1.0`）；hosted 侧依赖名 `cloud-postgres` → `cloud-dataplane`，import 与 namespace 同步改。
2. 跑包内 migration：`migrate(pool, <pkg>/dist/sql)`，确认 `0006_device_presence_toolsets` 应用成功。
3. 全量 e2e：重点跑 dispatch（requiredToolsets 拒绝面）、presence（inventory 可见且 fixture 命令串不泄露——byok 仓 `real-cloud-salesko-mcp-e2e.test.ts` 是参照实现）、terminal 读取（迁移到 `readTaskResult()`）。
4. 有自定义 adapter 的话，按契约文档重写为 prepare/manifest 形态；TS 编译器会列出全部缺口。

## 不变面（可以不重测的部分）

- protocol-v1 wire 字节、runtime id closed enum、`/byok/*` 路由常量。
- `@byok-sdk/keys` 0.1.0（broker 零改动）。
- 凭证隔离铁律、embedded server host-global operator 面。

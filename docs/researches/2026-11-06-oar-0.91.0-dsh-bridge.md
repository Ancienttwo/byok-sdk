# dsh native bridge probe (OAR 0.91.0)

## Scope

`runtimes/dsh` in OAR 0.91.0 replaces the ACP path with a private plugin bridge.
`dsh --profile acp` runs with the ACP plugin off and the bridge on, and the two
sides exchange JSON lines. Tracking issue: #1469.

Probes ran against real dsh 0.2.1-rc.5 on macOS with the bridge source from
`packages/client/vendor/oar/0e92470/runtimes/dsh/bridge.ts` and a loopback model
server that streams a scripted OpenAI-compatible response. `fake-dsh.mjs` copies
the frames recorded here. The qualified version is 0.2.2-rc.1, which the runtime
contract suite covers.

## Wire

Commands: `open`, `peek`, `resume`, `prompt`, `queue`, `steer`, `withdraw`,
`cancel`, `models`, `dispose`. Frames: `ready`, `startup-error`, `response` and
`native` on the channels `session/event`, `agent/assistant-stream`,
`agent/status`, `agent/error` and `subagent/*`.

## Tool input

`session/event` `tool/call` data is `{turn, step, callId, name, arguments}`, and
`arguments` is one complete JSON string.

| Input | Result |
| --- | --- |
| `bash` command of 12,027 characters | arrives whole; the parsed `command` has the same length |
| `write`, `read`, `edit` calls | structured objects; `classifyToolCall` returns a non-normal class |
| Model arguments that are not valid JSON | dsh rewrites them to `"{}"` and refuses the call |

The SDK projection parses `arguments` once and fails the session when the result
is not an object.

## Patch and model

- Two `--patch` files load together: the provider row, then the bridge overlay.
- A key named by `apiKeyEnv` reaches the provider as `Authorization: Bearer` and
  the patch holds no key.
- A custom `baseURL` route serves a root turn and a subagent turn without an
  `agent-default-model` row. In dsh that plugin is read only by
  `api-session-controller` and `headless`. The SDK patch drops the row.
- `TMPDIR` is honoured: dsh spill and subprocess directories land in execution
  scratch.

## Permissions

`approval/request` is a plugin waterfall whose default answer is `unavailable`.
The bridge registers no answerer. Outcomes with no client attached:

| Mode | Probe | Result |
| --- | --- | --- |
| `read-only` | bash writes outside the workspace | `exit=1`, `Operation not permitted`; turn completes |
| `read-only` | bash with `sandbox_permissions: workspace-write` | tool error `requires approval, but no approval channel is available`; `approval/asked` and `approval/decided` recorded; turn completes |
| `workspace-write` | bash writes to `/tmp` | `exit=0`; turn completes |

No mode hangs a turn on a pending approval.

## Turn order

Probed on real dsh 0.2.2-rc.1, at frame level and through `DshAdapter`. `subagent`
starts a background child and returns `started subagent <id>`, so the root turn
can end while the child runs.

When the child finishes, dsh opens a new root turn on its own, with no prompt.
Its input is `Background subagent <id> finished ...`, and the root model is called
again. The adapter emits that turn's `progress`, `usage` and `turn_end` like any
other, and the turn's model may call tools: a scripted `bash` call ran and
reached the Host as `tool_use` and `tool_result`.

| Moment of `followUp` | Result |
| --- | --- |
| Right after the first `turn_end`, child still running | accepted; the spontaneous turn still follows when the child ends |
| During the spontaneous turn | refused: non-retryable `infrastructure`, reason `busy` |

The native `turn/start` frame carries `cause` on a prompted turn and none on the
spontaneous turn.

Background `bash` jobs do the same: `run_in_background` returns `started
background job <id>`, and the job's end opens a root turn on `tool-jobs`
`completionDelivery: wakeup`. `goal-round-driver` also calls `agent.followup`.

## Ruling and resume

Per #1469 the session closes dsh and disposes the process tree at the root turn
end, then reports `turn_end`. The contract cases `dsh.turnEnd` and `dsh.resume`
run a turn that ends with a live subagent and a live job, then a second Turn of
the same session through resume. Both pids are gone at `turn_end`.

After the resume, on 0.2.2-rc.1:

- The model request carries the first turn's history, ending with `started
  subagent <id>` and `started background job <id>`, and no notice that either
  stopped.
- dsh does not restart the subagent: no child model request follows.
  `list_agents` reports it `[inactive]`.
- `job_list` reports `(no background jobs)`.
- `usage` covers the resumed turn only.

Not probed: `send_message` to the stopped child with its real id.

## Disabling background subagents

The `dsh-tool-subagent` and `dsh-subagent` READMEs document no option that turns
off background delegation or makes it foreground, and every call returns before
the child ends. `dsh-subagent` `maxDepth: 0` leaves both tools in the schema.
Disabling the rows `tool-subagent` and `tool-subagent-fork` in a patch does remove
them, but those are composition row ids rather than a documented option, and
`workflow`, `bash run_in_background` and goals would remain. The SDK patch is
unchanged.

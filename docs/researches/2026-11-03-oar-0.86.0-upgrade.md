# OAR 0.86.0 selected-source upgrade

## Scope and trace

Replace OAR 0.83.0 (`ddec7e575a5f8e65ea35011e64c0d35eef08f6bd`) with the
upstream v0.86.0 tag (`47c2c3f078b7706ec87b50ffc9c31040c116d7a7`). OAR remains
selected SDK-owned source, not an npm dependency. The owner asked on
2026-11-03 to move the dependency to 0.86; there is no issue.

The vendor directory moves from `packages/client/vendor/oar/ddec7e5/` to
`packages/client/vendor/oar/47c2c3f/`. Upstream changed eight of the 93
selected paths between the two tags (25 commits, +101/-44) and deleted none:
`contracts/records.ts`, `contracts/runtime.ts`, `contracts/session-options.ts`,
`contracts/session.ts`, `contracts/status.ts`, `runtimes/codex/open.ts`,
`runtimes/codex/session.ts` and `runtimes/grok/session.ts`. The last three
carry BYOK changes. Three new files enter the import closure with upstream
bytes: `contracts/compaction.ts`, `runtimes/codex/compaction.ts` and
`shared/manual-compaction.ts`. The closure grows to 95 source files plus
LICENSE: 79 keep upstream bytes and the same 16 carry BYOK changes. The
`@botiverse/oar@0.86.0` npm release, its SLSA provenance commit, the annotated
tag and all 96 upstream hashes agree (see `PROVENANCE.md`).

## Decisions

- Adopt the manual compaction in the vendored Codex session (upstream #610):
  the `compact` member and a compaction busy check on the steer, queue and
  abort gates. The three-way merge conflicted only where upstream reformatted
  lines next to BYOK seams, so the upstream hunks were applied by hand. Every
  BYOK seam stays: injected spawn, no goals, the raw AdapterSession, the
  `onRecord` observer registered first, server-request handling and the
  `beforeOpen`/`afterOpen` hooks. `compact` runs through the existing
  redaction guard, which also redacts its outcome, as upstream's credential
  seal does.
- Do not expose `compact` through the SDK bridge. The Codex and ACP member
  checks in `scripts/api-surface/oar-bridge-types.ts` name it as an
  intentional omission. Exposing manual compaction is a separate product
  decision.
- Follow upstream #606 in `runtimes/codex/open.ts`: a resume with
  `appendSystemPrompt` is no longer refused. The SDK Codex adapter never
  passes `appendSystemPrompt` (`codex-adapter.ts` session options), so its
  opens are unchanged. The `oar-0.80.test.ts` assertion of that refusal is
  removed with it.
- Take the new wording of the Grok append-only resume refusal. The refusal
  itself is unchanged.
- Leave out upstream additions that no selected file imports: the Grok shared
  session and sharing modules, ACP `routing-types` and `diagnostic-summary`,
  and `stream-json/compaction`.

## P1: ownership map

`AgentMessageOutbox` owns immutable drafts, session activation, consumer
dispositions and explicit local revoke facts. `AgentReliableSpool` owns reliable
event/exact-ACK facts. `CursorStore` and `ConnectionManager.advanceCursor` own
the inbound progress receipt. `TaskRunner` owns pending/active task identity,
context tokens, cancellation and terminal/disposal. The new `DurableJsonlFile`
shares file mechanics between both logs; it has no domain parser or extra ledger.

## P2: concrete faults and regression evidence

- R10: identity allocation -> append bytes -> sync/close error -> no memory commit
  -> blind retry appended a competing identity. Six real-file regressions for
  write/sync/close failed before the change because retry resolved. They now
  require quarantine, reopen, one exact identity and rejection of changed content.
  Successful short writes are completed; failed partial frames remain untouched
  and reopening explicitly rejects them. Reopen itself waits for successful sync.
- R11: `CursorStore.save` -> `atomicWriteFile` omitted fsync, so injected sync
  failure did not reject save. Both natural 512-entry compactors also omitted it.
  Regressions now delay/fail temp-file, target-file and POSIX directory barriers,
  ensure no successful receipt, quarantine failed compactors, and verify restart.
  A controlled Windows branch checks writable target flush; this is not a native
  Windows or physical power-loss simulation.
- R12: retained refused bodies counted against 64 messages / 4 MiB of sending
  quota. A regression with a one-message/five-byte budget now admits 65 consecutive
  refusals plus a legitimate message, including mid-run and final reopen. All
  bodies and exact refusal receipts remain auditable. Held remains charged.
- R13: token lookup -> append await -> activate await -> stale closure send.
  Three real-runner pre-fix races returned pending after cancellation. New guards
  cover both waits, startup activation, actual activation fsync in flight, and
  restart. Cancellation cannot emit its terminal before the local revoke is
  durable; revoked records cannot be replayed. A separate regression preserves
  ordinary failure/admission recovery after a send attempt.

## P3: bounded decisions and operational consequences

- An uncertain write poisons the existing serialized writer. Do not retry on that
  instance, infer absence from EIO, or suppress duplicate records. Reopen validates
  framing and domain identities, then flushes recovered bytes before returning.
  Fixed reliable event IDs are replay-idempotent only for the same immutable data.
  Partial/corrupt logs require explicit repair; their bytes are never auto-deleted.
- Cursor saves and compaction use the existing strongest platform-native durable
  replacement. Other caches are unchanged. Windows Node/libuv cannot fsync a
  directory, so writable file flush plus its existing rename path is the stated
  limit. No claim of physical power-loss proof is made.
- Local revoke is distinct from consumer refused. Cancellation and unsent teardown
  join the outbox mutation queue before terminal truth. Ordinary failure after a
  send attempt preserves the pre-existing message/admission recovery dependency.
- Refused/revoked evidence is excluded from sending quotas. Internal maintenance
  `archiveTerminalRecords(absoluteArchiveDirectory)` requires the existing single-
  writer Agent-home ownership: sync complete audit facts before durable live-log
  replacement. Archives are not another replay source and are never silently
  expired. An interrupted archive may leave an extra complete audit copy.
  No public maintenance CLI or public API was added. The 64 MiB live-log read
  ceiling and finite disk remain; operator retention must precede exhaustion.
- At 10x load, serialized disk barriers and audit retention dominate. This slice
  adds neither a business scheduler nor a second retry queue. Broad TaskRunner
  decomposition is outside scope.

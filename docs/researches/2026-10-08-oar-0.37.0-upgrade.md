## P2 runtime path

`CodexAdapter` calls the JS bridge, which exports the private `codexSession`.
The adapter injects the owned line process from
`packages/client/src/runtime/owned-line-process.ts`. That transport kills
through `src/adapters/process-tree.ts`.

Abort path: `CodexSession.interrupt()` calls `raw.abort()` and races it
against `interruptTimeoutMs` (default 1000 ms). `raw.abort()` now arms the OAR
abort fallback (10 s). With the default, the adapter deadline fails and closes
the session first. The close kills the app-server, and the exit clears the
fallback. So the adapter events do not change with the default.

Exit path: the owned transport calls the exit handlers only after `close`,
which comes after stdout ends, and after tree quiescence. No reply line can
follow the exit. The upstream client keeps pending entries after an exit for
late replies. BYOK has nothing to observe there, so the client keeps its
existing cleanup.

### Process tree (killTree)

Upstream now spawns the app-server with `killTree: true`. On POSIX, OAR
0.36.1 (6d1589d) reads the process table before SIGTERM and SIGKILL. It then
kills the descendants that left the runtime's process group, and their groups.

The BYOK owned spawn does not do this. `process-tree.ts` signals the POSIX
process group only. On Windows it uses `taskkill /T` and the kill-on-close
Job Object, which reach the whole tree. A probe confirmed the POSIX gap on
macOS. A runtime child spawned with `detached: true` (a new session) was alive
after `dispose()` resolved. A child in the runtime's group was gone.

So `killTree` is not mapped to a second mechanism here. The smallest fix is
in the one SDK authority, `src/adapters/process-tree.ts`. Read the
descendants (`ps -A -o pid=,ppid=,pgid=,lstart=`, or `/proc` on Linux) before
the SIGTERM and again before the SIGKILL. SIGKILL the descendants whose start
time still matches, and their groups, but never the host group. The host-exit
sweep does the same. OAR `shared/executable/process-tree.ts` is a direct
reference for that code. The fix changes disposal for every runtime, so it
needs its own decision.

Gap closed (follow-up commit). `shared/executable/process-tree.ts` is now
vendored with upstream bytes and called through the bridge
`src/runtime/oar-process-tree.js`. `src/adapters/process-tree.ts` stays the
one mechanism. On POSIX it reads the descendants before the SIGTERM and again
before the SIGKILL, SIGKILLs those whose start time still matches and their
groups, and never the host or its group. When the root stops on SIGTERM, the
descendants from the first read are killed after the group is gone. Disposal
then waits until they are gone. The host-exit sweep reads the table once and
does the same for each root still running. Windows is unchanged. `killTree`
maps to this mechanism. Not reached, as in OAR: a process that left the tree
before the first read, and one started after that read that outlives the
root. Also not reached: a host exit in the short window between the root's
exit and the disposal's final sweep.

Acceptance on 2026-10-08 (`2026-10-08-minimal-guardrails-acceptance.md`)
showed the first case with the real agents. Claude and Pi run each shell
command in a session of its own. For `cmd &` the shell exits at once, so the
background job is re-parented to init before any disposal read. It is not
below the root, and its dead shell's group is not signalled. The job survived
`close()` and `daemon.stop()`. The owner chose to document this limit and add
no new mechanism. Descendants still below the root at the read are reached,
including those that left the process group.

The same follow-up wraps the existing server-request deadline timer in
`session.ts` with the S2b guard, so a failed settlement there cannot throw
out of the timer.

`client.kill()` exists on the BYOK client. It fails pending work at once,
kills through the owned transport, and ignores later lines. Upstream kills and
settles pending work at the exit. For a control in flight, both record
`runtime_exited`.

## Behavior changes

- Raw Codex session: an unrefused interrupt with no turn end or exit within
  10 s is accepted, and the app-server is killed.
- A control in flight at an exit, a kill or a dispose records `rejected` with
  code `runtime_exited`. Before, it recorded `runtime_refused` (steer:
  `not_steerable: …`).
- An error reply settles with the redacted native error object.
- `CodexAdapter` with the default `interruptTimeoutMs` has no event change.

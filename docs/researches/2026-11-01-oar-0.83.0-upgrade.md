# OAR 0.83.0 selected-source upgrade

## Scope and trace

Replace OAR 0.80.1 (`044633e9be0dfbae6d171591ef03ea31593e9fb5`) with the
upstream v0.83.0 tag (`ddec7e575a5f8e65ea35011e64c0d35eef08f6bd`). OAR remains
selected SDK-owned source, not an npm dependency. Pi stays 1.4.0.

The vendor directory moves from `packages/client/vendor/oar/044633e/` to
`packages/client/vendor/oar/ddec7e5/`. Upstream changed five of the 93
selected paths between the two tags: `shared/acp/process.ts`,
`shared/acp/records.ts`, `shared/acp/session.ts`, `shared/acp/turns.ts` and
`shared/executable/process-tree.ts`. The closure stays 92 source files plus
LICENSE: 76 keep upstream bytes and the same 16 carry BYOK changes. The
`@botiverse/oar@0.83.0` npm release, its SLSA provenance commit, the annotated
tag and all 93 upstream hashes agree (see `PROVENANCE.md`).

## Decisions

- Adopt the Windows pid-reuse guard in `descendantsOf`: on Windows a parent
  edge counts only when the child started no earlier than the parent. The
  POSIX walk is unchanged. The bridge declaration gains the optional `source`
  argument, and the strip-only `reason` field delta stays.
- Adopt `shared/acp/records.ts` with upstream bytes. Its refusal of an
  unaccepted child attribution reads the `associations` callback, which only
  upstream's shared session pool passes. The vendored `acpSession` does not, so
  the bundled private ACP entry is byte-identical to 0.80.1.
- Do not vendor the ACP cancellation observation (upstream #571, #572, #577):
  `prepareShutdown`, `markNativeStop`, `observeCancellation`,
  `shared/executable/process-cancellation.ts`, and the dispose and abort calls
  that use them. They are backed by the upstream executable manager, which the
  fork does not vendor, and the injected line process has no such members.
  `process.ts`, `session.ts` and `turns.ts` mark the omission at their seams.
- Known gap left by that omission: on POSIX the SDK reads the agent's
  descendants just before it signals the tree at dispose. A tool that left the
  agent's process group and was orphaned by an earlier native user cancel is
  no longer below the agent at that read, so it can outlive the session. A
  Windows tree stays in its kill-on-close job object and is not affected.
  Tracked in [#1297](https://github.com/Ancienttwo/byok-sdk/issues/1297).

# OAR 0.75.0 selected-source upgrade

## Scope and trace

Replace OAR 0.71.0 (`c88a514458b3d80f18d32f29863f2b8fea5b1c96`)
with the upstream v0.75.0 tag (`51b83c96811735b3a9f045ab20bab7cd20e61cdf`).
OAR remains selected SDK-owned source, not an npm dependency. Pi stays 1.4.0.

CodexAdapter passes the SDK-owned process factory and explicit environment to
codexSession; codexThreadOpen constructs the native start/resume request.
The private ACP bridge opens Grok through the same caller-owned process and
terminal boundaries. Both sessions retain records in the upstream session kernel.
Runtime JS bridges, bridge declarations, CI scope pins, tests and build asset
copying now point to one replacement snapshot.

## Decisions

- Preserve all thirteen existing BYOK deltas, including approval policy,
  credential redaction, process disposal, record observation and failure provenance.
- Merge upstream Codex option refusals with the BYOK approvalPolicy signature.
  Explicit appendSystemPrompt on resume now refuses rather than sending an option
  Codex ignores. The SDK adapter does not supply this option.
- Keep ACP terminal spawning and disposal under the SDK process-tree owner;
  upstream direct platform-specific child-process management does not replace it.
- Import the new conversation/input-carry closure needed by the session kernel.
  Add one maintained delta in observe/events.ts: project current typed kernel
  records directly, without upstream pre-0.14 record translation. There is no
  historical raw-record ingestion at this boundary.
- Keep 86 source files plus LICENSE: 72 unchanged upstream, 14 maintained.
  The manifest records upstream and maintained SHA256 for every selected file.
- Upstream process-table reading adds Windows support. The private declaration
  includes its source selector; this upgrade does not claim Windows live acceptance.
- New auth/env/provider and interrupt-delivery contracts remain private upstream
  types. The SDK does not expose a new deliver or configuration-exclusion API.

The main cost is the conversation projection in the session-kernel closure.
Input-carry validation scans retained records only for prompts with nonempty carries;
the SDK's text-only bridge does not supply carries. At 10x retained history that
scan would grow linearly if a future bridge exposed it. Existing SDK record budgets
and deadlines remain authoritative.

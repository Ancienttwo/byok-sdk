# #605 A7: owner VM runbook and harness validation

This prepares the before/after experiment for [#605](https://github.com/Ancienttwo/byok-sdk/issues/605).
The scripts never power off a VM. The owner supplies a licensed, disposable Windows VM,
records its storage profile, authorizes the experiment, and cuts only that VM's power.
Windows intent B remains false. A successful process-kill run is **harness validation, not A7**.

The before revision is pinned to `04add5d414bbe6ed0301f1bded3c6a40cb76dfa0`, before W2-B.
The after revision is an explicit immutable commit from `feat/605-helper-protocol-4`
([L1 Draft #1650](https://github.com/Ancienttwo/byok-sdk/pull/1650)); pass its chosen head to `prepare`.
Both runs use the same VM image lineage, disk/controller/cache settings, seed and trigger schedule;
each starts with a fresh experiment store. Keep the before result even when it fails an invariant.

## What runs where

Run `scripts/agent-memory-a7/run.mjs` with Bun. It imports each selected checkout's existing W5
Host, real intent processor, helper backend and fault driver. The protocol-4 backend receives the
canonical store root. The Windows B override exists only inside the existing experiment backend.
No production admission flag changes.

The surviving Host keeps `evidence.jsonl` outside the guest, on storage that survives the cut.
Every issued intent, complete receipt and acknowledged notice is recorded before the Host answers.
Each row includes Host UTC time, sequence, the previous row's SHA-256 and its own SHA-256. The
complete receipt includes the operation digest and result revision/existence. This is an integrity
chain, not an authenticated signature. Preserve the original file and its final digest.

Each guest connection sends its commit, helper-manifest digest and OS version. The Host rejects
mismatches. Before recovery writes, the guest reads raw ledgers and hashes memory files after
Windows has mounted NTFS and replayed its log. The Host retains those snapshots. After the final
recovery it reopens every existing home through the real helper, releases each lease, and records
a separate cleanup snapshot. Pre-recovery temp files are observations; post-cleanup temp files fail.

The offline Node verifier calls the pinned before checkout's real strict parser and #998-correct
checker through a small Bun bridge. It independently recomputes I1–I5 from raw snapshots and the
Host journal, checks every issued intent is eventually acknowledged, and requires a complete
trigger/reboot schedule and final cleanup. It does not accept an after checkout's checker as its
acceptance authority.

- I1: strict ledger parse, only issued intents in their correct homes, only the last record applying.
- I2: each Host complete receipt has the identical durable terminal outcome.
- I3: each Host-observed acknowledgement has durable `ackedAt`.
- I4: memory existence **and** revision match states allowed by ledger order. A deleted file and an
  existing empty file differ, including the inverse empty-replace case from #996/#998.
- I5 additionally rejects a torn or unissued nonempty body. The existing experiment also records I6
  recovery results and fails on conflicting completion replay or unsettled recovery.

## Prepare exact revisions

Use a private test network. The guest TCP transport carries synthetic test data without TLS or
authentication; expose its listener only to the disposable guest. No credentials or user data belong
in either checkout or store. Install the repository's pinned Bun and Go toolchains on the build
machines. The verifier needs Node and Bun on PATH.

From a checkout that contains this harness:

```sh
git fetch origin main feat/605-helper-protocol-4
AFTER_SHA=$(git rev-parse origin/feat/605-helper-protocol-4)
bun scripts/agent-memory-a7/run.mjs prepare "$PWD" "$AFTER_SHA" /absolute/new/a7-revisions
node --test scripts/agent-memory-a7/verifier.test.mjs
```

`prepare` creates detached `before` and `after` worktrees, runs `bun ci`, `bun run build`, and
`build:agent-memory-helper` separately in each, and writes their resolved revision/manifest metadata.
It does not fetch, modify release pins, accept a licence or create a VM. A pin/build disagreement is
a failure to resolve before the run. The after helper assets must report protocol 4.

Prepare the same exact commits inside the guest, with their own dependencies, build outputs and
matching release helper assets. Copy this harness directory beside those checkouts. Keep experiment
checkouts clean: tracked modifications are rejected. Do not copy a protocol-3 helper into the after
checkout. Host and guest helper manifests must match. The Host can build all helper target assets
on its own OS with the repository build command.

## Run, cut, reboot, verify

1. On the surviving Host, run `bun scripts/agent-memory-a7/run.mjs run --config /absolute/before-host.json`.
2. In the disposable guest, run `bun C:/a7-harness/run.mjs device --config C:/before-guest.json`.
3. Wait for the Host's **A7 CUT READY** line. Hard power off only the named disposable VM using the
   owner-approved hypervisor action. Do not use guest shutdown, pause, suspend, checkpoint restore or
   a hypervisor graceful stop; those can flush storage or change the observed disk state. The harness
   contains no power-control commands. The owner is responsible for the cut's mechanism and timing.
4. Reboot that same disk and restart the guest device. The Host retains its process, journal and
   pending-intent state across every cut. A lost Host process makes the run incomplete: preserve the
   artifacts and start a fresh run, rather than appending or resuming an in-memory Host.
5. Repeat until all cuts and the final recovery/cleanup connection finish. The first six triggers
   stop at fetch/complete/acked boundaries; the remaining seeded delays can land inside writes.
   Manual reaction time affects delay windows: record the observed windows and actual hypervisor
   event timestamps, rather than claiming exact flush-instruction coverage.
6. Repeat the full sequence for after, on the identical recorded profile and fresh store. The result
   is evidence for owner review; it cannot itself enable Windows intent B or close #605.

On the surviving Host:

```sh
node scripts/agent-memory-a7/verify.mjs verify /absolute/new-before-run/evidence.jsonl /absolute/a7-revisions/before /absolute/before-result.json
node scripts/agent-memory-a7/verify.mjs verify /absolute/new-after-run/evidence.jsonl /absolute/a7-revisions/before /absolute/after-result.json
node scripts/agent-memory-a7/verify.mjs compare /absolute/before-result.json /absolute/after-result.json /absolute/comparison.json
```

A failing before result is useful experimental evidence and remains in the comparison. Nonzero exit
means a violation or incomplete run; retain the files and inspect `failures`, raw ledger bytes and
windows. Do not rerun over the same output directory. The result contract is
[`result.schema.json`](../../scripts/agent-memory-a7/result.schema.json). Archive both configs,
resolved commit metadata, full evidence files, results, hypervisor cut event records and the storage
profile. Owner acceptance must distinguish measured profile evidence from a general durability claim.

## Process-kill harness validation on win-ci

Use `hc exec --on win-ci` only. Stop if an Access popup appears; never accept it, use SSH, or create
a tunnel. Use a dedicated scratch directory and full tool paths or command-local PATH changes.
Go is at `C:/Users/win/byok-tools/go/bin/go.exe`. No machine/user PATH changes are needed.

The process-kill config has `mode: "process-kill"`, a fresh absolute `store` and `output`, and the
same required profile fields. Set `cutMechanism` to process tree kill, `dropsUnflushedWrites` to false,
and use actual `os.release()` for `osBuild`. `repo` must point to the exact clean before checkout.
It does not need `listen`, `port` or `ownerAuthorization`. Run it through `hc exec --on win-ci` with
Bun, then run the Node verifier against the same pinned before checkout. The existing W5 driver
kills the device/helper process tree and checks for survivors. This is explicitly **not A7**, even
when every invariant holds. Copy results to the local research record, then remove only the created
scratch and worktrees. Preserve any failure evidence before cleanup.

# OAR 0.91.0 selected-source upgrade

## Scope and trace

Replace OAR 0.88.0 (`be46fb3615a4de38e4004556c2b3a1a4860f72e6`) with the
upstream v0.91.0 release (`0e9247014498697ed4aaada8a911de68936ffec9`). OAR
remains selected SDK-owned source, not an npm dependency. Tracking issue: #1469.

`packages/client/vendor/oar/0e92470/`. Upstream changed 17 selected paths
between the two versions and deleted none. The closure gains
`runtimes/codex/messages.ts`, `runtimes/codex/task-control.ts` and
`runtimes/grok/tasks.ts`, for 104 source files plus LICENSE. 88 keep upstream
bytes and the same 16 carry BYOK changes.

`@agentclientprotocol/sdk` keeps the SDK's exact `1.4.0` pin. Upstream's range
is `^1.4.0` at both versions.

## Omissions

#652 forwards the agent's OOM score to ACP reverse terminals through
`shared/acp/terminal-launch.ts`, which imports `shared/executable/resolve.ts`
and the npm package `which`. The SDK never wraps a runtime to change its OOM
score. When a Host does, reverse-terminal commands keep the daemon's score, on
Linux only. The `agentPid` option and `AcpProcess.pid` field stay as upstream
bytes with no reader or writer.

`runtimes/dsh` is not selected here; a later slice takes it.

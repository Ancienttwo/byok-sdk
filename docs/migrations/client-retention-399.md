# Client retention API migration (#399)

This source change replaces the producerless journal GC with default daemon maintenance. It does not publish a package or migrate Host data automatically.

- Replace `hostedJournal.storagePolicy` with `storage: { budget, retention, scratchRoot?, skillPackDataDirs? }`. Budget only controls admission/ack watermarks; all daemons maintain storage by default.
- Remove `LocalStoragePressureEngine`, `LocalStoragePolicy`, `CleanupCandidate`, `CleanupResult`, `CleanableCategory`, `StorageCategory`, `CategoryUsage`, `createFilesystemCleanupExecutor`, log-rotation/cleanup-order helpers and their constants. They are not aliases. Audit logs retain their existing append-time size bound.
- Custom `LocalTaskJournal` implementations keep physical `measureUsage()` and add `listPrunableConfirmedTasks(cutoff: Date, limit)` and `pruneConfirmedJournalTask(taskId)`. Remove candidate listing/result APIs. SQLite-specific `enqueueCleanupCandidate` and `reportCategoryUsage` are removed; opening drops only local_artifact_ref/local_cleanup_candidate/local_storage_usage, not journal evidence.
- Every adapter start requires `ExecutionScratch`. Standalone Hosts call `createExecutionScratch({ root })` from the root or adapters entry, pass the same object to Pi launch resolution and start, and await release only after child disposal. Use a fresh standalone root for each process; daemon roots have persistent store identity. No shared-temp compatibility path exists.
- `PreparedRuntimeOperation.resolveRuntimeLaunch` takes `scratch: ExecutionScratch` in place of `projectionRoot: string`.
- A started session releases its scratch in `close()`. The Host still awaits `release()` after child disposal in every case, as the daemon does; `release()` is idempotent, so a second call is a no-op. `release()` removes only `exec/<token>/sdk` and writes the `released` marker; `exec/<token>/runtime` stays. The daemon sweeper removes released runtime directories after 24h. Nothing sweeps a standalone root: the Host deletes the whole root after its last release.
- Expired released runtime trees are reclaimed incrementally within the existing pass budget, including trees larger than the usage-measurement cap. `bytesReclaimed` includes successfully removed leaves in each pass; `deleted` increments only when a complete token is removed. Partial cleanup keeps the original release marker and can resume after daemon restart.
- The scratch root is a private real directory with no symbolic-link ancestors, owned by the daemon's user. Runtime Unix sockets limit it to 61 bytes on macOS and 65 bytes on Linux; Windows has no limit. The default is `<storeDir>/tmp`. When its canonical path does not fit, the daemon uses `/private/tmp/byok-scratch-<storeDir hash>` on macOS and `/tmp/byok-scratch-<storeDir hash>` on Linux. The hash is the first 16 hexadecimal characters of SHA-256 of the canonical store path. Otherwise, the default keeps the lexical `<storeDir>/tmp` and checks its length. On macOS do not derive a root from `os.tmpdir()`: it resolves through the `/var` symlink to a path past the limit.
- `PiAdapterOptions.durablePi` is boolean. The daemon supplies `<storeDir>/durable-replicas` in durableContext; direct Hosts must supply its explicit replicaRoot there. Old store/durable and runtime-projections data are protected unknown data: operator relocation must establish quiescence before moving or removing it.
- `storage` is always present on status. Read classes rather than categories; budget pressure is under optional `storage.budget`. Empty unconfigured scopes are `measured: false`; lastSweep is null before the first pass. Physical DB bytes are protected journal; confirmed row counts have zero physical bytes to avoid double counting.
- Normal cleanup prunes confirmed journal closure after 30 days, beyond unacked mailbox retention. A recovery marker prevents prune. Pressure keeps journal/home/skill evidence and only accelerates bounded compaction and rebuildable residue cleanup.
- `doctor` reports legacy shared-temp residue by count. The one-shot, bounded migration deletes exact same-uid real directories only with `doctor --fix --yes` after daemon stop. Remove this scanner next minor. Normal startup never scans or deletes OS TMPDIR.

Changed test contracts: candidate-injection tests become real on-disk producer/closure tests; private input-preparation expiry-timer tests become unified-pass pin/horizon/race tests; lifecycle tests spy on the single sweeper; adapter fixtures provide explicit scratch. Real pinned Pi bash and SIGKILL recovery remain runtime evidence, alongside locked replica, journal marker, lease and disposal-receipt tests.

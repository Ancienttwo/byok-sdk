# WO-12 restack integration

## P1 map

K8b owns group admission, member visibility, and per-Bot private context.
K8a owns context history projection and single-Bot action settlement.
K4 owns durable intents and execution state. The SDK owns the device session.

## P2 trace

A room message creates a seat and a frozen Request. turnContext applies the
member boundary. The shared history window counts Request and context bytes.
K4 offers the frozen payload. The real daemon starts the member session.
The Host commits speech only after it reads the result.

## P3 decision

Merge main normally. Then merge the pushed #530 normally. Keep K8a action
order, connector cancellation, state version, refusal reservations, and schema
fallback. Keep K8b team authority and private visibility.

Use one HistoryWindow type and one fitHistory byte calculation. Use turnLimit
from #530. Add message, refusal, Request, and metadata fields for K8b. Every
count exists in both room and private context. Keep the current Request in its
separate frozen section. Count it exactly once. Keep recent-100 turns/messages
and the K8a recent-12 card/question bound. Prefer pending items. Keep full
ledger rows unchanged. Do not add cross-Bot delegation or a K4 ledger rewrite.

Blocked turns use the #530 status and blockedReason fields. Room seats retain
their reason and blocked projection. Only schema cap and measured Request cap
errors become admission blocks. Other Host errors propagate.

7. Tighten three old 65536-byte output bounds to HISTORY_MAX_BYTES plus the
   frozen Request bytes. Keep the large input rows and all history assertions.

No timeout, skip, retry, worker count, original Unicode case, or real SDK path
is weakened. No replacement transport or session implementation is added.

## Review corrections

The independent Claude review found no weakened assertion. It identified three
bounded merge issues. New tests proved all three before the fixes.

- Reserve only refusal rows that remain in the frozen context. Count and byte
  trimming must not mark unseen feedback as delivered.
- Keep released blocked room seats unadmitted. A larger-budget restart may
  retry a private turn. It cannot restore a room seat that has lost authority.
- Require the Bot to exist in the fixed-point predicate. Two undefined
  revision fields do not prove readiness.

The settled-history test also proved the missing terminal-conclusion check.
All diagnostic guards were removed. No existing assertion changed for these
fixes. The added tests use the real SQLite ledger and embedded SDK server.

WO-12 intentionally changes the K8a metadata overflow rule. Only an oversized
Request or a schema cap blocks admission. Required metadata overflow has an
explicit notice. It does not hide authority data or reject an accepted Request.
This is the existing owner ruling documented in the history-window plan.

The pure command listed an absent team.test.ts filter. Vitest ran four actual
files and 38 tests. It did not run a fifth file. The full Bot suite passed all
10 files and 91 tests before the three review regressions were added. These
results precede the final review corrections and do not replace final checks.

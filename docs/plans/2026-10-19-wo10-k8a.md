## P1 map

K4 owns the SQLite ledger, Agent FIFO, frozen execution input, terminal
readback, and atomic outcome marker. K8-S supplies outcome schema fragments
and the routine calendar. K8a owns Bot policy and application state in
`examples/bot-collaboration`. It uses the K4 application transaction.

## P2 trace

Input -> frozen schema and ContextPack -> K4 FIFO -> embedded SDK -> daemon
-> submit_result -> device terminal -> K4 outcome transaction -> durable
action commands -> K4 FIFO or ordered wake outbox. Routine results return to
the owner. Confirmed actions use a Host connector with a stable idempotency key.

## P3 decisions

Keep K4 routine definitions immutable. Store K8a versioned routines in K4's
application ledger. Keep one consumer for K8a commands and wake operations.
Use a maximum of two unsettled occurrences per routine. On update, keep a
due armed slot, but stop replenishing the old chain. Finish all accepted old
occurrences before switching. Count self delegation against four continuations
per root input. It does not consume delegation budget or increase hop.

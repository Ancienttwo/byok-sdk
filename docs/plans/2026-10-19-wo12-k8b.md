## P1 map

`BotCollaboration` owns the K8a application transaction and serial consumer.
K4 owns Agent FIFO, frozen input, terminal readback, and outcome deduplication.
K8-S already exports group and management schema fragments. K8b extends this
Host. It does not change SDK packages or create a second execution core.
The two `.ai/context` files named in AGENTS.md are absent in this checkout.
No scoped agent context will be added.

## P2 trace

Structured user mentions -> durable round and ordered seats -> member Agent
FIFO -> fresh result-document offer without messageEgress -> device terminal
-> atomic speech and room_call application -> next seat. A waiting grace bounds admission. First observed claim starts a separate
running grace. Its timeout lets the next seat proceed. The old Agent FIFO remains held until its terminal.
A late post uses the original seat key and can enter shared history once.
Main Bot outcome -> profile and projection outbox -> SDK home projection ->
exact applied readback -> dispatch with the new profile revision.

## P3 decisions

Keep one ledger and one serial Host consumer. Add team policy and room state
as separate modules inside the example. Keep K8a actions on ordinary turns.
Use mention mode only. The admin identity changes budgets, not auto selection.
Use K8-S fragments and repeat current-role and membership checks on apply.
Archive Bot profiles. Do not delete homes. Freeze profile and context per
intent. Bound team notes at 20 and room context at 100 entries and 64 KiB.
Block excess context explicitly. Never drop history or authority enums.

The default seat budget is initial seats + 4, plus 4 if an admin exists.
Each member gets at most 2 seats; the admin gets at most 4. A room_call can
extend a closed round up to 3 times without new user input. Late posts have
a room-level cap of 10 per user root. Every seat reservation consumes budget,
even if execution fails. This prevents retries and timeouts from adding seats.

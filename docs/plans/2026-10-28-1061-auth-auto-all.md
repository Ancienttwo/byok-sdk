# #1061 工具授权硬切：只有 `auto` | `all`

状态：已实施，Draft PR 待房间验收。基线 `origin/main` = `c91c2e157404dde9a7206b56d762c70c05f87e95`。
需求：https://github.com/Ancienttwo/byok-sdk/issues/1061 。Owner 房间锁定合同：产品只有两种模式，
在同一个 Host/任务策略层决定，所有 runtime 共用。#1077（adapter 级 `beforeTool` + Codex/Grok
unsupported）已按错误方向关闭，本切片不叠加在它的分支上，只按新合同重写同步前置回调的思路。

## P1 — 改动前权限散落位置

- Pi（#1067）：`PiAdapterOptions.agentBuiltinTools` / `agentExtensions` / `agentUserContext`，默认
  `inherit`，写入 v6 launch 的 `agentToolPolicy`。
- Claude（#1073）：`ClaudeAdapterOptions.agentBuiltinTools` 白名单，默认 `inherit`。
- Codex：`sandbox`（执行层 sandbox，不是工具授权）。Grok：`--always-approve`，终端由 SDK 托管。
- daemon 已有唯一的用户授权通道：`TaskRunner.requestApproval` → `task.await_approval`，
  由 wire `task.approve`/`task.reject` 或本地 `Daemon.approve`/`reject` 决定，超时 fail-closed。

## P2 — 一次调用的路径

offer → `sealOfferManifest`（claim 前调用 `DaemonConfig.toolAuthorization(task)`）→
`auto` 且 adapter 未声明 `toolAuthorizationAuto`（或 prepared lane）→ decline
`tool_authorization_unsupported`；否则 `startInput.toolAuthorization` = daemon 构造的门 →
adapter 在每次原生工具执行前调用 `authorize(call)` → `classifyToolCall` → 普通调用放行；
高风险调用 → `requestApproval(summary)` → 批准才执行，否则 `tool_authorization_denied`
成为该工具的错误结果。`all`：不给 adapter 任何门，event pump 对 `tool_use` 分类后发
`tool-reminder` DaemonEvent。

## P3 — 决定

| 项 | 决定 |
| --- | --- |
| 类型 | `ToolAuthorizationMode = 'auto' \| 'all'`；`DaemonConfig.toolAuthorization: (task) => mode`；不接受任何别名（`full access`、`inherit` 直接 decline） |
| 默认 | 未配置 resolver 时为 `all`，即现有不阻断行为加提醒；不存在第三种模式 |
| 用户授权 | 复用任务唯一的 approval 路径，不新增 Host 回调 API |
| 分类器 | 单一函数，两种模式共用；规则写在 `docs/spec.md` 的 Tool authorization 一节 |
| Pi | v7 launch 携带 `agentUserContext` + loopback 门地址；hook 最后注册，判断扩展改写后的输入；原生子代理继承同一门；外部 runner 在门存在时拒绝启动 |
| Claude | `initialize` 注册 SDK `PreToolUse` 回调，确认 `hooks_applied` 后才发 prompt |
| Codex / Grok / Hermes / Pi prepared+durable | 不声明 `toolAuthorizationAuto`，`auto` 在 claim 前诚实拒绝 |
| 删除 | Pi `agentBuiltinTools`、`agentExtensions`、`agentToolPolicy` 与 v6 launch；Claude `agentBuiltinTools`；对应测试 |
| 保留 | `agentUserContext`（上下文隔离，不删工具）；Codex `sandbox`（执行层 sandbox） |
| native interactions | Owner 2026-10-28 裁定并入：只转发结构化问题。Claude 对非 AskUserQuestion 的 `can_use_tool` 立即 allow，不开 Host 请求；Codex 恒为 `approvalPolicy: never`，原生 approval 请求按不支持拒绝。两个 bridge 的 `approvalDecisions` 为空，单次工具调用只有一次权限决定 |

10x 时先遇到的瓶颈是高风险调用的人工审批排队（每任务 `MAX_PENDING_APPROVALS_PER_TASK`），
不是分类器成本（每次调用一次正则扫描）。

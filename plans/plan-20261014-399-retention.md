## P2 Concrete trace

### Execution start → disposal (Claude, daemon path)

1. `TaskRunner.handleOffer` (`task-runner.ts:~2140`) → `admitOffer` → `reserveOfferHome` → `admitOfferLimits`.
2. **New:** `scratch = await this.deps.scratchRoot.create()` (owner `'offer'`; declared beside `runtimeLaunch` at `:2169`). Creates `<scratchRoot>/exec/<token>/{sdk,runtime}` 0700, token 12 chars `[a-z2-7]` (60 bits), `mkdir` without `recursive` on the token dir, retry on `EEXIST`. Registers token in the in-process live set.
3. `prepareOfferRuntime` (`:3228`) builds `env = { ...buildRuntimeEnv({ ambient: process.env }), ...scratch.env }` (`:3269`). The same `env` feeds MCP probes, `projectPiMcpEnvironment`, `resolveRuntimeLaunch` (prepared allowlist keeps `TMPDIR/TEMP/TMP`, so it inherits the managed values) and `startInput.env`. #392 captured login env is already in `process.env`; the override is applied after it.
4. `resolveRuntimeLaunch({ …, projectionRoot: scratch.sdkDir })` (`:2374`).
5. `startInput = { …, scratch }` (`:2704`) → `startOwnedRuntime` (`runtime-start.ts:30`) → `ClaudeAdapter` writes `scratch.sdkDir/mcp-config.json` (0600) and spawns with `input.env`.
6. Active: `closeActiveSession` (`:1840`) receipt becomes `session.close()` **then** `scratch.release()`. `release()` = `rm -r sdkDir` → write `exec/<token>/released` (ISO time from injected clock) → drop token from live set. A failed `rm` throws `RuntimeDisposalFailure({ stage: 'cleanup', … })`; the token stays live; `awaitActiveSessionClose` (`:1850-1870`) reports it exactly as today and the receipt is retried.
7. `runtime/` stays. Sweeper deletes `exec/<token>/` once `now - released ≥ ttl['exec-runtime']` (24h).

Startup-owned path: `startupOwnership.register(taskId, { dispose })` at `:2788` and `:2830` composes `dispose` with `scratch.release()` (after the session/`retryDisposal` receipt). Clean start failure (adapter returned a typed `RuntimeExecutionFailure`, owner still `'offer'`): release scratch; if release throws, re-home the task under startup ownership with `dispose: () => scratch.release()` so the typed cleanup failure is retained and retried, never swallowed. Offer path (`finally`, `:3038-3058`): best-effort `scratch.release()`; on failure the token is dropped from the live set (`ScratchRoot.abandon`) so the next sweep owns it.

### Daemon start (owner lease → capabilities)

`startUnderLease` (`create-daemon.ts:2015`): lease → `ownedProcessLedger.reconcile()` (#393: crashed runs' process groups are dead or start is refused) → input-prep open → `initializeOwnedHostedStorage()` (journal only, no engine) → `auth.loadExisting()` → `agentHomeManager.preflight()` → `fleetJitter` → journal recovery marks (`:2117-2139`) → **New: `await sweeper.runPass('startup')`** (replaces the engine's first `tick()` at `:2148`) → `sweeper.start()` → `replaceControlServer(false)` → … → `computeCapabilities`. Because reconcile already ended crashed process groups and recovery marks closed every unfinished task, every exec token and every replica on disk at this point is residue of a dead run.

Startup pass contents:
- `exec/*/sdk` of every non-live token: delete, **not** subject to `maxDeletionsPerPass` or the pass time budget (secret-bearing: `mcpEnv`, Host input). Any failure (including an unreadable `exec/` listing) → `retention-failure` event, then start **halts before `replaceControlServer`/capabilities** with a typed `DaemonHaltError` reason (proposed `storage_cleanup_failed`, added to the #394 halt classification and exit-code table). Acceptance requires these secrets gone before the first offer, so continuing is not allowed; the operator fixes permissions and restarts. The pass is complete-or-halt for this class only; every other class stays bounded and non-fatal.
- `exec/*` without `released` marker: write marker = now (TTL starts at restart).
- `exec/*/runtime` past TTL, `tmp/daemon/*` past TTL: bounded.
- Durable replicas: see below.
- Agent homes: reader runs + home temp files, each home under its base lease (see below), bounded.
- Measurement: registry measure → pressure state (fatal only when `storage.budget` is set, same as today's awaited tick).

### SIGKILL recovery (durable Pi)

Before: worker held `durable-<task>.sqlite.lock.sqlite` (EXCLUSIVE); `launch-XXXX/config.json` (Host input + `mcpEnv`) beside the replica; daemon died. After restart: reconcile kills the worker group → lock is releasable → recovery marks the task `daemon_interrupted`. Startup sweep, per replica file, all guards required: (1) the filename decodes (`decodeURIComponent`) to a task id that is not active in `TaskRunner`; (2) the journal is available and `journal.readTask` returns the row with terminal authority (a recorded terminal, or the `interrupted` recovery marker just written); (3) `acquireReplicaLock(file, sweepLeaseId)` succeeds → `resetReplica(file)` + unlink lock sidecar while holding the lock → release. A replica with no journal row (unknown task, or row already pruned), an undecodable name, an unavailable/closed journal, or a held lock lacks terminal authority → protected `durable-replica-live`, measured, never deleted. Protected unknown replicas are surfaced in status counts; removing them is an operator action (`doctor --fix`, daemon stopped, lock acquired).

### Disposal of journal rows

Sweeper (state `normal` only) → `journal.listPrunableConfirmedTasks(cutoff = now - 30d, limit)` → `compact` first (§12.7.2.1 step 3) → `pruneConfirmedJournalTask(id)` each (in-transaction guard unchanged: confirmed terminal, no recovery marker).

## P3 Invariants, decisions, trade-offs

Invariants:
- **I1 One root.** Every SDK-written temp path is under `scratchRoot` (default `<storeDir>/tmp`) or `<storeDir>/durable-replicas`. Non-test `os.tmpdir()` appears only in comments, except O3.
- **I2 Protected is a type, not a filter.** `RetentionClass` is a discriminated union: `ExpiringClassId` entries have `sweep()`; `ProtectedClassId` entries have only `measure()`. `sweep(classId: ExpiringClassId)` — a `@ts-expect-error` test proves a protected id is not accepted; `retention.ttlMs` keys are `ExpiringClassId` (runtime validation also rejects others).
- **I3 Live or unproven is never swept.** Exec tokens in the live set; replicas whose task is active, whose lock is held, or whose terminal authority cannot be read from the journal; homes with an active Attempt or whose base lease is not acquired; skill-pack revisions referenced by a current `lock.json` or younger than TTL: skipped. Live-set removal happens only after a successful `release()`.
- **I4 Receipts stay typed.** `sdk/` deletion is part of the disposal receipt and fails as `RuntimeDisposalFailure{stage:'cleanup'}`; startup ownership retains on failure. Adapters stop deleting; they never swallow.
- **I5 Idempotency outlives redelivery.** Confirmed journal rows retained 30d (> mailbox redelivery window); unconfirmed and recovery-marked rows never listed.
- **I6 Bounded work** (except startup `exec/*/sdk`, which is complete-or-halt). Each pass: `maxDeletionsPerPass` (default 256) and `maxPassDurationMs` (default 10s) across all classes except startup `exec/*/sdk`; scans are bounded by a per-pass entry budget (default 4096 dirents) and resume next pass; `lastSweep.truncated = true` when a bound hit. One pass in flight; `stop()` clears the timer then awaits the in-flight pass before the journal closes (`create-daemon.ts:3166-3171` barrier is reused).
- **I7 No paths out.** Status, support bundle and observer events carry counts/bytes/class ids/error codes only.

Decisions:
- **D1 Sweeper owns cadence; pressure becomes a state holder.** `LocalStoragePressureEngine`'s timer, executor and candidate pass are deleted. `daemon/retention/pressure.ts` keeps `computePressureState`, the `noteAckCriticalFailure` latch, `admissionGuard()` and `assertAckCriticalAllowed()`; it is fed by the sweeper's measurement. Cadence: `sweepIntervalMs` 15 min in `normal`, `pressureSweepIntervalMs` 5 min otherwise, each through `fleetJitter.delay('retention', seq, base)`. Compaction remains journal-owned work the sweeper runs when due (1h normal / every pass under pressure). Under pressure the order truncates to rebuildable classes (I-order below); TTLs are not shortened (protects `cmd &` children and resumed Pi `fullOutputPath`).
- **D2 Order** (§12.7.2.1 rewritten against the registry): 1 `exec-sdk`, `daemon-temp`, `exec-runtime`, `durable-replica`, `input-preparation`, `skill-pack-stale` (rebuildable/expired); 2 rotated logs — removed (SDK has no log writer; `LogRotationPolicy` deleted); 3 `confirmed-journal` (normal only, compact first); 4 `reader-run`, `home-temp` (normal only, base lease); 5 orphan artifacts — removed (no producer). Pressure: step 1 only.
- **D3 Journal port shape.** `LocalTaskJournal` loses `listCleanupCandidates`, `markCleanupResult`; `measureUsage()` narrows to the journal's own footprint `{ measuredAt, journal: { bytes, entries }, quarantine: { bytes, entries }, confirmed: { entries, bytes, oldestConfirmedAt? } }`; gains `listPrunableConfirmedTasks(cutoff: Date, limit: number): Promise<string[]>` and `pruneConfirmedJournalTask(taskId)` (moved from the class onto the port). `SqliteLocalTaskJournal` drops `reportCategoryUsage`, `enqueueCleanupCandidate`; schema drops `local_artifact_ref`, `local_cleanup_candidate`, `local_storage_usage` with `DROP TABLE IF EXISTS` at open (no reader of them exists; one-shot, permanent, documented); `pruneConfirmedJournalTask` stops deleting from `local_artifact_ref`. `confirmed.bytes` is the summed stored payload columns (row bytes, not pages).
- **D4 Registry (closed).** `daemon/retention/registry.ts`:
  - Expiring: `exec-sdk` (store, TTL 0 after release / all non-live at startup), `exec-runtime` (store, 24h after `released`), `daemon-temp` (store `tmp/daemon/*`, 1h by mtime — a concurrent `doctor` may be using it, so never delete-all), `durable-replica` (replica scope, TTL 0, runner + journal-terminal-authority + lock guards; unknown → protected), `skill-pack-stale` (registered `dataDir` scope, D9), `input-preparation` (store, delegates to `store.gc(now)`), `confirmed-journal` (journal, 30d), `reader-run` (home, existing 32/7d rule, active + handoff-referenced protected), `home-temp` (home: `.byok-memory-<uuid>.tmp` and `.byok-agent-memory-<uuid>.tmp` in home root, `notes/**`, `.byok/`; `<name>.<pid>-<n>.tmp` only inside `.byok/`; 1h by mtime). `.byok-memory-delete-<uuid>.tmp` tombstones are **excluded**: a crash after rename-to-tombstone and before unlink leaves the only remaining bytes of a memory file whose deletion may not have been durably recorded; deleting it is erasure without proof of intent. They are protected `memory-delete-tombstone` (count+bytes) until a durable deletion-intent record proves the erasure was requested — no such record exists on this base, so they stay protected in this PR.
  - Protected (measure only, `measured:false` where the SDK does not own the bytes): `journal`, `quarantine`, `owned-processes`, `durable-replica-live`, `terminal-evidence` (`.byok/runtime-sessions/*-task-*.jsonl`, count+bytes, bounded scan), `agent-content`, `byok-authority` (`.byok` records), `agent-home-lease`, `workspace`, `retired-namespace`, `pi-session-dir`, `skill-pack-current` (revisions referenced by `lock.json`), `memory-delete-tombstone`.
- **D5 Scratch API** (`daemon/retention/scratch.ts`, exported from `.` and `./adapters`):
  ```ts
  export interface ExecutionScratch {
    readonly token: string; readonly sdkDir: string; readonly runtimeDir: string;
    readonly env: Readonly<{ TMPDIR: string; TEMP: string; TMP: string }>;
    release(): Promise<void>; // idempotent; RuntimeDisposalFailure{stage:'cleanup'} on failure
  }
  export function createExecutionScratch(options: { root: string; clock?: () => Date }): Promise<ExecutionScratch>;
  export class ScratchRootPathError extends Error {}
  ```
  Internal `ScratchRoot` (live set, `create`, `abandon`, path validation) is not exported. `root` must be exclusively owned by one process tree (documented).
- **D6 Socket budget.** At `createDaemon` (and in `createExecutionScratch`) on darwin/linux: `Buffer.byteLength(<root>/exec/<12>/runtime/)` + 16-byte documented suffix budget + 1 (NUL) must be ≤ `sun_path` (104 darwin / 108 linux) → runtime dir ≤ 87 / 91 bytes including the trailing separator; else `ScratchRootPathError` naming `storage.scratchRoot`. 16 bytes covers a short tool-owned socket leaf (e.g. `tmux-501/default` is exactly 16); tools needing more nest their own short paths and are outside the SDK guarantee (documented in `host-local-storage-layout.md`). Windows: no check. The test binds a real Unix socket (`net.createServer().listen(path)`) at `runtimeDir + 16-byte name` for a root at the computed maximum length (passes) and one byte over (constructor refuses), on darwin and linux, and checks the default `~/.byok/<productId>` and the #404 per-run test root both pass.
- **D7 Durable replica root (issue default).** Root fixed at `<storeDir>/durable-replicas`. The root travels inside `durableContext` (`{ tenantId, lifecycle, replicaRoot }`), which only the trusted parent constructs; `PiAdapterOptions.durablePi` becomes `boolean`. Standalone adapter Hosts that want durable Pi already supply `durableContext` (for `lifecycle`), so the root has one authority. Rejected: a separate start-input field beside `durableContext` (two authorities for one launch).
- **D9 Skill-pack revisions.** `DaemonConfig.storage.skillPackDataDirs?: readonly string[]` — absolute, canonicalized, validated at construction (typed error on relative/duplicate/overlapping roots or overlap with `storeDir`/`hostStorageRoot`). The daemon never discovers `dataDir` on its own; an unregistered root is never touched. Per registered root, current revisions come only from the existing `listInstalledSkillPacks(dataDir)` (`skill-pack-installer.ts:611`) — no second `lock.json` parser. A revision dir under `skillPacksRoot(dataDir)/<name>/<hash>` is deleted only when (a) not the revision any current lock references, (b) the dir name is a 64-hex content hash (exact installer shape), and (c) its mtime age ≥ `ttlMs['skill-pack-stale']` (default 7d) — (c) is the guard against an install that has written a new revision but not yet switched `lock.json`. A root whose `listInstalledSkillPacks` throws (corrupt lock) is skipped entirely and reported as `retention-failure`; never guess current revisions. Measured: stale count/bytes (expiring) and current (protected `skill-pack-current`).
- **D8 Managed TMP vars (issue default, pending O1).** Implemented as its own commit (slice S4) so it can be dropped if the owner keeps ADR-037 D2 verbatim; without it, `runtime/` is still created but unused and the Pi bash log stays in the OS tmpdir.

Trade-offs / what fails first at 10x:
- 10x executions/day: `exec/` holds ~24h of tokens; one readdir per pass, bounded by the dirent budget — fine. Disposal adds one `rm` + one small write per execution.
- 10x Agent homes: home sweep is the first pressure point (per-home lease acquire + `notes/**` walk). Mitigated by I6 budgets and round-robin cursor over homes; homes with active Attempts skipped. If it still lags, the next step is per-home sweep only on Attempt end (not in this PR).
- 10x journal: `listPrunableConfirmedTasks` needs an index on `journal_terminal(truth_state, updated_at)`; add it (`CREATE INDEX IF NOT EXISTS`).
- Diagnostics copy (≤512 MiB) now lands on the store volume instead of the OS tmp volume; under pressure it can push the store toward `hard-pressure`. Accepted; doctor is operator-invoked.
- Windows bridge executable now runs from `<storeDir>/tmp/daemon/` instead of `%TEMP%`; AV/AppLocker policies that special-case `%TEMP%` behave differently (residual risk, Windows CI covers the happy path).

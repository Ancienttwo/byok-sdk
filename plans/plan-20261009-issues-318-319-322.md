## P1: Boundaries

TaskRunner owns the run's text. It builds `task.complete` from `summaryParts`
and the closing reply from `finalTextParts`. Adapters own event granularity:
Codex emits one `progress` per completed `agentMessage`; Claude emits one per
text block; Pi emits deltas. Protocol owns the terminal payload schemas. Cloud
projects the stored terminal receipt into `TerminalResult`. Server narrows that
into `TaskResult`. AgentHomeManager owns the projection ordering record.

## P2: Paths

- #322: adapter `progress` -> TaskRunner `summaryParts` and `finalTextParts`
  -> `turn_end` -> `resolveResultDocument(finalOutput, task)` ->
  `task.complete` -> cloud receipt -> `projectTerminalResult` ->
  server `toTaskResult`.
- #319: `DaemonConfig.workspaceRoot` -> `TaskRunnerDeps.workspaceRoot` ->

  decline legacy offers first, and Git mode excludes `agentHome`.
- #318: `agent.home.projection` -> `AgentHomeManager.project` -> ordering
  record under the home lease. Agent offer -> execution lease ->
  `initializeExecution` -> runtime -> terminal envelope.

## P3: Decisions

- #322: add optional `finalMessage`. It is the same closing reply the daemon
  already uses for a required Agent message, so one value has one definition.
  Add descriptor flag `progressEventsAreMessages`; Codex sets it, so each
  `agentMessage` starts a new closing reply. Do not add an AgentEvent variant
  or a summary separator; both change existing wire meaning.
- #319: make `workspaceRoot` optional and validate at construction. A config
  union type would complicate `Omit<DaemonConfig>` users for no runtime gain.
- #318: choose option 2, evidence. Option 1 would decline offers forever when
  a host bumps `profileRevision` without a projection, and offer revisions
  need not be numeric. Record `{ profileRevision, projectionHash }` read under
  the execution lease on Agent terminals.

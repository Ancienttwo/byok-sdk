- Due diligence:
  - P1 map: the fork (`@byok-sdk/pi-ai`, `pi-agent-core`, `pi-coding-agent`; source only on this machine, sole remote = upstream `earendil-works/pi`, never pushed to) is `v0.85.1` + 26 own commits in four themes: (a) mechanical — RPC frame bound + `./rpc-types` export, model-catalog codegen fix, `find` parameter narrowing, MCP SDK production dependency, fork release tooling; (b) single-line `origin === undefined` host-canonical guards in usage/compaction/answer readers; (c) the lazy native-clipboard patch; (d) the prepared seam — `system-prompt-renderer.ts`, `prepareOpenAICompletionsRequest` / `consumePreparedOpenAICompletionsRequest`, `nativeModel()`, `PREPARED_RESIDUAL_TABLE`, `createPreparedAgentSession`, drift refusals. The SDK consumes the seam in `packages/client/src/adapters/pi/input-preparation.ts` and `packages/client/src/bin/pi-prepared-host.ts`, states its wire in `packages/protocol/src/input-preparation.ts`, and pins the fork by exact alias version. Out of scope: keys launcher, consent gate, counter, authority resolver, remote-lane transport, Salesko.
  - P2 trace (0.86.1, proven by S0): explicit prompt inputs → upstream `buildSystemPrompt`/`buildSystemPromptSections` → `Context{systemPrompt,messages,tools}` → `normalizeContext` (first message becomes a `SystemMessage`, literal `timestamp: 0`) → openai-completions `convertMessages` flattens the FIRST system message through `getSystemMessageText` into one string → request body D. S0 showed D computed this way is byte-identical to the first request of a real 0.86.1 `AgentSession` (both context shapes × no tools / `read+bash`; 1952 / 3668 bytes), that a wrong cwd differs only at `$.messages[0].content`, that D is stable under a 1h clock advance, that the only impure section builder is `docs` (`system-prompt.ts:153` → `config.ts` `getPackageDir()`), and that a live session always constructs a `CacheWarmer` (`sdk.ts:307`, default mode `streaming`) which stayed inactive only because the test model had no `promptCache`. Pressure points: the fork's own renderer (now divergent from upstream's section/XML rendering), the `Context`-typed drift comparison, and `CacheWarmer`.
  - P3 decision rationale: the seam's invariant is "the bytes the Host counted are the bytes the provider receives, or the session refuses". 0.86 changed how the system prompt is rendered, not what reaches the wire: `sections`, `toolsAdded` and `timestamp` never enter D. So the snapshot keeps carrying explicit prompt inputs (no transcript on the wire), and the fork stops owning a renderer — it calls upstream's builders with one added pure parameter. The rendered text does change (non-preamble sections are XML-wrapped), so every stored artifact of contract v2 is unusable against the new runtime; that is stated as a version bump with a named readiness refusal, not bridged. At 10x the first thing to break is per-provider body construction; the redo therefore converges on upstream's `onPayload` hook plus a pure exported request builder so the fork shrinks toward something upstreamable.

## Approach
### Strategy
A new fork line is built forward from the upstream tag; the 0.85 line is not merged or rebased (a dry-run merge conflicts in 22 files and would drag the old seam along). Slices run strictly in order, one writer at a time, on fork branch `claude/pi-086` cut from `v0.86.1`:

- **S1 Mechanical replay.** Re-apply themes (a) and (b) as fresh commits against 0.86.1 files: RPC frame bound + `./rpc-types`/root export + depth-1 id recovery; catalog codegen type-only import fix; `find` parameter narrowing; `@modelcontextprotocol/sdk` production dependency (only if S3 shows it is still needed — replayed provisionally, judged in S3); fork release tooling (`scripts/fork/*`, stage/publish, `assertStagedAliasCoherence`) with the upstream base moved to 0.86.1; the host-canonical single-line guards at their new locations (`evals/pi-harness.ts` is now `harness.ts`). Each replayed fix carries its original test. The prepared seam, the renderer split and the clipboard patch are NOT replayed. Exit: `npm run check` and the fork test suites green on the branch.
- **S2 Clipboard patch verdict.** Upstream deleted `clipboard-native.ts` in favour of pi-tui's helper. Decide with evidence whether the SDK helper argv still loads a native module eagerly: a sealed-host smoke under the SDK's argv. Outcome is either "obsolete, dropped" or a minimal new patch.
- **S3 Toolchain verification.** `tsc` + runtime on the S1 branch for: `@google/genai` 2.21, `openai` 6.40 (the seam sends a raw string body through `client.post` — prove it still goes out byte-exact), and whether the MCP SDK dependency fix is still required. Also settle the three items the consultation left unverified: `transform-messages.ts` determinism, raw-body `client.post`, and bun's behaviour on an unresolvable bare specifier.
- **S4 Seam redo.** (1) Add a pure `docsPaths` parameter to `BuildSystemPromptOptions`; the fork calls upstream's builders and carries no renderer of its own. (2) Snapshot inputs gain `toolGuidelines` and `sections`; `forceSystemPrompt` is refused. (3) Compile = `normalizeContext` + the openai-completions request builder, exported pure as `buildRequestPayload(model, TranscriptContext, options)`; consume moves onto the `onPayload` shape. (4) Drift comparison stays at the same point (after `normalizeContext`, before the stream function) and compares provider-visible identity: rendered text of the first system message, tool declarations from `getCurrentTools`, and the remaining messages; precondition — exactly one system message, in first position, else refuse. (5) A prepared session never constructs a `CacheWarmer` (`createAgentSession` passes `cacheWarmer: undefined` under `preparedInput`) and admission refuses one. (6) `nativeModel` admits the `promptCache` key only when absent-valued; `preparedToolProjection` includes `constrainedSampling` (built-in tools enable it by default from 0.86 and it changes the tools bytes of D). (7) Residual table: the top-level body key set of `buildParams` is unchanged 0.85.1 → 0.86.1, so no new classifications; the redo re-proves that with a test rather than asserting it. (8) Compiler and envelope contract versions 2 → 3; the v2 reader is deleted. (9) The S0 falsifier becomes a standing test, extended to what S0 did not cover: turn ≥ 2, tool-result turns, mid-conversation sections patch, non-empty contextFiles/skills/customPrompt, a model with `promptCache`.
- **S5 SDK wire v3 + pin.** Protocol snapshot gains `toolGuidelines`/`sections`; client compiler call, prepared host and store carry them; contract versions move to 3 with no v2 acceptance; a stored v2 record is refused at READINESS with the named reason `runtime_contract_superseded` (not left to fail as drift at consume); fork pin → the published 0.86 build; identity pins/gates, third-party manifest and the doc lines that state the pin move with it; a dated section in `docs/researches/runtime-input-preparation-contract.md`.

Fork versions follow `<upstream>.<forkBuild>` → `0.86.1xxx`; whenever `pi-ai` moves, every package that pins it by exact alias is re-published in the same build.

## Amendment 2026-09-21 — S4 design rulings after S3 (orchestrator ruling; read-only consultation, confidence HIGH)

The Strategy's S4 paragraph stands as written; where it conflicts with the rulings below, the rulings win.

1. **Consume is assert-only.** The prepared session runs upstream's normal stream path; inside `onPayload` it requires `JSON.stringify(livePayload) === D` and otherwise refuses before any socket opens (S3: a throw there aborts pre-egress; `onPayload` runs once and retries reuse the final params; nothing adds body bytes after it). No payload replacement, no raw `client.post` path, and the 0.85 fork's `AgentInitialRequest`/`promptWithInitialRequest` addition to `pi-agent-core` does NOT come back. Rationale: it is the only shape whose failure mode is a refusal rather than unverified bytes — a future upstream body-affecting option makes the live payload differ from D and the lane stops, instead of a frozen D going out while the session would have sent something else. This supersedes S4(3)'s "consume moves onto the `onPayload` shape" with a stricter reading of the same hook.
2. **Typed reasons survive.** `stream()` converts any thrown error into an `error` event, so the refusal is written to run-scoped state before the throw and re-thrown by `promptPrepared`. Admission-time checks stay (they fire before `getApiKey`, which may be a network refresh): `prepared_context_drift`, `prepared_model_drift`, `prepared_registry_drift`. At `onPayload`: `prepared_model_drift`, `prepared_endpoint_mismatch`, and a new `prepared_body_drift` for the byte mismatch. The per-request `validate` hook is dropped.
3. **One compiler.** `buildRequestPayload(model, TranscriptContext, SimpleStreamOptions)` is exported from openai-completions at the `streamSimple` boundary (base options incl. the `max_tokens` context clamp and the model sampling merge, thinking clamp, compat, transcript resolution, grammar properties, cache retention, `buildParams`); `stream`/`streamSimple` are refactored to call it. It takes the branded `TranscriptContext`; the prepared compiler calls `normalizeContext` itself. Exporting `buildParams` alone is rejected — it misses the clamp.
4. **No ambient input.** Prepared boundary: `cacheRetention` and `maxTokens` required; `temperature`, `toolChoice`, `reasoningEffort` allowed; `sessionId`, `samplingParams`, `env`, `thinkingBudgets`, `transport`, `metadata` and any other key refused. The prepared branch of the session's `streamFn` forces the same set, with `sessionId: undefined`, `samplingParams: undefined`, `thinkingBudgets: undefined`. `env: {}` is not passed (effect on key/base-URL resolution unverified). `prompt_cache_key` therefore stays unreachable and unclassified, as on the 0.85 line.
5. **`nativeModel` is re-derived against the 0.86 model/compat surface with the allowlist held at the 0.85 set** (explicit `thinkingFormat` still only `zai`); every compat key 0.86 added stays refused. This was missing from the plan. `promptCache` is NOT admitted (supersedes S4(6)'s "admits the key only when absent"): the SDK wire model is strict and cannot carry it, so admitting it would add a consent-gate field for a value no producer can send.
6. **CacheWarmer.** Warming is made unreachable by `sessionId: undefined` (the `streamFn` gate compares it with the session id); passing `cacheWarmer: undefined` alone does not stop `start()`. Admission still refuses a warmer, and a test proves `start` is never called on a `promptCache` model. Supersedes S4(5)'s mechanism, not its intent.
7. **`constrainedSampling` is admitted** and carried in the tool projection (preferably by delegating to upstream's `toToolDeclaration`). The 0.85 refusal was a projection-fidelity limit, not a semantic one; forcing it off would break S0 equality. `tools` is inside the projection keys, so `strict` and the rewritten `parameters` are part of P(D), not residual — the Host accounting ruling is unaffected. Refused at the boundary: `strict: "require"` and `type: "grammar"`, so the compiler can never throw mid-build. A mixed strict/non-strict tool list is normal and deterministic.
8. **Wire: exactly one new snapshot field, `toolGuidelines`** (Host-stated, bounded like `toolSnippets`). `sections` is NOT added (supersedes S4(2) and S5): its only producers are extension/`before_agent_start` paths that admission already refuses, so a wire field would be something the Host can state and the device can never produce. A non-empty `sections` and any `forceSystemPrompt` are refused at the compile boundary. No model field changes, so the SDK consent gate's compared-field constant is unchanged. The SDK's tool projection must stop stripping `constrainedSampling`.
9. **Version axes (S5):** compiler version 2 → 3, projection version 2 → 3, `PreparedSessionInputV2` → `V3`, `INPUT_PREPARATION_VERSION` 3 → 4, record version 4 → 5; `runtime_contract_superseded` joins the readiness reasons and is reached from the compiler-version check. `packages/cloud` fixtures carrying `compilerVersion: 2` move with it (contract `allowed_paths` to be widened before S5 if so).
10. **Host-canonical history is byte-path-critical on 0.86:** `estimateContextTokens` reads `usage` of every assistant and now feeds the `max_tokens` clamp, so the `origin === undefined` guard in `estimate.ts` decides request bytes. Admission's "no messages" check becomes "no non-system message" (0.86 keeps the leading system message in `state.messages`).
11. **Sub-slices, one writer, in order:** S4-1 host-canonical unit · S4-2 `docsPaths` (required) pure prompt builder · S4-3 exported `buildRequestPayload` + refactor — **gate A** — S4-4 prepare boundary v3 (+ residual re-proof sweep) · S4-5 envelope v3 · S4-6 consume + admission, delete the old consume · S4-7 standing falsifier (extended: turn ≥ 2, tool-result turns, non-empty contextFiles/skills/customPrompt, `promptCache` model, mixed strict tools — the "mid-conversation sections patch" case is dropped as unreachable) + tooling re-attachment — **gate B**. Cut from S4: `sections` on the wire, `promptCache` admission, `AgentInitialRequest`, `grammarToolInputProperties` in the artifact, any thinking-format widening.
12. Known cost, accepted: prepared launches on OpenAI-direct endpoints carry no `prompt_cache_key` (cost, not correctness). If it becomes material, `sessionId` becomes an explicit Host-stated compile input — a later, bounded change.

13. **Host-canonical discriminant encoding (ruled 2026-09-21 after S4-1 stopped).** The 0.85 encoding — `origin?: undefined` on `AssistantMessage` — cannot be carried: 0.86.1's `pico3` harness types durable state as strict JSON (`JsonObject`), and an optional property whose type is exactly `undefined` (or `never`) fails its index signature (4 `tsgo` errors in `packages/agent/src/harness/pico3/`, isolated by three full type-check runs; adding only the union member is clean). Ruling: **`AssistantMessage` stays byte-identical to upstream; `HostCanonicalAssistantMessage` carries a required `origin: "host_canonical"`; readers discriminate with `"origin" in msg`**, which narrows both ways. Rejected: `origin?: "host_canonical"` on `AssistantMessage` (the type would then permit a provider turn carrying the marker, and the else-branch does not narrow); changing pico3's durable-JSON contract (permanent rebase cost on a new upstream harness). The design itself — no provenance-less object is ever coerced into an `AssistantMessage`; the compiler enumerates every reader — is unchanged. Reader rule for sites the 0.85 survey did not cover: a site that reads only `content` treats both variants alike; a site that reads provenance (`usage`, `stopReason`, `model`/`provider`, `errorMessage`, response ids) excludes the host-canonical entry, as `cb4a6de14` did for usage, compaction and answer readers. S4-4/S4-6 validators are written against the same discriminant.

## P1: Boundaries

Client DeviceStore delegates secret authority to the OS store. The OS key is
productId. The test double has a different key. Daemon construction owns default
adapter options. Direct adapters accept a host-built environment. Protocol owns
runtime schemas. Keys and server own separate SQLite initialization paths.
Release state comes from npm readback, not the version in a manifest.

## P2: Paths

- DeviceStore -> OS service(productId) -> enrollment read; changing storeDir
  only changes the metadata projection.
- createDaemon -> default adapter factory -> shared daemon builder. Injected
  adapters bypass the factory, so codexSandbox must be rejected there.
- Host -> adapters export -> adapter.start(input.env); expose the existing
  environment builder for this host boundary.
- SQLite open -> schema validation -> store construction. Reject unsupported
  persisted state before it can serve a task or mutate an old profile schema.
- Consumer bundle -> adapters -> protocol runtime imports -> Zod schemas.

## P3: Decisions

Keep product-scoped OS credentials. Align test storage and explain unpair or a
new productId before a new enrollment. Reject ignored sandbox options on the
injected path. Export the existing environment builder. Keep runtime validation;
measure its bundle cost before deciding whether a safe build change is enough.
Reject pending non-v2 mailbox envelopes with a typed initialization error.
Do not add a v1 reader or delete historical rows. Reject old profile DDL before
write initialization. A general legacy importer is outside the core bug fix.
Record npm versions and integrity. Do not claim a release tag without source
artifact evidence.

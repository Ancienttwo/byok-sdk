## Approach
### Strategy
Land the revision first (it gates everything), then the adapter against it, then the deploy skeleton:

1. **Capability split + port narrowing** (`packages/cloud`): `CloudStores.blobs` type narrows to `{createUpload, getDownloadUrl}`; `verifySignedUrl`/`writeContent`/`readContent` move to a standalone `BlobContentProxy` interface, accepted as an **optional** composition input (not a `CloudStores` member); capability vocabulary gains `blobs.contentProxy`, and the two `/content` routes mount only when a proxy is provided AND the capability is declared; `blobs.presigned` continues to gate the presign routes. In-memory composition supplies both (narrowed store + proxy) — hosted-in-memory behavior is unchanged. `CLOUD_PORT_METHODS` updates; `route-inventory.test.ts` gains the new capability combination rows. S3a red lines untouched: handlers stateless, no Running map, no sniffing, inventory exhaustive.
2. **Conformance scope completes**: `CLOUD_CONFORMANCE_PORTS` grows to 9 — the narrowed two-method `blobs` port now has a stable cross-composition contract; add a `blobs` dimension to `runCloudConformance` (upload declaration → manifest pending; download URL only for committed; tenant-scoped, composition-agnostic assertions only). R2-specific behavior (SigV4 acceptance, HEAD re-verification, transient errors) stays composition-local — same placement logic as the b-slice concurrency tests.
3. **R2 adapter** (`packages/cloud-postgres`, per design §4 — manifest and bytes are one transaction authority): `aws4fetch`-signed presign PUT/GET, `HEAD` re-verification driving `pending→committed` via the b-slice objects store, key = `tenantObjectKey()` verbatim, `Content-Length` in signed headers, checksum header probed and adopted only if MinIO+R2 both honor it (HEAD stays unconditional regardless); a fault-injection `fetch` wrapper for deterministic 500/503/timeout sequences.
4. **S4A.4 nine object tests** against the compose MinIO: same-hash duplicate upload idempotent; size/hash/content-type mismatch rejected (`storage_integrity_mismatch`); tenant/resource-bound presign (MinIO rejects cross-tenant/cross-key use); expired presign rejected by MinIO; object exists before truth reference (committed-only rule); range/large response limits; no key/path traversal (hash hex-validated at the single key-construction point); cross-tenant same-hash upload produces no existence oracle (no dedupe across tenants, no observable timing/response difference); transient error/backoff/idempotency via the fault wrapper.
5. **Deploy skeleton**: `deploy/env/hosted.env.example` (+ any needed variants) with placeholder-only values; `deploy/scripts/migrate` invoking the a-slice runner against `DATABASE_URL`; a short `deploy/runbooks/postgres-rls.md` documenting optional RLS hardening as defense-in-depth explicitly **not relied upon** (S4A.5 box; the catalog assertions + tenant-first discipline are the enforced layer). Secrets sample machine-checked to contain no real keys.
6. **Closing marks**: sprint S4A.5 remaining boxes, S4A → complete; notes; todos entries if the gate surfaces residuals.

### Trade-offs
| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Split capability + narrow port (design §6) | Suite stays all-or-nothing per composition; "R2 can't proxy bytes" becomes a type-level fact; no naked-blobId lookup path survives | The one contract revision in S4A; `route-inventory` and capability vocab churn | **Use** — the alternatives (subset waiver / meaningless rejection assertions) are both named anti-patterns |
| Keep five-method port, R2 throws typed rejections | No interface change | Conformance must either skip (waiver) or assert vacuous rejections; capability stays a lie for R2 compositions | Rejected — design §6 |
| `aws4fetch@1.0.20` pinned | Single-file WebCrypto SigV4; loud 403 failure mode; no ambient credential chain | S4B's ListObjectsV2 needs hand-rolled XML paging (cost recorded in design §3) | **Use** — swap back to AWS SDK affects only this adapter file if S4B rules the cost too high |
| MinIO as the SigV4 verifier | Independent implementation: presign bind/expiry assertions are real, not self-certified | MinIO/R2 behavioral deltas (checksum headers, conditional requests) | **Use** — HEAD re-verification is unconditional so correctness never rests on either implementation's strictness |
| Fault-injection fetch wrapper for transient errors | Deterministic 500/503/timeout sequences; no shadow S3 | Doesn't exercise real network faults | **Use** — design §3: it's a fault injector, not a mock S3; MinIO covers the real-protocol side |
| RLS as enforced isolation layer | Belt-and-braces | A second enforcement authority competing with the catalog assertions; §12.6.2's layers are the ruled design | Rejected — documented as optional hardening, explicitly not relied upon (S4A.5 wording) |

### Code Snippets
The split's type-level shape (design §6):

```ts
// CloudStores.blobs: what every composition can honestly provide
interface CloudBlobStore {
  createUpload(tenant: TenantId, decl: BlobUploadDeclaration): Promise<BlobUploadGrant>;
  getDownloadUrl(tenant: TenantId, blobId: BlobId): Promise<BlobDownloadGrant>;
}
// Byte proxying: an optional composition input — absent for R2, present for in-memory
interface BlobContentProxy {
  verifySignedUrl(...): ...; writeContent(...): ...; readContent(...): ...;
}
// Route mounting (cloud.ts): both conditions, no sniffing
if (contentProxy && declares('blobs.contentProxy')) registerContentRoutes(...);
```

### Data Flow
Upload: `createUpload` → manifest `pending` (Postgres) + presigned PUT (R2/MinIO, Content-Length signed, expiry bound) → device PUTs directly → first reference/download → `HEAD` re-verify (size/content-type vs declared) → mismatch `storage_integrity_mismatch` / match `committed` → truth may reference. Download: `getDownloadUrl` only for `committed`, tenant-scoped key, expiry bound. Transient errors: fault wrapper injects deterministic 500/503/timeout around `fetch`; adapter retries idempotently (PUT/HEAD/GET are idempotent by construction).

# F08-01: provider total HTTP deadline

## Scope and result

Fixed F08-01 only. `fetchWithProviderGuards` keeps one original deadline and the caller abort listener alive across headers and actual response-body reads. It returns a guarded Response owning the original reader, races stalled headers even for abort-ignoring injected fetches, errors stalled body consumers promptly, and cancels owned/late responses without awaiting an uncooperative cancel hook. Success, source error, caller cancellation, deadline and explicit body discard remove the timer/listener. An already-aborted caller never invokes fetch. Existing client and HTTP error classification remain intact.

The early content-length rejection now cancels the owned body to release this lifecycle guard. This does not implement a streaming byte ceiling. F08-02 remains pending: response.text still buffers before the existing decoded-byte check. F08-03 remains pending; profile persistence is unchanged.

## Limits

Focused verification is not repository-wide acceptance. Full-workspace build/typecheck/test is coordinator-owned and was not rerun here. No actual provider/network, native OS, production storage, or power-loss tests ran. Tests use installed Vitest, production source modules, native Response/ReadableStream, inert secrets and deterministic fake timers. The guard bounds the consumer's asynchronous wait and requests disposal; it cannot force arbitrary injected JavaScript or underlying I/O that ignores cancellation to stop, nor interrupt event-loop-blocking synchronous computation. F08-02's memory ceiling is explicitly not fixed.

## Independent-review repair round 1

Review requested changes because cancellation between the pending-fetch observer and the `Promise.race` await continuation returned the correct abort error but leaked the unclaimed Response body. The observer now acquires explicit response ownership, retaining it until synchronous transfer to the body reader. Abort, the finished continuation, the late-response observer and catch all use one disposal function which takes and clears ownership before requesting cancellation. Listener/timer cleanup is idempotent. No untrusted cancel promise is awaited.

Read the analogous S11 status-client fix in the integration checkout for its per-handoff ownership checks; this implementation keeps the provider's existing response-returning contract and stable abort/timeout mapping.

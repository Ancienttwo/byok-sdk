# F08-02: streaming provider response byte ceiling

## Scope and implementation

F08-02 only, on top of approved F08-01 commits b052bd0 and 27e3c39. The JSON parser now reads the response stream and counts each chunk's byteLength against the remaining 2 MiB budget before decoding or retaining that chunk. It rejects and cancels on the first crossing chunk, without needing EOF or awaiting an untrusted cancellation hook. It incrementally decodes UTF-8 (including split code points/BOM handling), parses only bounded text, preserves existing invalid-JSON/HTTP/source-error mapping, and releases its reader in finally. The existing early content-length guard still cancels before reading.

The guarded response wrapper now uses highWaterMark 0, so the wrapper itself does not request another source chunk before the bounded consumer can reject the crossing chunk. F08-01's ownership, cancellation and original deadline logic is otherwise unchanged, and its 19 lifecycle regressions still pass.

Byte counting applies to body bytes exposed by Fetch (normally already decompressed), rather than trusted Content-Length or a re-encoding of the final string. No profile persistence changes: F08-03 remains pending, and work stops here for independent review.
